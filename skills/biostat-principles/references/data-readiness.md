# 分析就绪数据合同

本规则适用于 P 项目执行和 R 正式发布中首次生成清洗数据、改变清洗规则，或正式分析读取清洗数据的情形。Q 问答、单个单元格核验和不生成正式估计的 L 局部任务只检查受影响内容，不创建状态文件或异常审批流程。

## 1. 先确定输出合同

首次生成清洗数据前，从用户要求、项目既有约定和研究方案中确定以下内容：

| 字段 | 要求 |
| --- | --- |
| 相对路径 | 明确目录、文件名和工作表或对象名，不从 `data_neat` 等简称猜测它是目录、文件还是程序对象 |
| 格式及定位 | 明确 Excel、RDS、CSV、Parquet 或其它格式；同时记录工作表、对象、数据集等内部定位，单表文件明确写 `file`；说明会影响类型、缺失值和非有限值的读写规则 |
| 用途 | 区分研究者核对、后续正式分析、内部精确镜像和外发交付 |
| 权威角色 | 同一份清洗数据存在多种表示时，只指定一个权威分析输入，其余均标为镜像或查看文件 |
| 完成证据 | 实际路径存在、指定工作表或对象可读、字段和记录键可核对，正式分析从声明的权威输入读取 |

已有项目已经明确这些内容时直接沿用，不重复询问、不迁移路径。多个合理选择仍会改变正式分析的读取方式或数据语义时，列明差异后等待用户决定。

## 2. 区分数据状态

把清洗视为有条件的状态转换，不用文件名代替状态：

1. **来源解析**：只读导入原始数据，保留原字段和原值；去除首尾空格、统一方案已定义的缺失码、按数据字典进行无歧义类型转换等预先授权且确定的规范化可以自动完成。
2. **待核对**：发现会改变数值、缺失状态、分析集、终点、分组、插补资格或模型输入的异常时，生成可定位的核查材料并停止。至少保留记录键、变量、原值、当前解析值、建议处置、原因类别、决定字段和证据来源；建议值不得自动成为最终值。
3. **批准后生成**：由数据提供者、研究者或项目约定的责任人完成科学决定后，正式清洗脚本读取结构化决定并从最早输入重新生成权威分析数据。人工工作簿可以承载决定，但不得通过直接覆盖清洗数据成为唯一修正来源。
4. **分析就绪**：只有阻断性未决项为零、权威输入存在、输入哈希与状态记录一致、相关缺失和非有限值语义已经保留或决定后，才能标记为 `analysis_ready`。

没有异常且只执行预先授权的确定性规范化时，可以在同一次运行中直接形成 `analysis_ready`。已经明确接受的低风险异常可以通过可追溯决定关闭；自动规则不能替代临床、流行病学或数据来源判断。

## 3. 保留缺失与非有限值语义

- 普通缺失、结构性未测、尚未核对、因排除规则产生的缺失，以及数学上未定义或无穷的结果必须在进入插补或模型前可区分；不得因为 Excel 显示为空白而合并为同一类缺失。
- `Inf`、`-Inf` 和 `NaN` 先根据变量定义、分子分母和采集流程判断，不一律当作录入错误，也不静默改为空值。
- 插补脚本只接收 SAP 和异常决定允许的缺失类别。缺失原因或适用性尚未确认时，状态保持待核对。

## 4. 核对多种数据表示

同时导出 Excel、RDS、CSV、Parquet 或其它镜像时，在清洗脚本中核对记录键、行列数、字段含义、类型转换、缺失原因和非有限值表达。跨格式文件的二进制哈希本来就不同，不能用文件哈希相等代替内容核对。

正式分析脚本使用 helper 的 `analysis_source()` 从分析就绪状态记录同时取得权威输入路径、格式和内部定位，不在各脚本中分别手写另一个镜像路径或工作表名。用户确认 RDS 为权威输入时仍可使用 RDS；用户确认 Excel 为权威输入时，内部 RDS 只能作为已说明并核对的镜像。

## 5. 设置可执行关口

新项目使用 `02_code/vendored/data_readiness.R|py` 写入和检查 `results/derived/data-readiness.json`。该文件由正式数据准备脚本生成，不手工编辑，至少记录：

- `status`：`pending_review` 或 `analysis_ready`；
- `authoritative_input`、`input_format` 和 `input_locator`；
- `unresolved_issues`；
- `producer`、`decision_source` 和当前 `run_id`；
- 权威输入的哈希算法与哈希值。

总运行脚本把数据准备脚本和正式统计分析脚本分开列出。先运行数据准备；只要存在正式分析步骤，就在运行第一项分析前检查状态、未决项、权威输入、哈希和当前运行编号。检查失败时保留完整日志并拒绝运行描述统计、回归、ROC、插补、正式表图及其它统计估计。

既有项目不为迁移而自动改目录或重写全部清洗流程；本轮首次新增正式分析、改变清洗规则或发现同类风险时，在受影响范围内采用同一行为合同。项目状态和科学决定仍分别记录在项目 `CLAUDE.md`、`DECISIONS.md` 和必要的 `BACKLOG.md`，机器状态文件不替代责任人确认。
