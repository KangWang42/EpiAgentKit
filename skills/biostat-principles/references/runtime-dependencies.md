# 运行环境与普通分析包安装

本文件规定 R/Python 分析与统计绘图的依赖处理方式。目标是保留已选方法，先补齐普通包，而不是因本机缺包静默改变实现。

## 1. 先分类

1. 核对当前方案实际导入的最小包集合，不把示例资料或可选功能中列出的全部依赖一并安装。
2. 区分四类缺失项：
   - **普通分析包**：可从项目声明的 CRAN、Bioconductor 或 PyPI 官方仓库取得，不需要另装系统运行时。
   - **系统依赖**：操作系统库、编译器、驱动、Java、LibreOffice、TeX、R 或 Python 本体及包管理器。
   - **非官方来源**：GitHub、任意 URL、r-universe、自建索引、本地归档或来源身份无法确认的包。
   - **替代实现**：更换包、算法、图形实现或分析语言，即使输出形式相近也属于方法变更。
3. 只有普通分析包进入自动安装；运行时、系统依赖和非官方来源先说明用途、安装范围、风险和拟执行动作并征得用户同意。若用户不安装，进入第 4 节的等价实现评估。

## 2. 选择项目隔离环境

- 优先使用项目已经声明的环境和锁文件，如 `renv.lock`、`requirements*.txt`、`pyproject.toml`、`uv.lock`、`poetry.lock` 或 conda 环境文件，并使用该项目既有包管理器。
- 没有现成环境时，在项目内建立隔离的包环境；不得写入用户级、系统级、全局 site-library，或 Codex、Claude、插件和办公工具自带的共享运行时。
- 使用与实际运行脚本相同的 R 或 Python 环境安装。Python 使用同一套 Python 的 `-m pip` 或项目既有管理器，避免调用另一套环境中的 `pip`；R 使用项目库或项目既有 `renv`，避免写入全局 library。
- 只安装缺失包及必要的传递依赖。遵循锁文件、项目版本约束和当前兼容版本；不为追求最新版升级无关包。解决依赖冲突需要降级、移除或以不兼容版本升级已有包时，停止并请求用户决定。

## 3. 安装、验证与记录

1. 安装前记录包名、选择它的代码位置、目标环境和来源；包身份或仓库来源不明确时先核验，不猜包名。
2. 从项目声明的官方仓库安装普通包。Bioconductor 包按照官方安装说明，使用与当前 R 和 Bioconductor 版本相匹配的安装方法；不原样执行旧示例中的安装命令。
3. 安装完成后在同一 R 或 Python 环境中导入或加载包，记录实际版本，并重新运行原定脚本或最小复现。
4. 正式项目把新增的直接依赖写入现有依赖清单或版本锁定文件；名称、版本、来源、安装环境和验证结果保存在同一次自动运行记录或安装记录中。轻量任务只在交付说明中报告完成核验所需的这些信息。
5. 安装日志与异常按全局规则扫描 `error|warning|traceback|failed|nan`；不能仅凭安装命令退出码判定成功。

## 4. 失败与替代边界

- 网络、权限、系统库、编译器、版本冲突或官方仓库无此包导致安装失败时，停下并报告已核对证据、影响和下一步，不循环尝试不同镜像或来源。
- 用户拒绝安装或安装失败时，先评估现有环境中的替代实现。只有 estimand、统计方法、分析集、随机与数值设置、输出定义和验收标准均可保持，且用代表性输入核对一致时，才称为等价实现；语言或包不同本身不是方法变更。
- 无法满足上述等价条件时，把可选方案的差异、影响和验证方式列明，等待用户选择。未经同意不得改用功能相近的包、简化算法、手写低配实现、另一种绘图方案或另一种分析语言，也不得把近似结果表述为相同效果。
- 用户批准非等价替代后，把原因、方法差异、结果兼容性与恢复原方案的方法写入正式项目 `DECISIONS.md`；轻量任务在交付说明中明确说明。
- 咨询交付、项目审查、EpiAgentKit 安装同步和文档工具的最终复现检查仍服从各自“不现场改变环境”的边界；应在进入这些阶段前完成分析依赖准备。
