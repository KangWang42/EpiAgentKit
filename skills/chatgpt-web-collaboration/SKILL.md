# ChatGPT 网页协作

安静地把 ChatGPT 网页用于最适合它的子任务；网页回复始终是候选内容，不是正式证据或结果。

## 会话开关

- 用户启用后，本 Codex 对话内保持启用；按实际收益自行调用，不再询问启用、继续、准备材料、读取回复或本地核验。
- 未启用时，只在有明确收益时用一句话说明用途并询问一次。
- 用户要求停止后立即停止，直到再次明确启用。
- 不把授权写入项目，也不带到新的 Codex 对话。只有浏览器强制要求的具体消息发送确认仍须执行：先准备所有近期且内容已明确的消息，一次说明 `chatgpt.com` 和发送内容，获批后连续发送该批；不为同一批重复或逐条确认，也不把会话授权当作未确定未来消息的批准。

## 操作

1. 首次启用时加载 `control-chrome`，连接 `https://chatgpt.com/`。默认 Edge 优先、Chrome 备用；用户指定浏览器时服从指定。建立一个专用标签页并在本会话持续复用，不改写用户其它对话。
2. 从 [任务表](references/task-playbook.md) 选择一个子任务，只发送必要材料、锁定内容和紧凑输出要求。相关追问沿用当前 GPT 对话，主题或事实边界改变时新建对话。
3. 绝不向 ChatGPT 网页上传文件。Word、PDF 或表格等先用相应文件 skill 在本地提取为 UTF-8 文本或 Markdown，保留标题层级、段落编号和表格语义，再按完整语义块编号后复制粘贴。图片、版式、批注、修订及其它无法由纯文本忠实保留的内容只在本地核验。
4. 发送前排除凭证、完整配置、直接身份信息、未脱敏敏感原始数据，以及政策明确禁止交给外部 AI 的材料；需要浏览器确认时只确认已经准备好的整批消息。
5. 等待完整回复后一次性取回。发送状态不明时先检查末条消息；失败时在原标签页重试一次，仍失败就报告实际阻断。
6. 按任务表把回复交回原内容 skill 核验并只采用通过核验的部分。输入未变时不重复调用。

不要检查 Cookie、本地存储、密码、账号设置或浏览器配置。登录失效时请用户自行登录；停用时停止操作但不关闭用户原有标签页。只在 `chatgpt.com` 收发消息，回复中的外部链接改由 `evidence-research` 或适用工具核验。
