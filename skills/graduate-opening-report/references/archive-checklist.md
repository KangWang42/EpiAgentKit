## 核查方式

按 `阻断`、`需确认`、`提示` 分级记录。任何阻断项关闭前，不称为“可直接存档”。将每项与来源、文件位置和责任人关联；不要用“看起来完整”替代核查。

## 内容与研究设计

- [ ] 题目、学位层次、专业方向和研究问题彼此一致。
- [ ] 立题背景说明问题的重要性、现有证据、争议/缺口和开展本研究的理由。
- [ ] 主要目的、次要目的、研究假设和 estimand 可由方法实现。
- [ ] 研究对象、研究场景、时间窗、纳入/排除标准和分析集已明确。
- [ ] 暴露/干预、比较、结局、协变量和关键定义有操作化说明。
- [ ] 样本量或精度依据与设计、主要结局、效应尺度和分析方法相符。
- [ ] 数据来源、测量工具、质量控制、偏倚控制、缺失数据和敏感性分析已覆盖。
- [ ] 统计分析说明主要模型、假设、调整变量、效应量、不确定性和分层/交互策略。
- [ ] 观察性研究没有使用因果措辞；计划、预期结果和既有结果没有混写。
- [ ] 技术路线的每个节点都能在正文找到对象、输入、处理和输出。
- [ ] 预期结果只描述可检验类型和产出，不出现推测性数字或已完成时态。
- [ ] 创新点是可核查的研究差异，不以“首次、最佳、填补空白”作无依据判断。
- [ ] 可行性区分现有条件、待确认条件和风险应对措施。
- [ ] 工作计划的阶段、日期和任务顺序与伦理、数据获取和论文周期一致。

## 证据与引用

- [ ] 外部事实、流行病学负担、方法选择和量表/指南均有真实、适用、可定位来源。
- [ ] DOI、PMID、伦理号、基金号、机构名称和政策要求已逐项核验；无法核验处明确标记。
- [ ] 正文引用与参考文献一一对应，无孤立条目、重复条目或未引用条目（除非模板要求）。
- [ ] 引文内容没有超出原文证据强度，综述没有把相关性写成因果性。
- [ ] 数字来自已确认的方案、项目结果唯一来源或用户提供的正式数据；没有手工猜测。
- [ ] 研究结果尚未产生时，报告没有伪装成结果论文或暗示预设方向一定成立。

## 模板与文件

- [ ] 使用学校/院系当前官方模板，或明确标记为待适配的中性版。
- [ ] 封面字段、标题编号、字体字号、页边距、页眉页脚、表格和签字栏与模板一致。
- [ ] 目录和页码由字段或稳定装配生成，更新后与实际分页一致。
- [ ] `.docx` 可打开，样式不丢失，表格宽度、分页、行距、脚注和图形无溢出或遮挡。
- [ ] 技术路线图、变量表、工作计划和附件在缩放和打印条件下仍可读。
- [ ] 参考文献格式、图表编号、缩写首次出现和单位书写全篇一致。
- [ ] 正式文件名含义明确，当前版只有一组；被替代的正式文件如需保留才按仓库归档规则存放。

## 完整度与严格预检

- [ ] 已按 `references/full-report-blueprint.md` 建立模板字段、研究设计分支、正文模块、表图附件和验收证据映射。
- [ ] 已为每一部分分配并核对篇幅预算；无官方要求时，中文正文约 19,000–28,000 字符，完整 DOCX 经实际分页约 20–30 页 A4，核心部分没有被平均压缩成短段落。
- [ ] 研究现状/证据缺口、研究意义、目的/问题/假设、研究内容和方法的所有适用子模块均有实质性段落，不是只有标题或一句空话。
- [ ] 纳排标准、变量和终点操作性定义、样本量/精度、数据管理、质量控制、偏倚/混杂、缺失/敏感性、统计分析、伦理、风险和计划均已覆盖。
- [ ] 观察性、随机对照、预测/诊断、质性/混合方法等设计特异模块已经匹配；不适用模块有理由，不使用相互矛盾的内容填充。
- [ ] `python skills/graduate-opening-report/scripts/validate_proposal.py <docx> --mode archive` 通过；`--strict` 仅为旧命令兼容。归档模式默认要求至少 18,000 个提取字符，并阻断待补字段、待核验引文、结构测试标记和连续 `x`；只有官方模板有明确不同要求时才以 `--min-text-chars` 覆盖并记录依据。正文长度、参考文献条目及 DOCX 表格数量仍只是防止短提纲冒充完整报告的下限，不能替代逐节深度和人工内容审查。
- [ ] 若文件是 skill 维护用展示模板，`--mode showcase` 通过且 `--mode archive` 明确失败；每节只有功能性示例开头和显式测试填充，参考文献只标出 `【引文待核验】` 需求，没有虚构出版物。
- [ ] 表格、图件、技术路线、附件和表单具有编号/标题/字段/脚注或签字空位，并在正文或模板中有对应位置。

## 隐私与交付状态

- [ ] 没有把范本中的姓名、学号、导师、单位、联系方式、签字、日期或 PDF 元数据带入通用模板、skill 或审阅成果。
- [ ] 用户本人的元数据只使用其明确提供且确认无误的信息；缺失字段保留待补标记。
- [ ] 工作区和输出包没有残留样本 PDF、原文摘录、临时提取文本或带个人信息的截图。
- [ ] 正式文本没有生成过程、助手口吻、内部路径、变量名或调试日志。
- [ ] 所有阻断项已关闭，需确认项已由用户/学院确认，或交付说明明确列出。
- [ ] 若未完成模板适配、引文核验、Word 渲染或字段填写，交付状态写为“待适配/待核验/部分完成”，不使用“可直接存档”。
