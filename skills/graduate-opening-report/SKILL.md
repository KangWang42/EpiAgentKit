# 研究生学位论文开题报告

把已确认的研究问题、设计、证据和学院模板组织成内容完整、可评审、可追溯、可归档的开题报告。正式报告文件必须生成可编辑的 `.docx`；净文本或结构化 Markdown 只能作为方案锁定和写作中间稿，不能替代正式 Word 交付或证明达到学院存档质量。完整内容要求和设计分支见 [完整开题报告内容蓝图](references/full-report-blueprint.md)，正式写作前必须读取。

## 1. 先锁定范围与依据

1. 用户要求从零生成或结构性重写时视为 P；明确要求学院存档、正式提交或提交前质控时按 R 的严格检查执行。
2. 先读取 `biostat-principles`。涉及流行病学或生物统计研究设计时继续读取 `epi-study-design`；需要新增或核验方法、指南、量表或引文时使用 `evidence-research`。开题正文的生成与终审均使用 `academic-humanizer` 的共同学术语体门控；实际 `.docx` 读写加 `docx`；PDF 范本或输入加 `pdf`。
3. 在写作前记录唯一依据和状态：学校/院系当前模板及版本、学位层次、专业、研究题目、研究问题或假设、研究设计、研究对象、暴露/干预、结局、数据来源、时间窗、样本量或精度依据、统计方法、伦理状态、作者字段和提交时间。缺失信息使用 `[待补充：字段]` 或 `[待核验：依据]`，不得用常见做法代替。
4. 分组、终点、纳排标准、主要分析、多个合理页式或模板存在冲突时停在安全点，请用户确认；不能用“默认模板”掩盖会改变研究含义的选择。

## 2. 识别模板与范本共性

- 学校研究生院、院系当前官方模板和用户明确要求优先于任何师兄师姐范本。范本只用于学习组织、版式层级、表格用途和语言节奏，不复制原句、研究内容、数据、题名、姓名、学号、导师、单位、联系方式、签字或元数据。
- 读取 PDF 范本时只保留脱敏的 `template_profile`：页面尺寸与方向、封面/表单/正文/参考文献/评议页的顺序、标题编号层级、表格和签字栏用途、图表位置、字体层级和页眉页脚特征。不得把样本主题或个人字段写入 skill、模板或审阅成果。
- 若模板未知，先给出中性结构并列出必须由学校确认的项目：纸张和页边距、字体字号、标题编号、页眉页脚、封面字段、签字/评议页、参考文献格式、页数或字数、技术路线图格式、装订和提交格式。
- 页面和字体不能从少数范本推断为学校硬规则。已有模板时保留其样式；没有模板时采用克制的黑白层级、可读中文正文和可编辑表格，并明确这是待适配稿。

## 3. 组织完整报告

先完整读取 `references/full-report-blueprint.md`，建立“模板字段—研究问题—设计分支—正文模块—表图附件—验收证据”映射，再按院系表单的真实顺序映射标题。下列功能骨架只是导航，不能用标题数量替代完整正文；每个适用模块都必须有实质性论证、来源或明确的待核验状态。

同时建立逐部分篇幅预算。学校或用户有明确字数/页数时以其为准；没有明确要求时按蓝图的中性范围完成约 19,000–28,000 个中文正文字符，并把封面、目录、表图、参考文献、附件和表单装配为约 20–30 页 A4 当前版。总篇幅达标不能代替分节深度；背景与现状、研究方法等核心部分分别达到预算，低于范围时记录可核验理由。

内容矩阵是逐部分生成的控制表，不是写完后的目录或登记表。每个章节、表格和图件在生成前至少登记：研究对象或数据输入、研究动作、主要变量或终点、与方法的衔接、预期输出、停止条件/依赖、唯一证据来源、篇幅预算、状态和验收证据；随后按行逐部分生成并逐项验收，确认该行的内容组件、术语、证据和格式均已关闭后，才能进入下一部分或 DOCX 装配。某项不适用时记录理由，不用空段或重复表格填充。

逐部分生成步骤固定为：锁定本行输入和证据 → 生成该部分的完整段落/表图 → 对照内容组件和篇幅预算检查 → 做事实、术语、论断强度和表图映射终审 → 标记“已验收”并移到下一行。发现缺失、冲突或待确认事项时保留该行的阻断状态，不用下一部分的字数或总字数掩盖。

1. 封面与基本信息：题目、学位层次、专业/方向、作者、导师、单位、日期等，仅填入用户确认的信息。
2. 立题背景及依据：问题负担或理论背景、已有研究与证据、不一致或空白、为何现在开展本研究；每个外部事实有可核验来源。
3. 研究目的与研究问题：默认使用单层“研究目的”，在其中区分主要、次要和探索性问题，并明确研究对象、比较、结局、时间窗和目标 estimand；只有官方模板或用户明确要求时才拆成“总体目标/具体目标”。零假设表不是通用组成，仅在模板、导师或已确认统计方案明确要求时生成。
4. 研究内容：按目的列出研究任务、主要/次要终点、变量构建和各任务之间的依赖关系。
5. 研究方法：设计与研究场景、目标人群和纳排、样本量/精度、数据与测量、暴露或干预、结局、协变量和混杂控制、偏倚控制、质量控制、缺失数据、统计分析、敏感性分析、伦理与数据安全。
6. 技术路线或研究流程：用可编辑流程图、表格或文字步骤表示从资料来源到分析和产出的关键节点；正文解释关键决策和停止条件，不能只放一张装饰图。
7. 预期结果：写可验证的结果类型、表图和解释边界，不提前编造效应量、P 值、样本量、研究发现或结论。
8. 研究亮点、特色及创新性：只写相对已有工作可核验的设计、数据、测量、方法或应用差异，不使用“首次、最佳、填补空白”等未经证据支持的宣传性表述。
9. 可行性分析：数据可得性、样本或场景进入、技术和团队能力、时间、经费、伦理与风险应对；区分已经具备、待确认和需要申请的条件。
10. 各阶段工作计划：按月份或阶段写资料准备、伦理/数据获取、清洗、分析、论文和预答辩等任务，日期与研究周期一致。
11. 参考文献及附件：按学校指定格式列出已核验来源；附件只放实际需要的量表、变量表、流程图、报告清单或伦理材料。
12. 表单、导师意见、评议或考核页：若官方模板要求，保留字段、空位、签字和日期位置；不替任何人填写意见或签名。

完整报告不得省略研究现状与证据缺口、研究意义、研究假设/estimand、纳入与排除标准、变量和终点操作性定义、样本量或精度依据、数据管理与质量控制、偏倚/混杂控制、缺失与敏感性分析、伦理与数据安全、风险应对、设计特异模块、表图附件和正式表单。对不适用的设计模块记录理由，不用空泛段落填充。

### 长报告分块完成

一次难以稳定生成完整报告时，先建立逐节 todo/内容矩阵，至少记录章节功能、研究对象/数据输入、研究动作、主要变量或终点、方法衔接、预期输出、停止条件/依赖、所需输入、证据来源、研究设计依赖、拟用表图、篇幅预算、状态和验收结果。按矩阵逐部分生成：完成一行的事实与证据核验、段落功能、语言终审和表图映射后将该行标记为已验收，再处理下一行；任何未关闭的行都不得被压缩成一句话、跳过或直接装配。按以下依赖顺序分块完成：模板与字段 → 背景/现状/证据缺口 → 目的/问题/假设 → 研究内容与方法 → 技术路线和表格 → 预期结果/创新/可行性/计划 → 参考文献/附件/表单 → DOCX 整体装配。

每一块先做事实与证据核验、章节功能检查、术语和方法一致性检查，再进入当前 DOCX；不要把未经终审的片段直接拼接。最后统一核对题目、目的、终点、样本量、分析、伦理、表图、引文、编号、目录、分页和交付状态。todo 只用于内部制作和恢复进度，不进入正式报告；所有适用部分关闭前不得称为完整报告。

## 4. 生成正文与证据链

- 直接陈述研究对象、动作、依据、条件和范围；不以“本研究拟回答……”“本课题建立在……”“由于……所有结果均……”等结构元话语或全局免责声明代替实质内容。每一节先完成其研究功能，再处理段落衔接和语言；不写程序实现或内部变量名。真实局限和证据边界要保留，并用与设计匹配的术语表达。
- 先建立“论断—依据—适用范围”表。区分用户提供的事实、项目结果、外部文献、方法依据和待核验内容；找不到真实来源时保留待补标记，不编造文献、DOI、伦理号、基金号、数字或机构要求。
- 研究设计和统计内容必须与 PROTOCOL/SAP 或用户确认口径一致。观察性研究使用关联、差异或预测等与设计相符的表述；不把计划写成已经完成，不把预期结果写成研究发现。
- 方法段落要达到可复核程度：说明研究对象如何进入、变量如何定义、主要终点和时间窗、分析集、主要模型及其假设、混杂/偏倚控制、缺失和敏感性处理、质量控制、伦理与隐私。具体参数、阈值、样本量和软件版本只来自已确认方案或来源。
- 表格用于压缩可核对信息：研究问题与变量表、纳排标准、终点定义、时间表、风险与应对、分析计划和文献清单等。表头、单位、脚注和缩写完整，不能用空泛占位表格制造“完整感”。
- 技术路线图服务于研究复现和评审，节点必须对应正文的对象、数据、分析和产出。生成前在内容矩阵登记“适用/不适用”及理由；适用时建立“正文方法—流程节点—图件/表格—DOCX 位置”的一一对应，并核对节点输入、动作、输出、责任和停止条件。需要统计图时调用 `publication-figures`；需要流程/机制图时调用 `research-visuals`，若必须交付精确可编辑 SVG 才使用 `svg-diagrams`。

## 5. 版式与文件交付

- 先复制或基于官方模板工作，保留其页式、样式、表单和签字栏。模板没有明确要求时才设置中性默认：白底黑字、层级清楚、表格克制、避免装饰色块；不得把样本 PDF 的具体尺寸或字体硬编码为院系标准。
- 生成 `.docx` 时按完整报告蓝图装配全部适用正文、表格、技术路线、附件和表单；把页面大小、方向、页边距、正文和标题样式、表格宽度、分页、页眉页脚和页码显式设置；目录和页码使用可更新字段，不手敲最终页码。技术路线和表格保持可编辑，图片提供清楚的替代文字。
- 交付前按 `docx` 的结构检查、渲染和重新打开流程验证文件；若环境缺少渲染工具，报告“未完成视觉分页核验”，不能声称已可直接存档。文本交付也必须通过结构、证据、占位符和隐私检查。
- 正式文件中不保留样本 PDF、原文摘录、个人信息或脱敏前提取物；工作区中的样本在本轮完成验证后按用户要求删除。

## 6. 验收与状态表述

按用途选择互斥的预检模式，再按适用内容 skill 做人工终审：

- 正式提交或归档运行 `scripts/validate_proposal.py <报告.docx> --mode archive`；旧命令 `--strict` 仅作为同义兼容。该模式要求完整 DOCX、默认至少 18,000 个提取字符，并阻断待补字段、待核验引文、`x` 测试填充和其他占位内容。只有官方模板明确要求更短或更长时，才使用 `--min-text-chars` 覆盖默认下限并记录依据。
- 维护本 skill 的完整结构展示时运行 `--mode showcase`。测试模板允许每节先写一句该节应完成的研究功能，再用明确标注的 `【结构测试填充：……】` 和连续 `x` 检验篇幅、分页与装配；需要引文的位置只能写 `【引文待核验：……】`，不得编造来源。该模式只证明模块、设计分支、篇幅、表格和 DOCX 流程完整，不能证明正文质量或归档资格。
- 方案早期诊断使用默认 `draft` 模式；警告不会被包装为正式通过。

至少核对：

- 模板字段、标题层级、目录/页码、表格和签字栏与官方版本一致；
- 研究问题、目的、内容、方法、技术路线、预期结果、创新性、可行性和计划前后一致；
- 默认目标为单层“研究目的”；任何“总体目标/具体目标”分层和零假设表都有模板、导师或统计方案依据；
- 内容矩阵逐项关闭了研究对象/数据输入、研究动作、主要变量或终点、方法衔接、预期输出、停止条件/依赖和验收证据；技术路线若适用，正文、流程节点、表图和 DOCX 位置逐项对应；
- 所有数字、方法事实、引文、伦理信息和机构要求都有来源或明确待核验标记；
- 没有把计划写成结果，没有因果化或夸大创新，没有空洞段落、重复表格、生成痕迹或个人信息泄露；
- `.docx` 能打开、渲染后的分页和断行可读，完整报告的表格、技术路线、附件、签字栏和最终文件名/提交版本含义明确。

只有官方模板已确认、信息和引文已核验、未留阻断性占位符、文件检查与视觉检查均通过，才称为“可直接用于学院存档”。否则明确交付为“内容完成待模板适配”“待核验稿”或“部分草稿”，并列出责任人和下一步。
