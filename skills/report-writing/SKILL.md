# 专业报告写作

论文与投稿材料转 `academic-publishing`，咨询包打包转 `consulting-delivery`，已有文字的局部润色可只用 `academic-humanizer`。

## 1. 确认报告要求

只确认会改变内容的事项：读者、用途、采用的事实或结果来源、报告类型、允许修改的范围、输出格式和必须回答的问题。缺失但不影响事实的标题、层级和中性格式可直接采用保守默认。工作区或用户同时提供既有方案、报告或模板时，先逐个声明它是内容来源、版式母版、两者兼具还是仅供背景。用户明确说明只取内容时记为内容来源；用户要求根据或参照同一研究的 Word 生成、续写报告时记为内容与版式来源。多个合理文件或角色并存且不同选择会改变成品时，先请用户确认。

新建或结构性重写完整报告、包含多张正式表图的报告，或完整报告文件的首次装配时，必须读取 [报告装配与当前任务验收清单](references/report-assembly.md)，把内容与文件分别列为工作项并汇总已经确认的要求。已有报告的局部文字、表格、图片或格式修改仍按 L 处理，只更新和核对实际受影响的段落、表图与页面；一次用户纠正或一次重新保存本身不触发整份报告重审。完整流行病学研究报告、阶段结果分享或委托人汇报同时读取 [流行病学研究报告蓝图](references/epidemiology-report-blueprint.md)，先锁定读者决策、适用内容、正文与内部核查边界和表图计划，并按当前问题选择和组织论文式内容。

- Q：只回答问题，不创建报告。
- L：单段、单节、备忘或一个指定文件，只验证该产物。
- P：报告会成为项目当前正式结果时，才同步受影响的结果、表图和方法决定。
- R：明确外发、归档或正式审查时才核验授权、隐私、当前版并运行正式发布检查。

## 2. 数据与证据

数字来自以下已经确认的来源之一：新项目的 `results/results.yaml`、旧项目结果文件、已经核对的正式表格，或用户明确指定的外部正式结果。用脚本生成报告时，按每项结果的固定名称读取数字，不重复调整格式或手工输入。流程、操作或进展报告不一定需要项目结果文件，但采用的事实必须位置明确且可以核验。

- 源中没有的数字、日期、引用或决定不猜测；正式成品前清除或明确接受待确认项。
- 数字需要变更时，回到实际生成结果的分析脚本，或由用户明确指定并确认的外部结果；不得直接修改报告、表格或图注中的数字。
- 观察性结果不写因果结论，探索性发现不升格为主要结论。
- 内部脚本路径、调试、试错、日志和实现过程不写进面向读者的研究结果报告；操作指南本身需要路径或命令时除外。
- 同一项目有论文、报告、复现说明和内部核查等多类成品时，分别声明允许信息、排除信息和输出位置。对外正文与内部核查分开不等于隐藏会改变分析集、偏倚、结果或结论的问题；这些影响仍须在责任人可见的正式位置如实呈现。

## 3. 结构与长度

研究、分析和结果报告使用与论文一致的学术句法、论证方式、统计表达和证据边界，内容范围以当前问题为界，只采用完成该问题所需的论文部分。先完整回答读者最关心的问题，再按事实、时间、比较或操作关系展开。重要结论应有依据，必要限制和后续行动应放在相应部分。结构与长度由任务复杂度决定，不强制背景—方法—结果—结论模板，也不设最低字数；短报告可以简洁，但不能省略理解结论所必需的内容。

常见形式：

- 分析报告：问题与范围、数据与方法、关键结果、不确定性、局限和结论。
- 决策备忘：结论、依据、风险、待决定事项。
- 进展报告：已完成、证据、阻塞、下一步与责任。
- 操作指南：前提、步骤、检查、停止条件和故障处理。
- 会议纪要：决定、依据、行动项、责任和期限。

段落、列表和表格按信息功能选择。连续论证用段落，真正并列的行动、风险和步骤用列表或表格，不为“报告感”机械分节。包含多张正式表图时，先按 `report-assembly.md` 建立编号、功能、来源、位置、题注和引用清单，再写正文和装配文件；不得按文件遍历或生成顺序自动编号。

## 4. 表图与输出文件

只加入对当前读者有独立贡献的表图，不因目录中存在就全部嵌入。现有正式表图优先复用；需要新统计图时调用 `publication-figures`，流程或框架图调用 `research-visuals`。表题、图题、编号、尺寸和格式服从实际 Markdown、Word 或其他指定文件及机构要求。报告图只保留读图所必需的对象、坐标、单位、图例和必要数值，不在图内添加解释性段落或 `OR（对数……）` 等教材式文字。

用户只要正文时直接返回净稿，不创建文件。用户要求完整报告文件时，不得以聊天摘要或 Markdown 草稿代替；已有当前报告、项目约定或已经判定的版式母版时沿用，格式仍不清且会改变工作量时只问一个简短问题。指定 Markdown 或 Word 时只生成用户指定格式的文件，不擅自附加另一种格式；实际 `.docx` 操作调用 `docx`。

报告 Word 采用连续的黑白学术文档：正文、标题、题注、页眉页脚和表格文字均为黑色，页面和表格单元格保持白底，以字号、字重、间距、对齐和必要黑/灰细线建立层级。科学图件按其内容 skill 保留经核验的必要颜色，Word 正文继续使用黑白学术版式。采用默认版式时可复用 `references/build_report.py` 装配已完成正文；视觉要求与验收仍由 `docx` 负责。

## 5. 语体

中文正式报告在写作与终审中执行 [共用中文语言编辑门控](../academic-humanizer/references/chinese-academic-style.md)，再用 `academic-humanizer` 审查事实保真、内容功能、论证结构、论断强度、术语、作者视角、学术书面语和真实披露边界。研究结果报告中的摘要、背景、方法、结果、解释、建议、局限和结论按各自功能控制语体；决策备忘、进展报告、操作指南和会议纪要仍围绕读者任务组织，不强行套论文结构。

新建、结构性重写或正式发布完整报告时，在各部分写作后先做局部审校，装配当前完整版本后再做跨部分终审。L 局部修改只终审指定段落、表图及因其变化而必须调整的相邻文字，不因一次用户纠正重新审查全稿。发现内容或统计逻辑疑问时单列给作者或责任人核实，不在语言修改中猜值、改结论或增加解释。

## 6. 完成条件

- 报告直接回答读者问题，长度与复杂度匹配。
- 每个关键数字、事实、引用和决定都能回到已经确认的来源。
- 表图确有实际用途，且与正文和结果来源一致。
- 多表报告的编号、内容功能、来源、正文或附录位置、题注和引用与写作前清单一致。
- 完整流行病学报告已按读者问题重写，实际采用的研究设计和统计方法要求有明确位置；内容功能、统计字段对账和目标文件显示分别通过。
- 既有方案、报告和模板的角色已经记录；使用版式母版时，成品版式由母版基线和已经确认的变化组成。报告 Word 符合连续黑白学术文档的字体、页面、层级、表格和题注规范。
- 新建、结构性重写或正式发布完整报告时，当前任务的全部确认要求均已核对；L 重新生成后只复查实际受影响且此前检查已失效的要求。正式研究结果报告没有无读者功能的生成状态、工具说明、内部路径、运行日志或执行者自述。
- L 范围外差异为零；P/R 中实际受影响的结果、表图、正文、授权和当前版已经同步。
- 语言编辑未改变研究事实、统计量、分组、变量含义、证据层级或结论边界；仍需核实的内容或统计逻辑问题已经单列，未被流畅措辞掩盖。
- 文件按请求生成且可打开；Word 文件同时通过 `docx` 的结构、任务专属要求和适用页面检查，无法渲染时明确未验证范围；只要正文时没有多余过程文件。
