# 技能知识检索

用于跨技能或大量 references 中查找细则。已有任务分流表和技能描述决定工作范围，SQLite 只帮助定位文件。普通研究任务可直接调用工具，无需加载维护技能。

## 从任务到原文

1. 先按用户请求和现有工作区确定 Q/L/P/R 范围、内容技能与文件技能；已经知道的必读文件直接打开。
2. 细则位置不明确时，提取具体任务、方法或文件术语，用 `search` 查询。已确定技能时带 `--skill`；寻找技能入口时可用 `--kind skill`。中文使用两个字以上的词，例如“缺失数据”；多个检索词用空格分开，如“修订 事实”。
3. 依据返回的用途、标题、章节和路径判断候选。默认最多六项，可用 `--limit` 调整到 1–20 项；数量是显示上限，不是必读文件配额。工具按词项相关度排序，不判断科学定义或是否适用。
4. 对尚不熟悉的候选用 `peek` 核对真实文件头、哈希和同库链接，再直接读取适用正文。文件头被截断会明确标记，不能把预览当作完整规范。已知候选可以直接打开，不额外重复 `peek`。
5. 无匹配、候选不适用或仅正文出现关键词时，改用 skill 中的链接或 `rg` 检索明确目录。不能把元数据未命中解释为没有要求，也不能因排名较低跳过适用的必读细则。

仓库内入口：

```bash
python scripts/epiagentkit.py lookup search "缺失数据" --skill r-biostats
python scripts/epiagentkit.py lookup peek r-biostats/references/regression.md --lines 30
python scripts/epiagentkit.py lookup build --verify
```

安装后的入口是实际 `epiagentkit-maintenance` 技能目录中的 `scripts/knowledge_index.py`。用同样的参数直接执行该文件；默认检索脚本所属的 skills 目录。需要检查另一份安装时显式传入 `--root <skills目录>`，参数放在 `search`、`peek` 或 `build` 前。不猜运行时技能目录，也不合并其它插件或另一客户端的库。

## 数据来源与更新

索引仅包含指定 skills 目录下的 `SKILL.md` 和 `references/**/*.md`。程序从现有 `description`、Markdown 标题、开头段落提取用途和章节，保存相对路径、所属技能、文件类型、时间、大小与 SHA-256；不另写一份技能说明，不要求批量添加 YAML 文件头。文件复杂时先按原有标题和链接分层查找；只有真实检索用例证明标题或开头说明不足时，才在原文改进其说明。

SQL 表与 FTS5 保存上述元数据及其检索词，不保存正文副本、用户会话、研究数据、凭证、生成结果或历史版本。目录范围明确，符号链接和 Windows junction 不被跟随。Markdown 是唯一维护位置；SQLite 是可丢弃、可重建的派生缓存，不接受人工规则入库。

每次查询会枚举允许的文件名并检查时间和大小，只重新读取发生变化的文件，删除源文件时清除对应记录。这里仍有文件系统扫描，但不会把整份目录或全文送入模型。`peek` 再读取目标并核对 SHA-256，防止把过期摘要当成当前原文。需要排除时间戳未变等情况时运行 `build --verify` 全量核对哈希。

缓存默认位于 skills 的上级 `.epiagentkit-cache/`，数据库名按源目录区分，保留在本机、不随技能分发。`--cache-dir <目录>` 可指定其它可写位置，但不能放进 skills；仓库试验使用本批次 workbench。索引损坏或格式升级时运行 `build --rebuild`，先完整生成再替换缓存。更新失败时返回错误，不继续展示旧记录。SQLite 同事务维护元数据与搜索表；重建也用于释放长期删除后的空闲页。

文件同步后，下次查询自动更新该客户端自己的缓存，无需额外同步数据库。没有 Python、FTS5 或写权限时退回原有文件检索，不安装运行时、不改分析语言。

## 长期积累与验证

发现可复用经验时先定位现有唯一维护位置，核对是否已涵盖，再修正原条目及调用者；项目事实仍留在项目文件，一次性材料仍留在 workbench。缓存不承接这些内容的确认责任。不要为每次纠正新增一份摘要、情景文件或数据库记录，也不要从历史聊天自动提取未确认的规则。

维护工具时覆盖中文与英文、按技能筛选、无匹配、增删改与改名、缓存损坏恢复、路径越界、链接隔离和安装副本。对实际查询记录首次建库、重复查询耗时、重新读取的文件数、返回字符量及目标文件是否命中。对比对象使用相同技能范围和检索词；字符数不换算成未经测量的 token。检索测试不能证明模型自动分流、科研准确率或端到端任务速度提高。

实现依据：[SQLite FTS5](https://www.sqlite.org/fts5.html) 的匹配与 BM25；[Python sqlite3](https://docs.python.org/3.13/library/sqlite3.html) 的参数绑定和事务。中文用连续双字词项，词内要求共同命中，不把只含“数据”的文件当作“缺失数据”的匹配；这仍是词项检索，不是语义搜索。
