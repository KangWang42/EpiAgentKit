# 来源驱动的科研图规划与审校

本规范用于完整论文、项目材料、多图系列、由多个子图组成的复杂图件和带参考图的任务。目标是先决定“是否需要图、图要证明什么、内容从哪里来”，再进入 imagegen。单张图需求已经给出明确内容、比例和用途时，可只执行简要图前说明。

## 1. 图件计划表

完整论文或项目不按章节机械配图。先读取与任务有关的章节、方法、结果、表图、模板和项目规则，建立候选矩阵：

| 字段 | 要求 |
| --- | --- |
| 候选 ID | 稳定短标识，不预先占用正式图号 |
| 科学问题 | 该图只回答一个什么问题 |
| 核心命题 | 读者数秒内应理解的一句话 |
| 所依据的材料 | 文件、章节、小节、表、results.yaml 中的结果名称或已核验文献 |
| 证据属性 | 统计数据、原始证据、证据综合、解释插图或精确结构图 |
| 信息角色 | 正文内容图、真实截图、氛围插图、统计图、原始证据或无需图片 |
| 独立贡献 | 相比现有正文和其它图新增什么理解 |
| 图类与使用位置 | 图类、PPT/论文/标书/报告/网页及实际占位 |
| 绘制方式 | `publication-figures`、保留原始证据、`research-visuals`；仅在 imagegen 不可用或有明确矢量要求时使用 SVG |
| 文字与模板 | 图内必须逐字呈现的标签；模板必须保留与允许调整的部分 |
| 采用理由 | 为什么图比文字、表格或现有图更清楚 |
| 拒绝理由 | 无独立贡献、证据不足、最终尺寸不可读或其它原因 |

只有同时满足以下条件的候选才进入生成：

1. 有明确的依据，或明确标为拟议机制、研究假设、解释示意。
2. 有不可由已有图表或短段落等价替代的独立信息贡献。
3. 在最终页面或图位尺寸下能保持核心关系和必要标签可读。

章节存在不等于需要配图。完整论文也不得默认“每个主要章节一张图”。

## 2. 图前说明

新图、重大重绘和由多个子图组成的图件在生成前确认八项：

1. **核心命题**：一句话说明图要传达的结论、关系或路径，不写“本图展示了”。
2. **来源与边界**：列出所依据的材料、证据属性、可以抽象的内容和禁止推断的内容。
3. **各部分的作用**：写明每个区域或子图的独立作用；移除后不影响理解的部分应删除。
4. **结构原型**：选定主阅读方向、分支、合并、反馈、时间或层级关系。
5. **尺寸与版式要求**：确定实际比例、占位、最终物理或像素尺寸、背景和安全区；按 `carrier-specs.md` 核对最长标签的自然字宽、节点内边距、箭头、间距和侧栏是否能放入可用宽度，并明确不得使用窄体压缩或非等比缩放。
6. **风险清单**：预先标出精确文字、数字、因果、解剖、来源、可访问性和裁切风险。
7. **信息与文字作用**：判定正文内容图、真实截图或氛围插图。内容图先对候选文字做删除测试，只将删除后会造成对象、关系、条件、状态或核心结论歧义的文字列入 `Text (verbatim)`；截图必须来自真实产物；氛围图才默认无字。定义、理由、完整方法、限制与来源优先移到正文、图注或复杂图的详细说明。
8. **模板适配**：列出尺寸、品牌、字体、色彩、安全区和必要组件等必须保留项，以及区域数量、阅读方向、图文比例、密度和视觉权重等允许调整项。

轻量改色或明确的单点修正只需确认“必须保持的内容、目标问题、最终尺寸”三项，不重复完整规划。

## 3. 结构原型

原型由信息之间的关系决定，不套用固定期刊风格：

| 原型 | 适用关系 | 关键要求 |
| --- | --- | --- |
| 单向主链 | 流程、技术路线、研究设计 | 4 至 7 个主阶段，起点与输出闭合 |
| 并行汇聚 | 多源数据、多分支模型、多研究问题 | 共用输入清楚分叉，汇入唯一整合或输出节点 |
| 总览加局部 | 复杂模型、关键部分、跨尺度机制 | 总体图交代位置，局部图只放大一个部分，两者对应关系明确 |
| 多类证据组合 | 机制或概念图与真实统计图或证据图组合 | 各子图保持原有证据属性，统一配色与边距，不让示意图替代数据 |
| 对照矩阵 | 方法、路径或状态的并列比较 | 比较维度一致，不生成虚构指标或占位数据 |
| 时间或层级 | 随访、项目计划、系统层级 | 时间、依赖或包含关系不能混用普通流程箭头 |

由多个子图组成的图件不预先指定一个占据最大面积的主要子图。证据重要性确有差异时，让核心子图获得更大面积；等权比较、诊断矩阵和对称实验应保持相同视觉重点。子图顺序按研究内容排列，并逐对检查是否重复使用相同数据、回答相同问题、可由另一子图直接推导，或删除后仍不影响核心信息。

## 4. 模块内微型图元

复杂流程或模型图中的模块不应只是空框和方法名。允许在模块内放置一个与真实操作对应的微型图元，例如波形、频谱、矩阵、特征图、数据表轮廓、空间网格或小型关系网络，但必须满足：

- 图元直接说明该模块的输入、变换或输出，而非填满空白。
- 统计图缩略图只能来自真实图件或抽象轮廓，不生成似真数值、坐标和趋势。
- 同类模块共享图元语法；关键模块可增加细节，辅助模块保持简洁。
- 最终尺寸下无法辨识时删除，不把复杂细节缩成噪声。

## 5. 参考图解构与编辑目标

先区分图片的角色：仅用于借鉴风格、布局或信息组织的是**非编辑参考**；用户要求保留视觉身份并修改、重绘或继续修正的图片是**编辑目标**；用户只要求提取事实和关系、重新组织内容且不继承原设计的是**内容来源**。三者不能混为一类。

### 5.1 非编辑参考解构

非编辑参考只提供可迁移的组织方法，不自动成为证据或模板，也不随全新生成调用上传。先在调用外查看原图，把可迁移信息转写为纯文本提示词，再按以下顺序处理：

1. **核验身份**：记录来源、作者或仓库、链接、版本和许可证。无法核验时只标为风格参考，不引用其科学内容。
2. **双尺度查看**：查看原始分辨率，再按目标页面或图位尺寸查看；只在大图成立的微小细节不迁移。
3. **分层提取**：分别记录核心问题、结构关系、阅读顺序、视觉重点、配色作用、文字密度、微型图元和页面适配。参考图的宽高比、节点宽度和字体形态只作为观察项；目标页面不匹配或存在压窄时记入反例，不迁移。
4. **内容与样式分离**：保留可迁移的结构和视觉逻辑，不复制论文专属数据、公式、标签、机构标识或装饰特征。
5. **反例记录**：同时写明不可复制的拥挤、伪文字、错误标注、无来源机制、固定配色和生成痕迹。

解构记录使用：`来源身份 → 图的任务 → 为什么有效 → 可迁移规则 → 不可复制内容 → 最终尺寸结论`。所谓 Nature、Cell、CVPR 或 NeurIPS 风格不能替代目标期刊正式要求，也不能作为事实依据。

### 5.2 确定文档或页面中的待修改图件

Word、PPT、PDF、HTML 或导出包中的媒体文件名只是存储标识，不是图的实际身份。确定待修改原图前按以下顺序定位：

1. 用户明确指向的图号、图题、页面、幻灯片或正文位置。
2. 图题与正文交叉引用、替代文本、相邻段落和页面顺序。
3. 文档关系、媒体绑定和渲染后主体、标签、比例与配色的视觉核对。
4. 提取文件名或媒体序号只作为回到实际文件的定位线索，不据此推断正式图号。

图在文档中的位置和含义与存储名称冲突时，以图题、正文引用、文档关系和渲染结果的共同核对为准；仍有多个候选时先并排查看，只有无法确定待修改图件时才向用户提出一个问题。独立计算机方法图确需在图面烧录标题时只保留一个简短标题，副标题、覆盖标签、版本摘要、来源和实现说明由图注、正文或配套审计成果承担。

通用 skill 只保存定位方法、所需信息和核对规则。图号、文件名、标签、方法名、阈值、比例、配色和单次修改等项目专属事实只进入本次任务记录或项目记录，不回写通用 skill、references 或示例。图号、图题、论文标题和来源说明由 Word、PPT、网页或排版系统处理时，不烧录进图片。

### 5.3 根据原图修改或按内容重构的要求

需要修改既有图片、根据既有图重绘、修正上一版成图或按图中内容彻底重构时，先建立缩略要求：

| 字段 | 要求 |
| --- | --- |
| 待修改原图 | 唯一需要编辑的图片，也是核对修改结果的依据；保留原件，记录来源和当前版本 |
| 内容来源图 | 只提供文字、数字、对象、节点和关系；转写并核验清单后不附给全新生成，不继承原图布局、比例、卡片、颜色或审美 |
| 可选参考图 | 用户已经提供或指定且确有帮助时使用；只参考经核验的配色、空间安排、阅读顺序和线条表现，不照搬宽高比、节点宽度、窄体字体或压缩变形 |
| 图在文档或页面中的位置 | 由用户指向、图题或正文交叉引用、页面位置与文档关系共同确认 |
| 项目专属事实 | 本次来源支持的标签、方法、阈值、比例、配色和修正要求；只用于本次任务 |
| 由文档或网页排版的文字 | 由 Word、PPT、网页或排版系统处理、不得烧录进图片的图号、图题、标题或来源说明 |
| 单一修改 | 本轮只解决一个主要问题，写成可观察的变化 |
| 必须保持 | 不得改变的文字、数字、公式、对象、人物身份、节点、连线、方向和结论 |
| 表现身份锁 | 不得改变的真实/写实/示意类型、时相图、概率图、热区图、矩阵等关键微型图元，以及裁切、材质和已认可局部质量 |
| 可以调整 | 允许优化的版式、间距、字体层级、配色、线宽、背景和视觉重点 |
| 不得改变 | 不得添加、删除、纠正、推断或合并的内容 |
| 核验基线 | 初始原图、上一轮结果和最终页面或图位尺寸 |

- 所有需要附带的图片都有本地路径时使用 `referenced_image_paths`；只能从近期对话取得图片时，使用能够覆盖全部必要图片的最小 `num_last_images_to_include`；两者不得并用。一种附图方式不能覆盖全部图片时，优先附带待修改原图；可选参考图对修正确有帮助时再请用户重新附图。
- 待修改原图提供全部内容与身份。用户已经提供或指定且参考图确实能改善视觉表达、空间安排或结构时才加入可选参考图，禁止从中复制对象、标签、数据、错误布局或品牌。上一轮结果需要继续修改时，可以把上一轮结果作为本轮待修改图片，但仍须与最初原图核对，防止多轮修改造成内容偏移。
- 内容来源图先转写为精确事实、拓扑和覆盖清单。全新生成时不附带该图；只有用户要求多个用途、最终图位确需拆图或单图无法成立时，才把架构沟通和审计明细等任务分给不同成果，并分别写清覆盖范围，不能把原图的拥挤或卡片墙当作“内容完整”的必要形式。
- 按 `事实语义 → 精确文字、数字、公式和身份 → 对象、节点、箭头和关系 → 表现身份、关键微型图元、裁切、材质与已认可质量 → 最终尺寸可读性 → 视觉完善` 的顺序核对。修改结果更美观但任一高优先级项目变差时，保留待修改原图。
- 最多连续修改两轮；用户已经提供且确有帮助的参考图可以在任一轮使用，不为使用参考图单独增加一轮。第二次修改后保存该图作为当前结果，分别说明内容硬伤、表现身份漂移、审美问题、影响和未通过的检查，再询问用户是否继续；不自动重生整图或改用 SVG。不可替代的用户原图不得重新生成后冒充原图修改。
- 统计图回到分析代码修改，科研原始证据只做允许的确定性处理，均不得使用生成式图片修改。
- 第一次 HTTP 524 使用同一目标重试一次。可以删除重复形容词和通用禁止项，但必须保留全部事实、文字、节点和连接关系；第二次 524 停止并保留待修改原图，不把超时计为设计失败，不静默降级模型或切换 SVG/API。

## 6. 图外规划与实际调用包

提示词不设固定字数。写到足以消除结构歧义即可，复杂不等于冗长。生成前在调用外整理以下字段；这是来源与验收工作表，不得原样粘贴给 imagegen：

```text
Figure ID: <候选 ID>
Source material: <文件/章节/表图/results.yaml 中的结果名称/核验文献>
Core claim: <一句核心命题>
Evidence class: <证据属性>
Information role: <正文内容图 / 真实截图 / 氛围插图；其它证据类按原路线>
Final use and size: <论文、PPT、报告或网页，比例、实际占位>
Geometry and typography: <可用宽度、节点/侧栏容量、必要的重排方式、正常字宽、保持宽高比、禁止非等比缩放>
Template requirements: <必须保留 | 允许调整 | 根据内容调整的版式>
Archetype and reading order: <结构原型、主方向>
Regions: <区域 ID | 比例位置 | 任务 | 内容>
Micro-visuals: <模块 ID | 与真实操作对应的微型图元；无则 none>
Icon strategy: <正式研究流程/研究设计/技术路线/病例流转/方法架构固定为 none，禁止 emoji、pictogram、clip-art 和小图标；只有图形摘要、机制示意或科普/教学插图可记录大型图像型例外及其内容贡献>
Image inputs: <待修改原图决定事实、文字、结构、真实/写实/示意类型、关键微型图元、裁切、材质与已认可质量；内容来源图已转写事实与关系且不附给全新生成；可选参考图仅提供经核验的配色、空间安排、阅读顺序和线条表现>
Target location and project-specific facts: <图在文档或页面中的位置、实际待修改原图、项目专属事实、由文档或网页排版的文字>
MUST PRESERVE / MAY ADJUST / MUST NOT CHANGE: <必须保持的准确内容、允许调整的视觉形式和禁止变化的内容>
Nodes and edges: <精确节点、边、方向、关系>
Text (verbatim): <必须逐字准确的短标签>
Text selection: <身份标签 | 必要关系/条件 | 少量消歧限定语 | 移到正文/图注/长描述的解释>
Palette roles: <常规路径/辅助或对照/警示或关键状态；默认两类主色相，必要时第三类，主色相总数不超过三种；黑白灰中性色不计>
Safe zones: <标题、正文、按钮、裁切和图注区域>
Must not infer: <不得生成或推断的内容>
Avoid: <本任务的反例与生成痕迹>
```

完成规划后，按 `prompt-recipes.md` 只装配 `USE`、`CONTENT LOCK`、`GRAPH OR LAYOUT`、`VISUAL DIRECTION`、`CONSTRAINTS` 五段。来源路径、Figure ID、采用理由、300 ppi 换算、验收日志和问题记录保留在图外；模型只接收生成当前成果所必需的内容。精确图谱使用 `NODES: ID="label"; ...` 与 `EDGES: source>target; ...`，同一 ID 和同一边只写一次，汇聚拆成多条有向边。编辑任务每轮只写一个可观察修改目标，并重新列出直接相关的不变量。

完整论文生成多张图时，每个候选必须记录所依据的材料、核心信息、采用理由和建议比例，不得只保存一段脱离来源的长提示词。长提示词可以工作，但不能据此承诺 imagegen 完美遵循密集文字或精确拓扑；关键文字、节点、边、数字和公式仍须逐项核对，未通过就按实际失败报告。

## 7. 四轮终检

### Pass 0: 必要性与证据

- 候选满足必要性条件；所列依据真实存在。
- 统计图、原始证据和解释示意选择正确。
- 无虚构结论、数值、公式、解剖、期刊要求或来源。
- 真实 UI、终端、代码、文档和成果示例采用实际渲染截图，不由 imagegen 伪造。

### Pass 1: 内容与结构关系

- 核心命题、内容链和区域贡献一致。
- 节点、文字、数字、箭头、方向、分支、合并和反馈逐项准确。
- 组合图没有回答相同问题、重复使用相同数据或没有独立作用的填充子图。
- 修改结果与待修改原图对照后，关键文字、身份、节点和边均完整保留。
- 局部编辑与初始原图、上一轮结果对照后，真实/写实/示意类型、关键微型图元、裁切、材质和已认可质量均未发生非目标漂移。
- 按内容重构的结果与内容来源清单逐项对照后事实和关系一致，同时没有继承用户已经否定的布局或审美。
- 正文内容图含理解结构所需的准确短标签；氛围图才把标题与正文全部交给 PPT、Word 或网页排版。

### Pass 2: 视觉与可读性

- 原始分辨率下无伪文字、重复对象、解剖或物理错误。
- 要求纯色平涂的色块和矩阵单元内部均匀、不透明；渐变、白雾、中心高光、颗粒或色噪、随机深浅、纹理和透明叠色分别检查。
- 层级、主次、负空间、配色角色和微型图元有语义。
- 流程图主色相不超过三种，通常使用两类语义色；第三类仅对应真实警示、失败、异常、不良结局或关键状态。
- 最终尺寸下文字、箭头、轮廓和各子图仍可辨识；颜色不是唯一线索。
- 画布比例有实际页面或图位依据；中文字形、圆形和方形保持自然几何，节点未因单行过载而压窄。
- 模板已根据信息关系调整结构、层级、密度、留白和图文比例，没有机械套版或把内容硬塞进预设卡片。

### Pass 3: 嵌入后显示

- 已嵌入真实 PPT、论文页、标书、报告或网页渲染检查。
- README、技术文档和教程已检查桌面与窄屏显示、真实截图清晰度、替代文本和文件体积。
- 比例、裁切、安全区、图注、替代文本、打印或投影均符合实际论文、PPT、报告或网页要求。
- 修改结果通过所有高优先级检查后才替换待修改原图；美学改进不能补偿事实、精确内容、结构或可读性退化。
- 所有 must-fix 处理完成后才能正式交付；建议项可以记录但不得掩盖失败。
