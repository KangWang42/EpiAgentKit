# Imagegen 科研视觉工作流

把 imagegen 作为科研非统计图件的默认生成方式，而不是固定画风生成器。先判断最终使用位置（论文、PPT、报告或网页）、读者、信息功能、证据属性和实际显示尺寸，再选择主体、文字、视觉语言与配色。科研感必须来自真实主题和关系，不来自 DNA、显微镜、试管或公式堆砌。科研内容图默认必须呈现具体对象、字段、关系、流程状态、方法模块或真实截图依据；除网页装饰或用户明确要求的特殊场景外，不生成没有任务内容的空泛概念插图。模板可按需调整，科学性、内容清晰度与最终可读性优先于套版一致。

## 图像生成工具

- Codex 使用当前会话提供的内置 `imagegen` 技能和 `image_gen` 工具；其它平台使用当前会话明确提供且已经配置的图像生成工具。
- 调用前确认完整提示词、全部输入图片、目标用途和验收条件。所有目标图片都有本地路径时传入这些路径；只能从近期对话取得图片时，使用能够覆盖全部目标图片的最小 `num_last_images_to_include`。
- 按工具实际返回的图片或文件路径保存和检查结果，不猜输出位置，不修改会话历史，也不把 data URL、base64 或内联图像内容写入项目文件。
- 缺少必要输入图片时，说明缺失条件并停止。只读检查确认当前会话没有可用的图像生成工具时（例如 Claude Code 未配置图像生成），流程、框架、机制、技术路线、研究设计和病例筛选等精确结构图记录证据后转 `svg-diagrams`；写实场景、封面、解释性插图等 SVG 无法替代的图件说明缺失条件并停止。任何情况下都不另写 API 脚本，也不静默改用 CLI、第三方 API 或其它生成模型。

## 必读资源

- 每次生成前读 [视觉策略](references/visual-strategy.md) 与 [美学、内容取舍与文字边界](references/visual-and-text-rules.md)，确定图片作用、风格、配色、材质与文字边界。
- 按最终使用位置读取 [不同版式规格](references/carrier-specs.md) 中对应的 PPT、论文、标书、报告或网页章节。
- README、技术文档、项目主页、教程、skill 示例、真实截图、成果展示或已有模板任务，完整阅读 [场景选择指南](references/scenario-playbook.md)。
- 输入是完整论文、项目材料、多图系列、由多个子图组成的复杂图件或参考图时，先读 [图件规划](references/figure-planning.md)。
- 生成流程图、框架图、机制图、研究设计、技术路线或图形摘要前，完整阅读 [科研图件模式](references/research-figure-patterns.md)，并必须读取并完整执行 [无图标边界与图像型例外](references/diagram-iconography.md)（该文件是 L0、方法图元和图像型例外的唯一规则来源）。
- 计算机科学、人工智能、机器学习、信号处理、软件系统、数据系统或计算方法图件，完整阅读 [计算机视觉图件](references/computer-science-visuals.md)；医学人工智能等混合场景按各部分证据属性分别处理。
- 内容要求确认后读 [提示词写法](references/prompt-recipes.md)；需要扩展架构或复杂多图提示词词汇时，先读 [外部上游说明](references/external/SOURCE.md) 再按需查阅上游原文，不得把上游文件当独立 skill 直接执行。
- 修改既有图片、重绘上一版、按内容重构或遇到 HTTP 524 时，必须完整读取并执行 [图片编辑不降质与 HTTP 524 处理](references/edit-and-retry.md)。

## 证据属性检查

先给目标视觉归类，不能为了“更美观”跨越证据边界：

1. **证据型原始图像**：显微、病理、影像、临床照片、仪器输出、原始截图、凝胶等不得由 imagegen 新造、补全、净化或重绘；仅做期刊允许且不改变信息的确定性处理，保留原文件。
2. **统计数据图**：效应量、区间、分布、时间、空间等统计量通过坐标位置、长度、面积、角度、颜色、大小或连续比例等视觉通道表达时，调用 `publication-figures`，不得让 imagegen 虚构或改变映射。
3. **精确结构图**：流程、病例筛选、机制、框架、路线、研究设计和图形摘要归入本类。节点出现已核验样本量、排除人数、日期、阈值、比例或结果数字不会把结构图变成统计图；作为准确标签随节点和箭头由 imagegen 生成并逐字逐边核对，有误时按 `references/edit-and-retry.md` 最多定向修改两轮，不用 Python、PPT/Word 文本框或 SVG 覆盖层补字。
4. **解释与编辑插图**：科学教育插图、研究场景、概念配图、封面、网页主视觉和标书配图默认用 imagegen。
5. **界面控制图标**：按钮、工具栏、导航和状态控件优先复用 Lucide 或项目既有图标系统；定制功能插画和空状态可用 imagegen。
6. **真实界面与成果截图**：软件界面、终端、代码、文档、PPT、表格、实际图件和交付包示例运行或渲染真实产物后截图，不得由 imagegen 伪造。

## 开始前检查

- 命中本技能 `description` 后先加载本技能与所需 references，再选路径；当前可见 skills 清单未列出本技能不等于 `image_gen` 不可用，也不是转 SVG 的依据。
- 触发本技能不等于每页都要生成图片。PPT 先逐页确定主要表达方式，目录、定义、公式、创新、可行性和计划页若文字/表格/公式更清楚，不生成装饰插图；README/网页先逐位标记 `内容图/真实截图/氛围图/统计图/原始证据/无需图片`。
- 信息足够时直接执行；只有缺失项会明显改变内容、比例或留白方向时最多问一个必要问题。用户要求实际出图或嵌入文档时，必须完成生成、看图、修正、保存、嵌入并检查实际显示，不得停在方案或提示词。
- 通用 skill 只保存可迁移规则；项目专属的正式图号、导出文件名、标签、阈值、比例、配色和单次修正只进入本次任务记录或项目记录。

## 核心工作流

0. **规划图件集合**：完整论文、项目或多图请求先按 `figure-planning.md` 制定图件计划，逐项写明每张候选图的来源、独立作用和采用理由，不按章节机械配图；单张明确请求只需确认必要性、核心信息和不可缺元素。
1. **读取实际文档或页面**：核对模板/页面的比例、占位、背景、配色、字体和相邻文字。定位文档中已有图件时以用户指向、图题交叉引用和位置为准，导出文件名和媒体序号仅作存储线索，不得从中推断正式图号。按场景标记 `说明研究内容的图/真实截图/氛围插图`。
2. **确认用途、类型与领域分支**：单选主用途（解释关系/建立情境/提示功能/区分章节/突出创新/展示路径/品牌识别），区分正文内容图、真实截图与氛围插图（网页 hero、登录页和章节氛围图默认无字），并按计算机或流病/临床对象分流图形语法。
3. **审查模板适配与横向容量**：拆出模板的必须保留与允许调整项，按 `carrier-specs.md` 用实际图位核定宽高比并估算最长标签正常字宽的横向容量。模板迫使流程变成卡片墙、层级变平或压缩节点/文字时重排或拆图，不得压扁图元或非等比缩放。
4. **写图件要求**：内部 ≤120 字写明用途、读者、核心命题、依据材料、视觉语言、构图、配色、目标比例、留白与禁止项；用于论文印刷或指定 DPI 时写明毫米尺寸、目标 ppi 与最低像素。
5. **确认内容和图中文字**：根据实际来源材料核对对象名称、关系、数字和结论，并按 `references/visual-and-text-rules.md` 确定 `Text (verbatim)`、正文内容图/氛围插图边界及删除说明的处置（不得把删除说明机械转移到图注或正文，但重要局限、阴性或不利结果、伦理合规披露和期刊强制信息如实放入恰当位置）。
6. **统一系列图视觉表达**：同项目共享配色、光线与材质语言，配色与材质细则见 `references/visual-and-text-rules.md`；正式科研流程的 L0、方法图元和图像型例外按 `diagram-iconography.md` 执行。
7. **构造最小提示词包**：图外规划保存完整事实、语义分辨率与像素计算；规划表不得整段粘给 imagegen。按 `prompt-recipes.md` 装配 `USE`、`CONTENT LOCK`、`GRAPH OR LAYOUT`、`VISUAL DIRECTION`、`CONSTRAINTS` 五段（空字段省略，同一事实只写一次），精确图谱用短 ID 紧凑邻接表且汇聚拆成多条有向边；每轮编辑只设一个可观察修改目标，不承诺提示词能保证 imagegen 完美遵循；真实像素靠调用参数与文件验收保证，不靠提示词中的 `300 dpi`、`4K` 或 `print-ready`。
8. **生成并保存**：成果数量、覆盖范围和使用位置服从用户当前请求，不擅自增加近似版本；全新生成不附带非编辑参考图；真实界面与成果渲染后截图；项目采用的成果移入工作区。
9. **按本次修改选择检查**：新图或重大重绘查原始尺寸与最终显示尺寸；局部修改先查目标区域与不变内容。印刷/指定 ppi 核对实际像素（`像素 = 毫米 ÷ 25.4 × ppi`），插值放大或仅改元数据不算通过。嵌入文档保持原始宽高比，不得横向或纵向拉伸。
10. **根据原图定向修改或按内容重构**：修改既有图、重绘上一版、按内容重构或遇 HTTP 524 时，完整执行 `references/edit-and-retry.md`（不降质 6 级优先级、待修改原图/内容来源图/可选参考图分工、最多连续修改两轮后停止自动修改并把该图保存为当前结果并披露问题；HTTP 524 不计入两轮内容修改）。
11. **在实际成品中复核**：新图、重大重绘、尺寸/比例变化及 P/R 交付放进实际文档、PPT 或网页检查一次；网页和 README 的相应图位检查桌面与窄屏显示、替代文本与体积；局部显示修改未变尺寸位置时只确认成品已用新图。
12. **记录与归档**：正式项目记录图件要求、提示词、工具、核验结论和改用它法的原因；当前版稳定命名，旧版与未采用候选整组归档；提示词与生成过程不入正文。

## 选择图像生成方式

- imagegen 可用时，流程、框架、示意图和图形摘要不得因“SVG 更容易”提前跳过。
- 仅在用户明确要求 SVG、矢量源、完全可编辑图形、编辑现有 SVG 或目标格式强制矢量，或只读检查确认当前没有可用 imagegen 路径时（并记录不可用证据）调用 `svg-diagrams`。
- imagegen 已返回但文字、数字、节点、连线、布局或美学不合格，或遇 HTTP 524，均不得据此转 SVG。改用其它绘图方式时保持已确认的信息结构不变。

## 最少检查

每项检查必须能指出本次修改可能造成的一种具体错误；不能说明所防止错误的检查不执行，也不新建检查表、状态文件或缓存记录。

- 局部改图只检查两项：目标内容已经按要求修改且其余内容未被误改；实际使用该图的论文、报告、PPT 或交付文件已经更新。
- 新图或重大重绘按 `figure-planning.md` 检查必要性与证据、内容和结构关系、最终尺寸可读性、实际成品中的显示。
- 数据、统计方法、结果、图件尺寸或位置改变时增加对应检查；正式发布再加期刊、机构或归档要求。已通过且本次修改不会影响的检查不重复执行。
