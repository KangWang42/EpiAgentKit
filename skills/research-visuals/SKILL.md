# Imagegen 科研视觉工作流

把 imagegen 作为科研非统计图件的默认生成方式，而不是固定画风生成器。先判断图片最终用于论文、PPT、报告还是网页，以及读者、信息功能、证据属性、信息角色和实际显示尺寸，再选择主体、文字策略、视觉语言、材质、构图、配色与细节密度。科研感必须来自真实主题和关系，不来自 DNA、显微镜、试管、冷蓝界面或公式堆砌。科研内容图默认必须呈现具体对象、字段、关系、流程状态、方法模块或真实截图依据；除网页装饰或用户明确要求的特殊场景外，不生成没有任务内容的空泛概念插图。模板是可调整的要求集合，不是不可改变的构图答案；科学性、内容清晰度和最终可读性优先于套版一致。

Codex 使用内置 `imagegen` 技能及其 `image_gen` 工具。不要另写 API 脚本，不猜模型参数，不把 CLI/API 当作内置工具失败后的静默替代。其它平台只使用当前会话明确提供且已配置的图像生成工具。

## 图像生成工具

- Codex 使用当前会话提供的内置 `imagegen` 技能和 `image_gen` 工具；其它平台使用当前会话明确提供且已经配置的图像生成工具。
- 调用前确认完整提示词、全部输入图片、目标用途和验收条件。所有目标图片都有本地路径时传入这些路径；只能从近期对话取得图片时，使用能够覆盖全部目标图片的最少轮次。
- 按工具实际返回的图片或文件路径保存和检查结果，不猜输出位置，不修改会话历史，也不把 data URL、base64 或内联图像内容写入项目文件。
- 工具不可用或缺少必要输入图片时，说明缺失条件并停止；不另写 API 脚本，也不静默改用 CLI、第三方 API 或其它生成模型。

## 必读资源

- 每次生成前读 `references/visual-strategy.md`，确定图片作用、风格、构图和系列图一致性。
- 按图片最终使用位置读取 `references/carrier-specs.md` 中对应的 PPT、论文、标书、报告或网页章节。
- README、技术文档、项目主页、教程、skill 示例、真实截图、成果展示或已有模板任务，完整阅读 `references/scenario-playbook.md`，先选内容图、截图或氛围图路线，再确定文字与模板策略。
- 输入是完整论文、项目材料、多图系列、由多个子图组成的复杂图件或参考图时，先读 `references/figure-planning.md`，逐项列出每张候选图所依据的材料、独立作用和采用理由，再完成图前说明、参考图分析和四项必要检查。
- 生成流程图、框架图、机制图、研究设计、技术路线或图形摘要前，完整阅读 `references/research-figure-patterns.md`，确认这类图应包含的内容、证据属性和表达方式。
- 计算机科学、人工智能、机器学习、信号处理、软件系统、数据系统或计算方法图件，完整阅读 `references/computer-science-visuals.md`；医学人工智能等混合场景按图中各部分的证据属性分别处理，不用计算机风格覆盖真实原始图像或统计图规则。
- 生成流程图、研究设计、技术路线、病例流转或方法架构时，必须读取并完整执行 [无图标边界与图像型例外](references/diagram-iconography.md)；该文件是 L0、方法图元和图像型例外的唯一规则来源。
- 内容要求确认后读 `references/prompt-recipes.md`，选择相应的提示词写法。
- 计算模型、网络架构、由多个子图组成的复杂图件或需要扩展提示词词汇时，先读 `references/external/SOURCE.md` 的调用规则，再按需检索所列上游原文；不得把上游文件当独立 skill 直接执行。
- 同时遵循内置 `imagegen` 的生成、编辑、保存位置、目标图选择和透明背景规则；全新创作只提供文字要求，修改既有图或修正上一版时附带待修改原图。

## 证据属性检查

先给目标视觉归类，不能为了“更美观”跨越证据边界：

1. **证据型原始图像**：显微、病理、影像、临床照片、仪器输出、原始截图、凝胶或其它研究证据，不得由 imagegen 新造、补全、净化或重绘。仅做期刊允许且不改变信息的确定性处理，并保留原始文件。
2. **统计数据图**：效应量、区间、分布、时间、空间或其它统计量通过坐标位置、长度、面积、角度、颜色、大小或连续比例等视觉通道表达时，调用 `publication-figures`，不得让 imagegen 虚构或改变映射。
3. **精确结构图**：流程、病例筛选、机制、框架、路线、研究设计和图形摘要按信息关系分流到本类。节点中出现已经核验的样本量、排除人数、日期、阈值、比例或结果数字，不会把结构图变成统计图；这些数字作为准确标签随节点和箭头一起由 imagegen 生成并逐项核对。先用 imagegen 生成包含最小充分文字及必要数字、箭头的整张图并逐字逐边核验。结果有误时按第 10 步最多定向修改两轮，不用 SVG 覆盖、重画或补字。
4. **解释与编辑插图**：科学教育插图、研究场景、概念配图、封面、网页主视觉和标书配图默认用 imagegen。
5. **界面控制图标**：按钮、工具栏、导航和状态控件已有 Lucide 或项目图标系统时直接复用，不生成位图替代；定制功能插画、内容卡片和空状态可用 imagegen。
6. **真实界面与成果截图**：软件界面、终端、代码、文档、PPT、表格、实际图件和交付包示例优先运行或渲染真实产物后截图；不得让 imagegen 生成看似真实但不可复核的 UI、命令、论文页或结果预览。

## 不降质要求

图片编辑和重绘必须以待修改原图为内容核对依据，而不能把它当作可覆盖的临时输入。提示词只能降低风险，不能保证修改结果更好；原图始终保留，修改结果只有通过全部核对要求后才成为当前版。

按以下优先级比较待修改原图与修改结果，前项不能用后项补偿：

1. 事实与语义忠实度。
2. 文字、数字、公式和人物或对象身份的精确性。
3. 对象、节点、箭头、分支、汇合和关系的正确性。
4. 表现身份与关键微型图元的保持，包括真实/写实/示意的表示类型、对象类别、裁切、视角、材质、概率图或热区图的功能，以及用户已经认可的视觉质量。
5. 最终显示尺寸下的可读性。
6. 视觉精修。

修改结果更美观但任一高优先级项目变差时，判定失败并保留待修改原图。不得覆盖、删除或改名原图，直到修改结果通过对应图类的全部核对要求。

必须明确每张参考图的作用：

- **待修改原图**：唯一需要编辑的图片，也是核对修改结果的依据。图中的科学内容、人物或对象身份、结构关系、表现类型、关键微型图元和已经认可的局部质量均以此图为准。
- **内容来源图**：用户要求根据图中事实重新组织、重构布局或按内容重画，但不要求保留原图视觉设计时使用。先逐项提取并核对文字、数字、对象、节点和关系，把原图只作为事实清单与结果审计依据；布局、比例、分区、颜色、图形语法和审美均不继承。完成清单后按全新创作调用 imagegen，不附带内容来源图，避免生成工具继续模仿其构图；原图保持只读并在生成后逐项对照。
- **可选参考图**：仅当用户已经提供或指定，并且确实有助于改进配色、空间安排、阅读顺序或线条表现时使用。不得从参考图复制对象、标签、数据、错误布局或品牌，也不得让参考图决定目标画布比例、节点宽度、正常字宽或任何压缩变形。
- 不为凑足图片数量寻找或生成参考图。已有确有帮助且来源已经核对的参考图时，可用于一次生成或修改；不存在有用参考图时直接省略，不增加额外步骤。参考图不能改变待修改原图的内容要求。

## 开始前检查

- 命中本技能 `description` 后，必须先加载本技能与所需 references，再选择实现路径。当前可见 skills 清单未列出本技能，不等于 `image_gen` 不可用，也不是转 SVG 的依据。
- PPT 任务先为每页指定主要表达方式。触发本技能不等于每页都要生成图片；目录、章节、目的、定义、公式、创新、可行性和计划页若用模板、文字、表格、公式或时间轴表达更清楚，应明确不生成装饰插图。
- README、技术文档和网页任务先为每个图位标记 `内容图/真实截图/氛围图/统计图/原始证据/无需图片`。正文中的工作流、架构、技能示例和成果路径不得误判为无字装饰插图。
- 信息足够时直接执行。只有缺失项会明显改变内容、比例或留白方向时，最多提出一个必要问题；其余按实际文档或页面和现有视觉系统作保守判断。
- 通用 skill 只保存可迁移的方法、字段和验收规则。项目专属的正式图号、导出文件名、标签、方法名、阈值、比例、配色和单次修正只进入本次任务记录或项目记录，不写回本技能或 references。
- 用户要求实际生成图片、PPT、论文、标书、报告或网页时，不得停在方案、提示词或“正在运行”。必须完成生成、查看原图、修正、保存、嵌入，并检查实际文档或页面中的显示。

## 核心工作流

0. **规划图件集合**：完整论文、项目或多图请求先按 `figure-planning.md` 制定图件计划，逐项写明每张候选图的来源、独立作用和采用理由。只保留来源明确、具有独立信息贡献且能在最终尺寸成立的候选；不按章节数量机械配图。单张明确请求只需回答：为什么需要、读者看完应知道什么、哪些元素不可缺、删去哪项会改变正确解释。不能回答独立的科研问题，或已有文字、表格和图件已经能够同样清楚地表达时，不新增图片。
1. **读取实际文档或页面**：检查模板、页面或网页的比例、占位、背景、配色、字体、相邻文字、按钮位置和已有图片。文档或页面中的图先按用户指向、图题与正文交叉引用、页面或段落位置、文档关系和渲染外观定位；导出文件名和媒体序号仅作存储线索，不得从中推断正式图号。PPT 先按页型标记 `插图/统计图/原始证据/表格/公式/流程图/时间轴/纯文字`；README、技术文档和网页按图位标记 `内容图/真实截图/氛围图/统计图/原始证据/无需图片`；没有现成视觉系统时才建立新的系统。
2. **确认图片的主要用途和类型**：只选一个主要用途：解释关系、建立情境、提示功能、区分章节、突出创新、展示路径或形成品牌识别；再确定图片属于`说明研究内容的图/真实截图/氛围插图`。说明研究内容的图必须包含理解结构所需的具体对象、字段、短标签和关系，不能只用抽象图标、渐变背景或象征性设备填充画布；截图必须来自真实可核对的产物；只有用户明确选择网页装饰或特殊氛围场景时才把标题和正文留给 PPT、Word 或网页排版。
   同时按研究对象选择领域分支：计算机相关图件以数据表示、计算模块、接口、维度、控制或数据流为主要语法；流行病学、临床和公共卫生图件仍以研究对象、设计、时间、变量、证据状态和实施路径为主要语法。混合图先拆分证据属性，再组合版面，不按论文所属院系给整张图套一种风格。
3. **审查模板适配与横向容量**：把模板拆成 `必须保留` 与 `允许调整`。保留尺寸、品牌、字体、核心色和必要组件；按 `carrier-specs.md` 先用实际图位核定宽高比，再根据最长标签的正常字宽、内部图元、节点内边距、箭头、间距和侧栏估算横向容量，同时记录各区域适合横向、近方形或纵向的自然形状。没有既定图位时由内容计算自然比例，横向完整架构可以采用约 2:1、21:9 或其它合适宽幅，但加宽后仍形成一排高窄列时必须改为双行、大小不一的编辑分区、上下布局、分面或拆图。模板迫使流程变成卡片墙、比较失去对称、层级变平、节点过窄、文字或图元压缩时同样重排；不得用窄体字、压扁图元或非等比缩放硬塞，也不得在内容本可重排时仅用无限加宽掩盖布局问题。
4. **写图件要求**：在内部用不超过 120 字写明最终使用位置、读者、一句核心命题、所依据的材料、图片类型、文字处理、主体、风格、构图、模板适配、配色来源、材质、目标比例、图形完整性、留白和禁止出现的内容。位图用于论文、印刷或用户指定 DPI 时，同时写明最终毫米尺寸、目标 ppi、据此计算的最低像素；提示词中的 `300 dpi`、`print-ready` 或 `4K` 不作为分辨率证据。不得先套固定画风。
5. **确认内容和图中文字**：根据实际来源材料核对对象名称、关系、数字和结论，再列出各区域必须提供的信息，以及必须出现、必须逐字准确、可以简化、不得出现和不得推断的对象、文字、数字与关系。计算机相关图件同时按 `computer-science-visuals.md` 选择完整架构、方法总览或模块详解，并按实际来源建立不限层数的语义分辨率清单；来源或用户要求触发完整架构时，不得为留白、克制或避免贴近参考图而删除已经确认的模块、重复块、维度、公式、训练目标或关系。独立的计算机方法图需要烧录标题时只保留一个简短标题；副标题、覆盖标签、版本摘要、来源、导出参数、实现备注和页脚句子移到正文、图注或内部核查材料。来源没有的结论、期刊标识、仪器读数或医学细节不得补写；只有删除后不影响当前科研问题的区域才删除。说明研究内容的图只把删除后会造成对象、关系、条件、关键状态或核心结论误读的文字列入 `Text (verbatim)`；定义、理由和完整方法按实际作用放入正文、图注或详细说明。内部制作问题和不影响读者解释的项目短板默认留在内部核查材料，不能因从图中删除就机械转移到图注或正文。会改变科学解释的重要局限、阴性或不利结果、伦理合规披露和期刊强制信息仍须按内容工作流如实放在恰当位置。不得为避免伪文字而删除必要标签，也不得给每个节点机械添加副标题。
6. **统一系列图的视觉表达**：同一项目的系列图共享主色来源、光线方向、材质、线条或摄影语言；不同内容结构和使用位置按实际尺寸重新安排结构、密度和裁切，不能把同一模板机械复制到所有图片。流程图默认使用两类有明确含义的主色相，只有真实警示、失败、异常、不良结局或必须单独识别的关键状态才增加第三类；全图主色相不超过三种，黑、白、灰等中性色不计入。不得把蓝白配色作为科研流程的默认答案，也不得为了避免单调而随机换色。正式科研流程的 L0、方法图元和图像型例外按 `diagram-iconography.md` 执行。
7. **构造最小提示词包**：先在调用外按 `figure-planning.md` 保存来源、核心命题、证据属性、完整事实与关系、语义分辨率、模板适配、300 ppi 像素计算和验收要求；规划表不得整段粘给 imagegen。实际调用只按 `prompt-recipes.md` 装配 `USE`、`CONTENT LOCK`、`GRAPH OR LAYOUT`、`VISUAL DIRECTION`、`CONSTRAINTS` 五段，空字段省略，同一事实、节点、边和约束只写一次。精确图谱用短 ID 的 `NODES` 与 `EDGES` 紧凑邻接表，汇聚拆成多条有向边；计算机相关图件仍须包含当前覆盖模式需要的全部节点和边，并在空间不足时明确采用分区、多行主链、局部展开或拆图。每轮编辑只设一个可观察修改目标并重述直接相关的不变量。用具体图形要求替代“高级、科技感、学术感”，不设机械字数下限，也不承诺提示词能保证 imagegen 完美遵循；生成后仍逐字、逐节点、逐边核对。工具暴露质量参数时，密集标签或复杂信息图优先比较 `medium` 与 `high`；真实像素和 300 ppi 由调用参数与文件验收保证，不靠提示词中的 `300 dpi`、`4K` 或 `print-ready`。
8. **生成并保存任务要求的成果**：成果数量、覆盖范围和使用位置服从用户当前请求，不擅自增加近似版本。全新生成不附带非编辑参考图；真实界面与成果先运行、渲染或打开实际文件后形成真实截图或文档结果，不调用 imagegen 伪造。项目采用的成果必须移入工作区，不得只留在 `$CODEX_HOME/generated_images/`。
9. **按本次修改选择检查**：新图或重大重绘按原始尺寸和最终显示尺寸执行适用检查。局部修字、调色、降噪、移动、删除说明或其它显示修改，每轮先查看目标区域，并与修改前版本核对必须保持的内容和表现方式；不重复与本次修改无关的全图、系列图或成品检查。连续修改时先生成预览图确认目标变化，本轮已知修改全部明确后，再进行一次交付前检查。位图用于正式论文、印刷或用户指定 ppi 时，交付前读取实际像素与 DPI 元数据，按 `像素 = 毫米 ÷ 25.4 × ppi` 核对目标物理尺寸；仅改写元数据或插值放大不能算通过。嵌入论文、PPT、报告或网页时保持原始宽高比；若目标位置的比例不匹配，使用留白、裁切或重新生成，不得横向或纵向拉伸。真实截图同时检查敏感信息、光标、通知、无关窗口、缩放和裁切。
10. **根据原图定向修改或按内容重构**：用户要求修字、调色、降噪、移动局部、保持风格或修正上一版时，把图片作为待修改原图，先写清四类要求：必须保持的文字、数字、公式、身份、对象、节点、连接、方向和结论；必须保持的表现身份，包括真实/写实/示意类型、关键微型图元、图像裁切、材质和已认可的局部质量；可以调整的版式、间距、字体层级、配色、线宽、背景和视觉重点；不得添加、删除、纠正、推断、合并、替换或简化的内容。用户说“重新画图”但仍只要求修正纯色、噪声、文字或单条连线等局部问题时，仍按待修改原图路线处理，不得把局部修正扩大成重新解释整张图。只有用户明确要求重新组织全部内容、重构整体布局或放弃原图视觉设计时，才把图片作为内容来源图；此时先形成完整事实、关系和需要继续保留的表现身份清单，再按全新创作生成，不附带原图，也不继承用户已经否定的区域、比例、卡片、颜色或阅读路径。只有待修改原图路线才把全部必要图片通过 `referenced_image_paths` 或能够覆盖全部输入的最小 `num_last_images_to_include` 附给工具，两者不得并用。一种附图方式不能同时包含待修改原图和可选参考图时，优先保留待修改原图；只有参考图对修正确有帮助时才请用户重新附图。每轮只修一个主要问题并重复四类要求；成功返回的修改结果必须与初始原图和上一轮结果逐项对照，任何非目标文字、结构、图元、表示类型、裁切或已认可质量发生漂移都判定本轮失败，保留修改前版本，不把新图提升为当前版。最多连续修改两轮；现有参考图确有帮助时可在任一轮使用，不为使用参考图单独增加一轮。第二次修改后停止自动修改、整图重生和 SVG 切换，把该图保存为当前结果；分别列出仍存在的内容硬伤、表现身份漂移、审美问题及其影响，明确说明哪些检查未通过，再询问用户是否继续修改。不可替代的用户原图始终保留，不以重新生成的图片冒充修改成功。
11. **在实际成品中复核**：新图、重大重绘、改变比例或显示尺寸的修改，以及 P/R 交付，把拟采用成果放进实际 PPT、论文页面、标书页、README、技术文档或网页，本轮已知修改全部明确后查看一次相应页面。只改图内一个显示项，且成品中的图片位置、尺寸和裁切均未改变时，沿用最近一次页面检查，只确认论文、报告、PPT 或交付文件已经使用新图；不要重复渲染无关页面。网页和 README 的相应图位检查桌面与窄屏显示、替代文本和文件体积，PPT 的相应页面检查缩略图和投影尺寸。存在多个候选时，用户选定当前版后再按既有项目规则替换正式引用；未选定前保留清楚的候选标识。
12. **记录与归档**：正式项目记录实际成果的要求、提示词、使用工具、核验结论和改用其它绘图方式的原因；存在多个候选时再记录差异与用户选择。当前版使用含义明确且长期不变的文件名，未采用候选和旧版整组归档。提示词和生成过程不进入正文。

交付前按 `figure-planning.md` 选择本次修改可能影响的检查：必要性与证据、内容与结构关系、视觉与可读性、实际成品中的显示。新图和重大重绘执行四轮；局部修改只重查它可能改变的内容。数据与材料来源、图件内容、作图方式和实际使用位置均未改变时，沿用最近一次成功检查。所有必须修改的问题处理完成后才能交付；参考图或外部示例不能替代来源核验。

## HTTP 524

把 HTTP 524 视为附带图片生成时的服务或传输失败，不是修改结果的质量问题，也不计入两轮内容修改：

1. 第一次 524：使用相同的待修改原图、相同必要附件和同一修改目标重试一次；可以删除重复形容词和通用禁止项，但必须保留图片用途、全部节点与连接关系、必须保持的内容、允许调整的内容、不得改变的内容以及核对要求。
2. 第二次 524：停止重试，保留待修改原图，不解释为提示词或设计失败；不静默降级模型，不另写或切换第三方 API，也不因超时改用 SVG。

只有 imagegen 成功返回修改结果才计入两轮定向修改。第二次成功修改后按第 10 步交付当前结果并披露问题，不自动重生整图或改用 SVG。

## 美学要求

- 主体必须一眼可辨。小图保留一个主对象，大图通常保留一个焦点和 2 至 4 个支持元素。
- 优先自然不对称构图、稳定视觉重心和有用途的负空间；避免平均分布、机械居中、边缘拥挤和无意义漂浮。
- 配色优先取自现有论文、PPT、报告或网页。流程图默认使用两类语义主色，必要时增加一类警示或关键状态色，主色相总数不超过三种；中性色用于画布、文字、边框和连接线。红色只用于真实警示、失败、异常、不良结局或当前重点，普通排除、常规步骤和一般分组不自动标红。不把整个项目做成单一蓝色相，也不为“高级感”加入霓虹渐变。
- 材质必须有语义：文献与证据可用纸张、油墨和索引；临床与现场可用自然光纪实；机制与系统可用干净科学插画；数字研究可用克制几何和网格。不得无理由加入玻璃、金属、烟雾、景深或电影灯光。
- 系列资产要有家族一致性，但每张图仍服从其内容角色，不能变成同构卡片墙。

## 文字与关系

- **正文内容图**：README 正文图、工作流、架构图、技能示例、教程内容图、流程图、机制图、技术路线和图形摘要必须直接包含脱离图注仍能理解结构所需的短标签、数字和箭头，并由 imagegen 生成完整图后逐字逐边核验。不得把“网页图默认无字”泛化到正文内容图。
- **氛围插图**：PPT 主视觉、封面、网页 hero、登录页和章节氛围图默认不烧录标题、正文、按钮或长解释；这些文字由 PPT、Word 或网页的文字元素排版。
- **真实截图**：界面、终端、代码、文档、PPT、表格、图件和交付物预览使用实际渲染内容。只保留任务相关区域，隐藏敏感信息；不得用 imagegen 生成可被误认成真实操作或真实成果的截图。
- 内容图文字、数字和箭头必须作为完整图的一部分由 imagegen 直接生成；不得用 Python、PPT 文本框、Word 文本框或 SVG 覆盖层修补错误文字、数字和箭头。真实截图的确定性裁切、缩放和不改变内容的标注不属于补写 AI 图，但标注不得遮盖证据或改写界面状态。
- 图内标签逐字沿用来源材料、研究方案或可核验方法文献中的规范术语。缩短标签只能删除不影响含义的修饰语，并保留术语核心；不得加入内部流程词、软件工程隐喻、口语化动作、生硬直译、自造缩略语或临时拼接的短语。来源未给出且存在多种合理名称时先向用户核实。
- 图题、图号、论文标题、报告标题和来源说明通常由论文、报告、PPT 或网页排版，不烧录进图片，除非目标格式明确要求。
- 生成似真论文页面、仪器界面或档案时，只使用不可辨识的短线、点阵和抽象标记，不生成看似真实但错误的段落与数值。
- 修改既有图片、保持原图设计进行重绘和修正上一版成图时，附带待修改原图。用户只要求提取原图内容并彻底重构时，先形成事实与关系清单，再按全新生成不附带内容来源图。待修改路线只附带全部且仅必要的目标图片；上一轮生成结果需要继续修改时，以该结果作为本轮待修改图片，同时与初始原图核对是否发生内容偏移。
- 非编辑参考不随全新生成调用上传，先把可以采用的图形规则写入提示词；首稿需要继续修改时，如果现有参考能改善视觉表达、布局节奏或结构，可以同时附带一张可选参考图，但必须明确它只提供已经核对的视觉参考，不提供研究内容。用户明确要求同时修改多张目标图时才传入多张待修改图片。

## 选择图像生成方式

- imagegen 可用时，为论文、PPT、报告或网页制作的流程图、框架图、示意图和图形摘要不得因“SVG 更容易”而提前跳过。
- 用户明确要求 SVG、矢量源、完全可编辑图形、编辑现有 SVG 或目标格式强制矢量时，调用 `svg-diagrams`。
- 只读检查确认当前没有可用 imagegen 路径时，可以调用 `svg-diagrams`，并记录工具不可用的证据。imagegen 已经成功返回但文字、数字、节点、连线、布局或美学仍不合格，不得据此转 SVG；HTTP 524 也不自动触发 SVG。
- 改用其它绘图方式时，沿用已经确认的内容要求和图件要求，不因更换工具而改变信息结构。

## 最少检查

每项检查必须能指出本次修改可能造成的一种具体错误；不能说明所防止错误的检查不执行，也不建立新的检查表、状态文件或缓存记录。

- 局部改图只检查两项：目标内容已经按要求修改且其余内容未被误改；实际使用该图的论文、报告、PPT 或交付文件已经更新。
- 新图或重大重绘再检查来源与证据属性、内容和关系、最终尺寸可读性、实际成品中的显示。
- 数据、统计方法、结果、图件尺寸或位置改变时，增加与该变化直接相关的检查；正式发布再增加期刊、机构或归档明确要求的检查。
- 已通过且本次修改不会影响的检查不重复执行。发现真实问题后，只复查该问题和实际受其影响的成品。
