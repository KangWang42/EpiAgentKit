# Imagegen 科研视觉工作流

先按全局 `CLAUDE.md` 判定 Q 问答、L 局部产物、P 项目执行或 R 正式发布；加载本 skill 不扩大范围。

把 imagegen 作为科研非统计图件的默认生成方式，而不是固定画风生成器。先判断图片最终用于论文、PPT、报告还是网页，以及读者、信息功能、证据属性、信息角色和实际显示尺寸，再选择主体、文字策略、视觉语言、材质、构图、配色与细节密度。科研感必须来自真实主题和关系，不来自 DNA、显微镜、试管、冷蓝界面或公式堆砌。模板是可调整的要求集合，不是不可改变的构图答案；科学性、内容清晰度和最终可读性优先于套版一致。

Codex 使用内置 `imagegen` 技能及其 `image_gen` 工具。不要另写 API 脚本，不猜模型参数，不把 CLI/API 当作内置工具失败后的静默替代。其它平台只使用当前会话明确提供且已配置的图像生成工具。

## 图像生成工具

- Codex 使用当前会话提供的内置 `imagegen` 技能和 `image_gen` 工具；其它平台使用当前会话明确提供且已经配置的图像生成工具。
- 调用前确认完整提示词、全部输入图片、目标用途和验收条件。所有目标图片都有本地路径时传入这些路径；只能从近期对话取得图片时，使用能够覆盖全部目标图片的最少轮次。
- 按工具实际返回的图片或文件路径保存和检查结果，不猜输出位置，不修改会话历史，也不把 data URL、base64 或内联图像内容写入项目文件。
- 工具不可用或缺少必要输入图片时，说明缺失条件并停止；不另写 API 脚本，也不静默改用 CLI、第三方 API 或其它生成模型。

## 必读资源

- 每次生成前读 `references/visual-strategy.md`，确定图片作用、风格、构图和系列图一致性。
- 按图片最终使用位置读取 `references/carrier-specs.md` 中对应的 PPT、论文、标书、报告或网页章节。
- README、技术文档、项目主页、教程、skill 示例、真实截图、成果展示或已有模板任务，完整阅读 `references/scenario-playbook.md`，先选内容图、截图或氛围图路线，再确定文字与模板策略。
- 输入是完整论文、项目材料、多图系列、由多个子图组成的复杂图件或参考图时，先读 `references/figure-planning.md`，逐项列出每张候选图所依据的材料、独立作用和采用理由，再完成图前说明、参考图分析和四轮终检。
- 生成流程图、框架图、机制图、研究设计、技术路线或图形摘要前，完整阅读 `references/research-figure-patterns.md`，确认这类图应包含的内容、证据属性和表达方式。
- 流程图、研究设计、技术路线、方法架构或图形摘要需要决定是否使用 icon 时，读取 `references/diagram-iconography.md`；先判定不用图标是否更清楚，再确定数量、复杂度、图标与主题的对应关系、统一风格和配色。
- 内容要求确认后读 `references/prompt-recipes.md`，选择相应的提示词写法。
- 计算模型、网络架构、由多个子图组成的复杂图件或需要扩展提示词词汇时，先读 `references/external/SOURCE.md` 的调用规则，再按需检索所列上游原文；不得把上游文件当独立 skill 直接执行。
- 同时遵循内置 `imagegen` 的生成、编辑、保存位置、目标图选择和透明背景规则；全新创作只提供文字要求，修改既有图或修正上一版时附带待修改原图。

## 证据属性检查

先给目标视觉归类，不能为了“更美观”跨越证据边界：

1. **证据型原始图像**：显微、病理、影像、临床照片、仪器输出、原始截图、凝胶或其它研究证据，不得由 imagegen 新造、补全、净化或重绘。仅做期刊允许且不改变信息的确定性处理，并保留原始文件。
2. **统计数据图**：任何坐标、比例、效应值、置信区间、样本量或真实数据映射，调用 `publication-figures`，不得让 imagegen 虚构。
3. **精确结构图**：流程、机制、框架、路线、图形摘要先用 imagegen 生成包含最小充分文字及必要数字、箭头的整张图并逐字逐边核验。对待修改原图完成必要的定向修改，已经提供且确有帮助的可选参考图也用于修改后，如果允许重新生成的图件仍可再完整生成一次；完成这些适用操作仍不准确时，才整图改用 `svg-diagrams`。
4. **解释与编辑插图**：科学教育插图、研究场景、概念配图、封面、网页主视觉和标书配图默认用 imagegen。
5. **界面控制图标**：按钮、工具栏、导航和状态控件已有 Lucide 或项目图标系统时直接复用，不生成位图替代；定制功能插画、内容卡片和空状态可用 imagegen。
6. **真实界面与成果截图**：软件界面、终端、代码、文档、PPT、表格、实际图件和交付包示例优先运行或渲染真实产物后截图；不得让 imagegen 生成看似真实但不可复核的 UI、命令、论文页或结果预览。

## 不降质要求

图片编辑和重绘必须以待修改原图为内容核对依据，而不能把它当作可覆盖的临时输入。提示词只能降低风险，不能保证修改结果更好；原图始终保留，修改结果只有通过全部核对要求后才成为当前版。

按以下优先级比较待修改原图与修改结果，前项不能用后项补偿：

1. 事实与语义忠实度。
2. 文字、数字、公式和人物或对象身份的精确性。
3. 对象、节点、箭头、分支、汇合和关系的正确性。
4. 最终显示尺寸下的可读性。
5. 视觉精修。

修改结果更美观但任一高优先级项目变差时，判定失败并保留待修改原图。不得覆盖、删除或改名原图，直到修改结果通过对应图类的全部核对要求。

必须明确每张参考图的作用：

- **待修改原图**：唯一需要编辑的图片，也是核对修改结果的依据。图中的科学内容、人物或对象身份和结构关系均以此图为准。
- **可选参考图**：仅当用户已经提供或指定，并且确实有助于改进配色、空间安排、阅读顺序或线条表现时使用。不得从参考图复制对象、标签、数据、错误布局或品牌，也不得让参考图决定目标画布比例、节点宽度、正常字宽或任何压缩变形。
- 不为凑足图片数量寻找或生成参考图。已有确有帮助且来源已经核对的参考图时，在改用 SVG 前至少用于一次修改；不存在有用参考图时直接省略，不增加额外步骤。参考图不能改变待修改原图的内容要求。

## 开始前检查

- 命中本技能 `description` 后，必须先加载本技能与所需 references，再选择实现路径。当前可见 skills 清单未列出本技能，不等于 `image_gen` 不可用，也不是转 SVG 的依据。
- PPT 任务先为每页指定主要表达方式。触发本技能不等于每页都要生成图片；目录、章节、目的、定义、公式、创新、可行性和计划页若用模板、文字、表格、公式或时间轴表达更清楚，应明确不生成装饰插图。
- README、技术文档和网页任务先为每个图位标记 `内容图/真实截图/氛围图/统计图/原始证据/无需图片`。正文中的工作流、架构、技能示例和成果路径不得误判为无字装饰插图。
- 信息足够时直接执行。只有缺失项会明显改变内容、比例或留白方向时，最多提出一个必要问题；其余按实际文档或页面和现有视觉系统作保守判断。
- 通用 skill 只保存可迁移的方法、字段和验收规则。项目专属的正式图号、导出文件名、标签、方法名、阈值、比例、配色和单次修正只进入本次任务记录或项目记录，不写回本技能或 references。
- 用户要求实际生成图片、PPT、论文、标书、报告或网页时，不得停在方案、提示词或“正在运行”。必须完成生成、查看原图、修正、保存、嵌入，并检查实际文档或页面中的显示。

## 核心工作流

0. **规划图件集合**：完整论文、项目或多图请求先按 `figure-planning.md` 制定图件计划，逐项写明每张候选图的来源、独立作用和采用理由。只保留来源明确、具有独立信息贡献且能在最终尺寸成立的候选；不按章节数量机械配图。单张明确请求只需简短说明作图要求。
1. **读取实际文档或页面**：检查模板、页面或网页的比例、占位、背景、配色、字体、相邻文字、按钮位置和已有图片。文档或页面中的图先按用户指向、图题与正文交叉引用、页面或段落位置、文档关系和渲染外观定位；导出文件名和媒体序号仅作存储线索，不得从中推断正式图号。PPT 先按页型标记 `插图/统计图/原始证据/表格/公式/流程图/时间轴/纯文字`；README、技术文档和网页按图位标记 `内容图/真实截图/氛围图/统计图/原始证据/无需图片`；没有现成视觉系统时才建立新的系统。
2. **确认图片的主要用途和类型**：只选一个主要用途：解释关系、建立情境、提示功能、区分章节、突出创新、展示路径或形成品牌识别；再确定图片属于`说明研究内容的图/真实截图/氛围插图`。说明研究内容的图必须包含理解结构所需的短标签和关系；截图必须来自真实可核对的产物；只有氛围图才把标题和正文留给 PPT、Word 或网页排版。
3. **审查模板适配与横向容量**：把模板拆成 `必须保留` 与 `允许调整`。保留尺寸、品牌、字体、核心色和必要组件；按 `carrier-specs.md` 先用实际图位核定宽高比，再根据最长标签的正常字宽、节点内边距、箭头、间距和侧栏估算横向容量。模板迫使流程变成卡片墙、比较失去对称或层级变平，或参考图的版式导致节点过窄和文字压缩时，改为双行、分组、上下布局或拆分说明，不得靠超宽画布、窄体字或非等比缩放硬塞。
4. **写图件要求**：在内部用不超过 120 字写明最终使用位置、读者、一句核心命题、所依据的材料、图片类型、文字处理、主体、风格、构图、模板适配、配色来源、材质、目标比例、图形完整性、留白和禁止出现的内容。不得先套固定画风。
5. **确认内容和图中文字**：根据实际来源材料核对对象名称、关系、数字和结论，再列出各区域必须提供的信息，以及必须出现、必须逐字准确、可以简化、不得出现和不得推断的对象、文字、数字与关系。来源没有的结论、期刊标识、仪器读数或医学细节不得补写；删除后不影响核心命题的区域直接删除。说明研究内容的图只把删除后会造成对象、关系、条件、关键状态或核心结论误读的文字列入 `Text (verbatim)`；定义、理由、完整方法、限制和来源移到正文、图注或复杂图的详细说明。不得为避免伪文字而删除必要标签，也不得给每个节点机械添加副标题。
6. **统一系列图的视觉表达**：同一项目的系列图共享主色来源、光线方向、材质、线条或摄影语言；不同内容结构和使用位置按实际尺寸重新安排结构、密度和裁切，不能把同一模板机械复制到所有图片。流程图默认使用两类有明确含义的主色相，只有真实警示、失败、异常、不良结局或必须单独识别的关键状态才增加第三类；全图主色相不超过三种，黑、白、灰等中性色不计入。不得把蓝白配色作为科研流程的默认答案，也不得为了避免单调而随机换色。流程图与技术路线图还应确定是否需要图标：默认不用图标，只有真实对象、操作或产出确实需要视觉提示时才加入少量简单图标或微型图形。
7. **构造提示词**：使用 `figure-planning.md` 的提示词结构和 `prompt-recipes.md` 的相应写法，至少保留所依据的材料、核心命题、证据属性、图片类型、模板适配、整体结构、各区域内容、必要的微型图形、图标使用原则、准确的节点与连接关系、必须逐字一致的标签、配色作用、目标宽高比、文字自然宽度、禁止非等比缩放、不可放置内容的区域和不得推断的内容。用具体的图形表达要求替代“高级、科技感、学术感”等空泛词，不设机械字数下限。
8. **生成或截图首稿**：概念性非统计视觉首轮只生成一个完整方案；真实界面与成果先运行、渲染或打开实际文件后截图，不调用 imagegen 伪造。全新生成不附带待修改图片；非编辑参考先用于分析信息关系、构图、视觉重点和配色作用，并把适用要求写进完整提示词。首稿需要继续修改时，将首稿作为待修改图片；确有帮助的现有参考图可以同时用于修改。项目产物必须移入工作区，不得只留在 `$CODEX_HOME/generated_images/`。
9. **按原始尺寸和最终显示尺寸检查**：在当前任务中查看实际文件。先按原始分辨率检查伪文字、解剖、纹理、阴影、重复对象、中文字形宽度和圆形或方形是否变形，再按最终显示尺寸检查主旨、轮廓、层级、留白、对比、裁切、标签和细节密度。嵌入论文、PPT、报告或网页时保持原始宽高比；若目标位置的比例不匹配，使用留白、裁切或重新生成，不得横向或纵向拉伸。真实截图同时检查敏感信息、光标、通知、无关窗口、缩放和裁切。
10. **根据原图定向修改**：需要修改既有图、根据既有图重绘或修正上一版时，先查看待修改原图，并写清三类要求：必须保持的文字、数字、公式、身份、对象、节点、连接、方向和结论；可以调整的版式、间距、字体层级、配色、线宽、背景和视觉重点；不得添加、删除、纠正、推断或合并的内容。所有需要附带的图片均有本地路径时使用 `referenced_image_paths`；只能从近期对话取得图片时，使用能够覆盖全部必要图片的最小 `num_last_images_to_include`；两者不得并用。一种附图方式不能同时包含待修改原图和可选参考图时，优先保留待修改原图；只有参考图对修正确有帮助时才请用户重新附图。每轮只修一个主要问题并重复三类要求；成功返回的修改结果必须与原图逐项对照，并确认没有损失事实、文字、结构和最终尺寸下的可读性。最多连续修改两轮；现有参考图确有帮助时可在任一轮使用，不为使用参考图单独增加一轮。仍失败时，仅对可替代的生成稿执行一次不附图的整图重新生成。完成这些适用操作后精确结构图仍不准确，才整图改用 `svg-diagrams`；不可替代的用户原图保留原件，不以重新生成的图片冒充修改成功。
11. **嵌入后复核**：把最终图放进实际 PPT、论文页面、标书页、README、技术文档或网页，并在当前任务中查看嵌入后的页面，而不是只查看孤立图片。网页和 README 检查桌面与窄屏显示、替代文本和文件体积，PPT 检查缩略图和投影尺寸。
12. **记录与归档**：正式项目记录最终图件要求、提示词、实际使用的工具、核验结论和改用其它绘图方式的原因；当前版使用含义明确且长期不变的文件名，旧版整组归档。提示词和生成过程不进入正文。

交付前按 `figure-planning.md` 依次完成四轮检查：必要性与证据、内容与结构关系、视觉与可读性、嵌入后显示。所有必须修改的问题处理完成后才能交付；参考图或外部示例不能替代来源核验。

## HTTP 524

把 HTTP 524 视为附带图片生成时的服务或传输失败，不是修改结果的质量问题，也不计入两轮内容修改：

1. 第一次 524：使用相同的待修改原图、相同必要附件和同一修改目标重试一次；可以删除重复形容词和通用禁止项，但必须保留图片用途、全部节点与连接关系、必须保持的内容、允许调整的内容、不得改变的内容以及核对要求。
2. 第二次 524：停止重试，保留待修改原图，不解释为提示词或设计失败；不静默降级模型，不另写或切换第三方 API，也不因超时改用 SVG。

只有 imagegen 成功返回修改结果且结果不满足内容精度要求，才判断是否需要重新生成整图或改用 SVG。

## 美学要求

- 主体必须一眼可辨。小图保留一个主对象，大图通常保留一个焦点和 2 至 4 个支持元素。
- 优先自然不对称构图、稳定视觉重心和有用途的负空间；避免平均分布、机械居中、边缘拥挤和无意义漂浮。
- 配色优先取自现有论文、PPT、报告或网页。流程图默认使用两类语义主色，必要时增加一类警示或关键状态色，主色相总数不超过三种；中性色用于画布、文字、边框和连接线。红色只用于真实警示、失败、异常、不良结局或当前重点，普通排除、常规步骤和一般分组不自动标红。不把整个项目做成单一蓝色相，也不为“高级感”加入霓虹渐变。
- 材质必须有语义：文献与证据可用纸张、油墨和索引；临床与现场可用自然光纪实；机制与系统可用干净科学插画；数字研究可用克制几何和网格。不得无理由加入玻璃、金属、烟雾、景深或电影灯光。
- 不默认使用塑料 3D 图标、黏土风、儿童卡通、商业素材照片感、悬浮全息屏、蓝色发光 DNA、无依据分子结构或科研符号拼贴。
- 系列资产要有家族一致性，但每张图仍服从其内容角色，不能变成同构卡片墙。

## 文字与关系

- **正文内容图**：README 正文图、工作流、架构图、技能示例、教程内容图、流程图、机制图、技术路线和图形摘要必须直接包含脱离图注仍能理解结构所需的短标签、数字和箭头，并由 imagegen 生成完整图后逐字逐边核验。不得把“网页图默认无字”泛化到正文内容图。
- **氛围插图**：PPT 主视觉、封面、网页 hero、登录页和章节氛围图默认不烧录标题、正文、按钮或长解释；这些文字由 PPT、Word 或网页的文字元素排版。
- **真实截图**：界面、终端、代码、文档、PPT、表格、图件和交付物预览使用实际渲染内容。只保留任务相关区域，隐藏敏感信息；不得用 imagegen 生成可被误认成真实操作或真实成果的截图。
- 内容图文字、数字和箭头必须作为完整图的一部分由 imagegen 直接生成；不得用 Python、PPT 文本框、Word 文本框或 SVG 覆盖层修补错误文字、数字和箭头。真实截图的确定性裁切、缩放和不改变内容的标注不属于补写 AI 图，但标注不得遮盖证据或改写界面状态。
- 图内标签逐字沿用来源材料、研究方案或可核验方法文献中的规范术语。缩短标签只能删除不影响含义的修饰语，并保留术语核心；不得加入内部流程词、软件工程隐喻、口语化动作、生硬直译、自造缩略语或临时拼接的短语。来源未给出且存在多种合理名称时先向用户核实。
- 图题、图号、论文标题、报告标题和来源说明通常由论文、报告、PPT 或网页排版，不烧录进图片，除非目标格式明确要求。
- 生成似真论文页面、仪器界面或档案时，只使用不可辨识的短线、点阵和抽象标记，不生成看似真实但错误的段落与数值。
- 修改既有图片、根据既有图重绘和修正上一版成图时，都要附带待修改原图。只附带全部且仅必要的待修改图片；上一轮生成结果需要继续修改时，以该结果作为本轮待修改图片，同时与初始原图核对是否发生内容偏移。
- 非编辑参考不随全新生成调用上传，先把可以采用的图形规则写入提示词；首稿需要继续修改时，如果现有参考能改善视觉表达、布局节奏或结构，可以同时附带一张可选参考图，但必须明确它只提供已经核对的视觉参考，不提供研究内容。用户明确要求同时修改多张目标图时才传入多张待修改图片。

## 选择图像生成方式

- imagegen 可用时，为论文、PPT、报告或网页制作的流程图、框架图、示意图和图形摘要不得因“SVG 更容易”而提前跳过。
- 用户明确要求 SVG、矢量源、完全可编辑图形或目标格式强制矢量时，调用 `svg-diagrams`。
- 已检查实际工具后确认不可用，或对待修改原图完成必要的定向修改、使用已经提供且确有帮助的参考图，并对允许重新生成的图件完整生成一次后，仍不能满足精度要求时，才改用 `svg-diagrams`。已经提供有用参考图却未尝试时不得转 SVG；没有参考图或参考图无助于当前问题时不必额外寻找。HTTP 524 本身也不能作为改用 SVG 的理由。
- 改用其它绘图方式时，沿用已经确认的内容要求和图件要求，不因更换工具而改变信息结构。
