# 构建网页与 Web UI

把网页视为内容、任务、品牌、组件行为、工程和真实运行状态的统一产物。先分流改动范围、风险和页面类型，再明确与本轮范围相称的页面、视觉与组件方案；页面能显示、静态检查通过或首屏截图好看都不能单独证明完成，机器报告为零问题也不能。单独后端、原生应用、统计图、PPT/Word 和独立图片不走本流程；网页内独立位图按 imagegen 或相应视觉技能处理。

## 按范围与页面类型读取

1. 先判断本轮是局部修复、既有页面改版、新页面还是跨页面系统重构。局部文案、间距或单组件修复只处理受影响角色，不重建整站设计系统。
2. 新站、整页改版或跨页面系统重构必读 [site-archetypes.md](references/site-archetypes.md)，区分科研结果/操作、非科研任务界面与表达型页面；混合站逐页分流，不因作者从事科研或名称含“管理台”就继承科研工具风格。
3. 确定风格、排版、密度或去 AI 感时读 [design-playbook.md](references/design-playbook.md)；整体美化、主题重构或配色决定整页身份时同读 [color-systems.md](references/color-systems.md)。
4. 新建或重构复合组件、表格/筛选、导航、弹窗、标签页、轮播、拖拽或动效时读 [interaction-components.md](references/interaction-components.md)。
5. 个人生活、作品集、艺术文化或活动站必读 [personal-cultural-sites.md](references/personal-cultural-sites.md)；参考既有网页选择设计语言时读 [local-reference-patterns.md](references/local-reference-patterns.md)。
6. 用户要求外部案例、开源仓库、可能新增依赖，或只给出“美观、现代、高级、有趣”等抽象目标且无锁定设计稿时读 [external-design-research.md](references/external-design-research.md)。
7. 涉及性能、SEO、无障碍实现或交付前验证时必读 [quality-gates.md](references/quality-gates.md)。
8. 登录后显示服务器数据并自动/按变更刷新，或用户反映读取、切换、刷新、滚动、保存或发布慢时，必读 [data-fluency.md](references/data-fluency.md)，先测量时间分布再决定改哪一层。

审计脚本：静态产物运行 `python scripts/audit_static_html.py <html-or-directory> [--root <site-root>]`；需桌面/手机浏览器证据且本机已有 Chromium 时运行 `python scripts/audit_browser.py <url...> --output <directory>`（CDP 真实布局视口，不自行安装浏览器，不评价审美）。

## 1. 建立页面、视觉与组件方案

1. 读取工作区入口、路由、样式、组件、构建命令和已有测试；保留来源不明的改动，不读取或回显 `.env`、凭证与私密配置。识别读者、核心任务、真实内容量、公开/登录状态和目标设备；仅在会显著改变架构、技术栈或品牌方向且无法推断时询问。
2. 建立页面清单，区分公开页、登录/账户页、后台/任务页和共享组件，列明真实长内容、适用状态、目标视口与验收路径；不得只改公开首页而默认后台已一致。
3. 沿用既有框架与依赖配置；不仅为视觉翻新迁移框架或重写正常业务逻辑。确需外部组件时，按 [external-design-research.md](references/external-design-research.md) 对当前需要的具体组件建立能力矩阵（源码所有权、状态、无障碍、主题、包增量与测试证据），星数与截图不作采用结论。
4. 编码前完成设计构思并建立可检查的视觉方案。整体页面或主题重构先在四个维度定调：表面层级与材质分工（画布/内容面/抬升面/浮层）、带气质的中性色盘与语义三元组、光学字阶与等宽数字秩序、克制的现代组件语汇（联排发丝线 KPI、柔和着色胶囊/唯一滑块、凹陷轨道分段、画布底色抽屉）；随后写明视觉命题、用户可见的必须特征与不得出现的特征、1 个主表达手段与至多 2 个辅助手段、首屏重心、桌面与手机外框/内容框宽度/左右安全区/共享对齐线、字体/间距/几何/动效角色、明暗与色彩职责及竞争色相预算，以及对应证据。单组件修复只写受影响角色。
5. 复合组件写明数据源、实际需要的状态、键盘/触控路径、失败恢复、减少动效与无 JS 基线；外部参考记录来源、许可、迁移模式与取舍理由。

## 2. 组织真实内容与任务

1. 先排任务与信息再选组件：公开首屏回答“是什么、给谁用、下一步做什么”，任务页先给当前对象、状态与动作。按页面类型覆盖核心路径（营销/电商/内容知识/管理台/账户权限），使用真实内容长度与字段，不编造评价、客户、数字或功能状态。
2. 公开内容提供稳定 URL、可抓取文本与清晰层级；应用界面覆盖适用的默认、悬停、聚焦、按下、选中、禁用、加载、空、成功、错误与权限状态。
3. 桌面、窄屏和触控各自成立，不把桌面版等比缩小；从 `viewport → page shell → section → content column → component` 建骨架，明确居中内容框、全宽或有依据的非对称构图；正文左对齐不算偏左，未声明的单边外边距、桌面偏移和不对称内边距不得带入手机端。

## 3. 形成现代且有来源的视觉系统

1. 从目的、类型、内容与场景推导视觉，不套固定“现代 SaaS”模板；模板与 showcase 只提供结构与角色证据，其配色不是本 skill 的默认值（权威品牌系统除外）。至少建立一项与主题直接相关的识别特征。
2. 按 [color-systems.md](references/color-systems.md) 分配表面、文字、操作、反馈和数据角色；每个竞争色相必有职责，语义色不做无语义大面积装饰。无品牌/素材依据时不因科研、医疗或“专业”自动使用大面积深绿、深蓝等暗色外壳。计算关键正文、次要文字、按钮、链接、焦点和状态色的对比度；渐变/图片/透明叠层不能可靠自动判断时人工核对。
3. 提炼少量实际使用的 token，删去未用或同义变量。默认 1 个主表达手段 + 至多 2 个辅助手段；同视口出现两类及以上动效/视觉特效（3D 倾斜、持续位移、滚动显影、自动轮播、视差、装饰运动）视为效果堆叠候选，无法说明任务价值或关闭后更清晰时撤回。实验或强动效需求仍不得让核心内容依赖动画、hover 或高配设备。
4. 删除无依据的渐变、玻璃拟态、同质卡片阵列、过量胶囊、空洞口号与大面积留白，同时不反向收敛成千篇一律的灰白网格。
5. 避免任务界面粗糙反模式并落地现代组件细节：多操作项用紧凑下拉、凹陷轨道分段控件或轻量图标组织，不平铺一排大按钮或生硬文字按钮；选中筛选用柔和着色胶囊（`accent-soft` + 细边）或唯一滑动镜片，不堆叠高对比纯黑/纯白实心块；状态与分类用极淡浅底配高对比正文与光点，不用重色块压字；摘要指标优先用联排发丝线 KPI 带，同排网格卡片等高对齐，宽屏（如 24 寸）通过合理容器宽度或响应式列数避免右侧空洞；低频配置收进右上角轻量设置入口；界面标签直述功能，不机械附加“AI”前缀，高频核心信息前置且不重复展示。
6. 原创品牌插画、英雄图或纹理按需调用 imagegen；界面文字、数据、表单和真实截图留在 HTML/CSS 或真实渲染中。

## 4. 实现稳健组件与基础质量

1. 使用语义 HTML、原生交互元素与可见标签；CSS 优先流式布局、容器/媒体查询与 token，JS 仅担必要交互。盒模型使用对称 `padding-inline`、`max-width`、`margin-inline: auto` 与 `min-width: 0`，窄屏撤回桌面固定宽度、单边定位与跨列，不重复嵌套页面边距。
2. 新页面或整体改版在 320、390、430 像素附近预览（至少保存 390 像素正式证据）；局部修复只查受影响宽度与同类组件。动效可中断、优先 `transform`/`opacity`，离屏停止更新，并提供静态基线、键盘、触控与 `prefers-reduced-motion` 等价路径；视觉重构保持业务、API、鉴权与数据结构。
3. 性能、技术 SEO 与无障碍按 [quality-gates.md](references/quality-gates.md) 同步落实：关键内容与 LCP 资源 HTML 可发现且不懒加载，非首屏图懒加载并声明尺寸/响应资源；字体子集化 WOFF2；可索引页配齐独立 title/description/canonical/主 H1/结构化数据，私密与后台页用鉴权或 `noindex`（不用 robots.txt 代替）；满足 WCAG 2.2 AA（键盘、可见焦点、对比度、触控目标与非纯色状态线索）。

## 5. 实跑、分级验收与反馈升级

按实际 diff 选层级并严格执行 [quality-gates.md](references/quality-gates.md) 对应检查：

- **L 局部纯前端**（文案、CSS、局部标记或既有 DOM 交互，不改路由、共享布局/组件、依赖、构建、API、鉴权、持久化或安全）：只跑目标文件的定向检查，HTML/元数据变化时再跑结构审计，不因网页 skill 自动触发无关的全仓测试、生产构建或整站审计。用一个受影响 URL、状态与最危险布局视口完成核对；用户明确在实际页面接手视觉验收，或针对个人工具与日常迭代明确要求快速完成、无需保守全套检查时，以核心功能流畅、构建/语法无错与目标视图整洁为准，不默认补做桌面/手机截图矩阵，部署后只做只读健康检查并分别记录自动检查与用户确认。
- **P 页面/前端系统 & P/R 接口或生产高风险**：运行受影响包的格式化、类型、lint、测试与构建；触及 API/schema/鉴权/持久化/安全/生产配置或正式发布时同时执行项目专项与安全检查。用真实浏览器覆盖页面清单与目标状态：约 1440 像素桌面 + CDP 仿真的 390 像素手机布局视口（新页/改版/手机体验补测 320 与 430 像素），记录 `innerWidth`、`clientWidth`、`scrollWidth` 与 `body.scrollWidth`，不得把 `--window-size=390` 外窗或裁切窄图充当移动端证据。公开页与后台页分别验收，每类覆盖首屏与一个锚点、滚动深处或任务状态，记录 H1、重复 ID、缺失 alt、破图、横向溢出、关键布局容器的左右间隙与中心偏移、越界，以及控制台异常、脚本异常、HTTP 失败和网络加载失败。
- **组件基线、失败去重与反馈升级**：已有 Storybook/截图回归设施时按 [quality-gates.md](references/quality-gates.md) 固化适用状态，差异失败不得通过自动更新基线关闭（无此设施不强制安装）。无关稳定失败按规去重但保留失败状态，不得声称全套测试通过。技术检查与人工视觉验收分开记录，机器零问题不等于视觉通过。用户审阅态标为“待审阅”或“被否定”并暂停生产部署，确认后标为“可部署”；同一页面第二次连续出现整体否定时停止局部补丁，按 `quality-gates.md` 回到内容基线重建视觉方案。发现共性缺陷扫同类源并按需撤回破坏体验的高级效果。

## 完成判定

- **L 局部任务**：确认唯一目标、使用它的页面与不变范围；定向检查通过、受影响状态已确认、范围外无意外差异，不将未跑的全仓或跨视口检查包装为已通过。
- **P/R 任务**：代表性页面（公开/后台分开）、视觉方案、组件状态、桌面与 CDP 手机视口首屏/深层/关键状态及布局几何均通过，无未解释偏移、溢出、裁切、破图或控制台/网络失败；高风险与发布任务同时通过专项与安全检查。
- 技术检查与视觉验收分开记录；审阅态无未关闭异议且部署符合授权。交付说明仅列本轮改动、实际验证与范围、已知限制及部署后观察项。
