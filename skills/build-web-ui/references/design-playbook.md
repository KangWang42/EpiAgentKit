## 先选信息气质

| 场景 | 主要气质 | 版式重点 | 适合的识别特征 |
| --- | --- | --- | --- |
| 学术、科研与专业工具 | 可信、克制、可核验 | 流程、状态、表格、证据、术语 | 方法路径、编号系统、证据层级、领域图形 |
| 教程、知识库与长文站 | 安静、清楚、耐读 | 搜索、目录、阅读宽度、代码与注释 | 内容索引、章节节奏、学习路径、边栏导航 |
| 个人、生活方式与文化站 | 有作者性、具体、有记忆 | 编辑式首屏、摄影、故事、地点、时间与浏览节奏 | 手帐、刊物、档案、广播、地图、票据或实物质感 |
| 产品、服务与活动页面 | 明确、可信、有行动力 | 价值、差异、证据、转化路径 | 产品行为、真实案例、交互演示、前后关系 |
| 管理台与数据产品 | 高效、稳定、低歧义 | 扫描、筛选、批量操作、状态与异常 | 操作台、时间线、对象层级、状态语言 |

这些是起点，不是主题包。先从内容提炼名词和动作，再决定视觉语言。

## 把视觉命题写成可检查合同

先写一句同时约束主题、媒介感和行为的命题，例如“像一本能按地点翻阅的私人城市食记”。若句子可替换成任何产品仍成立，它还不够具体。

随后为下列角色写明选择、用途和边界：

| 角色 | 必须明确 | 检查证据 |
| --- | --- | --- |
| 主题依据 | 内容中的名词、动作、材料、场景和读者怎样形成风格 | 真实内容、用户材料、品牌来源或已核验参考 |
| 正向与反向边界 | 页面必须能看见什么、不得出现什么、表达强度多高 | 首屏与深层截图逐项核对，不用抽象形容词代替 |
| 视觉重心 | 首屏和关键任务状态各由什么承担主次 | 同一状态的桌面和手机截图 |
| 字体 | 正文、标题、界面标签、数字各由谁承担 | 中文与英文真实截图、回退字体、长标题换行 |
| 色彩 | 表面、文字、主操作、辅助强调、语义反馈和数据序列怎样呼应主题 | 实际 CSS 值、色彩职责、竞争色相、关键对比度和状态双重编码 |
| 间距 | 4 至 6 个稳定级别及章节节奏 | 首屏与长页面截图、同级组件对齐 |
| 几何 | 圆角、边框、阴影和容器规则 | 同类组件一致，装饰不伪装为控件 |
| 图像 | 真实照片、截图、插画和装饰图的职责 | 来源、裁切、固有尺寸、alt 与移动端画面 |
| 动效 | 反馈、切换、空间关系或氛围由哪些动效承担 | 静态基线、触控、键盘、减少动效与停止条件 |

色值列表、字体名称或“现代、精致、高级”等形容词不能替代角色与证据。

## 先建立布局骨架再装饰

把几何居中、文字对齐和视觉平衡分开判断。正文、列表和表单通常左对齐，但承载它们的内容框仍应相对页面外框保持清楚且稳定的左右安全区；不能因为文字左对齐就接受整个区块无意偏向一侧。

1. 按 `viewport → page shell → section → content column → component` 画出页面骨架。每层只承担一种宽度或留白职责，标出共享对齐线、最大宽度、手机边距和允许越界的区域。
2. 为每个关键区块选择一种布局关系：居中内容框、全宽内容、有依据的非对称编辑构图或任务型侧栏外壳。相邻区块切换关系时必须服务内容层级，不能来自各组件各写一套宽度和单边外边距。
3. 居中内容框可以用“限制宽度并 `margin-inline: auto`”或“全宽外壳加对称 `padding-inline`”实现；同一层级不要无意叠加两套页面边距。使用逻辑方向属性，避免把 `margin-left`、`left` 或 `translateX` 当作常规响应式对齐工具。
4. 网格与弹性布局为可收缩列使用 `minmax(0, 1fr)` 或 `min-width: 0`，图像、表格、代码和长链接明确选择缩放、折行、局部滚动或替代视图。窄屏主动撤回桌面的固定列宽、跨列、绝对定位、旋转和位移。
5. 在 320、390 和 430 像素附近使用真实最长标题、正文、按钮和状态检查骨架。逐层比较左右间隙和中心偏移；若多个独立区块都向同一侧偏移，先修共享父容器或 token，不逐卡片补偿。
6. 几何中心不是唯一正确构图。图像视觉重量、侧栏和编辑式留白可以形成光学平衡；有意非对称必须在视觉合同中说明内容依据、对齐网格、手机重排与安全区。未声明的固定偏移、单边空白和桌面残留按布局缺陷处理。

装饰和动效只能建立在静态骨架已经成立之后。移除颜色、阴影和动画仍能看出主次、对齐与章节节奏，才进入视觉细化。

## 让主题、内容与配色互相证明

1. 从真实标题、对象、动作、材料、环境和使用时长中提取 3 至 6 个设计依据。例如长时间查阅、批量处理、现场活动、商品比较、私人记录会导向不同的密度、表面与色彩关系。
2. 为每项选择写出因果关系：“因为页面主要用于长时间查阅版本化文档，所以使用安静中性表面、强正文和轻量链接色”，不能只写“采用高级蓝灰”。
3. 有真实摄影、商品、作品或数据颜色时，先让内容色成为画面一部分，再选择不会与其争夺注意力的界面色。不要另建一套与素材无关的流行色板。
4. 同一品牌下允许营销页、正文、账户和管理台采用不同密度与色彩面积，但主操作、语义色和品牌识别的含义保持一致。
5. 主题词只能帮助提出候选，不能直接决定颜色。医疗不自动等于蓝绿，文化不自动等于米黄，科技不自动等于蓝紫渐变；以用户材料、读者、任务和可核验参考确认。
6. 编码后遮住站名复核：视觉是否仍与内容类型和任务相符，还是可以原样换给任意产品。后者判为主题依据不足，返回合同重选角色。

## 校准表达强度

| 模式 | 可以承担高强度的区域 | 应保持稳定的区域 |
| --- | --- | --- |
| 表达型个人、作品集、文化或活动站 | 首屏、章节转场、标题、图像编排、作品浏览 | 主导航、长文正文、表单、错误与权限信息 |
| 阅读型教程、知识库或文章站 | 封面、章节标识、插图和引用 | 正文、目录、代码、表格和搜索 |
| 转化型产品或服务页 | 产品演示、差异说明、案例和行动节点 | 价格、条款、表单、证据与操作后果 |
| 任务型工具、管理台或科研应用 | 品牌入口、关键状态和少量反馈 | 输入、数据、批量操作、异常、帮助与审计路径 |

从用户语气和材料选择安静、鲜明或实验强度。用户明确要求浮夸、高饱和、实验、沉浸或强动效时才把它视为目标；“有设计感但不浮夸”优先使用比例、字体角色、留白节奏、材料细节、精确对齐和短促反馈。

## 建立设计 token

1. 为正文、标题、界面标签和数字分别指定字体角色，不把每个区块变成新字体。
2. 按页面类型和主题声明非中性色预算。任务型界面通常使用一个主操作色和必要语义色；编辑、文化、商品或实验场景可有更多内容色，但每个明显色相都要有职责和面积边界。
3. 设定 4 至 6 个间距级别、2 至 4 个圆角级别和清楚的边框或阴影规则。
4. 用字体大小、字重、留白和对齐建立层级，颜色承担品牌、操作、状态或内容分类中的明确职责，不独自承担层级。
5. 中文正文优先稳定字面、适中行长和 1.65 至 1.9 的行高；英文字体不能破坏中文回退或数字对齐。
6. 把 token 映射到实际页面角色。未被任何页面或组件使用、同义重复的 token 删除，不以变量数量表现设计系统完整。

## 控制效果预算

默认让一个页面只有一个主表达手段和最多两个辅助手段。以下效果按“类型”而非元素数盘点：

- 3D 倾斜或指针跟随；
- 视差、连续漂浮或循环位移；
- 滚动显影、章节遮罩或大面积入场；
- 自动轮播、跑马灯或自动切换；
- 装饰圆环、光晕、颗粒、贴纸或重复悬浮图形；
- 大面积叠压、旋转或越界构图。

同一视口出现两类或更多时，先把每一类与具体内容、导航、反馈或品牌任务对应。无法说明、静态截图不成立、关闭后层级更清楚、移动端需要大量补丁或性能无法验证时，撤回该效果。用户明确选择实验强度时可以保留更多类型，但任务稳定区、静态基线和所有输入方式仍须通过。

不要用另一个动画、遮罩或装饰去修补已经造成的层级问题。先删除效果，再重新判断是否仍缺少信息提示。

## 消除通用 AI 感

重点删除没有内容理由的选择：

- 紫蓝渐变、玻璃卡片、发光边缘和模糊光球同时出现。
- 所有内容被切成相同圆角卡片，重复“图标、标题、两行描述”。
- 每个标签、导航和按钮都是胶囊，导致层级和点击范围混乱。
- 巨大标题配极少真实内容，首屏大面积空白只承担“高级感”。
- 使用“赋能、革新、无缝、下一代”等无证据口号，或虚构客户、评分、增长数字与评价。
- 用随机图标和柔和色块填满页面，却没有主题相关图像、数据或交互。
- 一个视觉风格复制到登录、教程、数据表、详情页和错误页，忽略各自任务。
- 所有区块都用居中排版、滚动入场和悬浮位移，造成模板化节奏。

不要反向把页面做成无色、无圆角或无动画。保留能解释内容、品牌或状态的元素，删除无法解释的装饰。

## 增加人类编辑感

1. 使用真实标题长度、字段、地点、日期、错误原因和操作后果安排版式。
2. 允许受控的不对称，例如主次列、跨列图片、边注、编号或不同内容密度，但保持网格可追踪。
3. 给一个视口一个视觉重心，其余元素支持它，不让每块内容都争夺注意力。
4. 让微文案说明具体后果，例如“将重新分析已选择的 3 篇文章”，而不是“确认继续”。
5. 为专业工具显示来源、口径、更新时间、状态或复核路径；为个人站显示真实物件、地点、照片与作者视角。

## 图像、图标与动效

- 使用真实产品截图、真实照片和实际数据图时，保持来源与内容真实性；不要生成式重绘科研原始图像或真实界面。
- 需要原创英雄插画、品牌符号、纹理或主题物件时，可用 imagegen 生成位图资产。把文字、按钮和关键状态留给网页渲染。
- 图标优先沿用现有系统；新图标保持同一视图框、笔画、填充和光学尺寸，不混用多套风格。
- 动效只表达出现关系、空间关系、进度或反馈。长动效允许跳过，并实现减少动效模式。
- 暗色模式只有在场景、使用时段或既有产品要求时实现；它是独立色彩系统，不是简单反转。
