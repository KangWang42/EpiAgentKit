# 个人、作品集与文化站

## 先校准表达强度

个人生活、作品集、摄影、音乐、艺术、文化或活动站需要作者性，但作者性不等于浮夸。先从用户原话与已有材料选择一个主强度：

| 强度 | 适用语气 | 主要手段 | 避免 |
| --- | --- | --- | --- |
| 安静编辑 | 私密、耐读、克制、温柔 | 字体角色、比例、纸张或摄影质感、细线、留白、短反馈 | 大面积撞色、巨字和持续运动 |
| 鲜明编辑 | 现代、有设计感、有记忆、技术力 | 清楚主场景、受控不对称、一至两个强调色、精确卡片切换、有限空间层次 | 旋转贴纸、过量硬阴影、每区不同效果 |
| 实验展示 | 用户明确要求浮夸、高饱和、沉浸、强动效 | 戏剧化排版、强色彩、拼贴、3D、视差或场景化转场 | 核心内容依赖动画、触控和键盘失去等价路径 |

出现“不浮夸、克制、耐看、精致”等限定时，不得只抓取同一句中的“现代、技术力、悬浮、高级”等词提高强度。用户后给出的强度修正优先于早期形容词。

合格结果应满足：

- 隐去站名后，仍能从构图、字体、材料、色彩或浏览行为辨认主题与作者气质。
- 静态截图已经成立，动效只增加空间、节奏与反馈。
- 强弱分布有节奏，不是全页平均放大、发光、旋转或漂浮。
- 手机端重新导演内容，不把桌面舞台缩小后裁切。

## 从作者材料建立视觉语法

1. 提取 3 至 6 个与作者或内容直接相关的名词与动作，例如“日记、电影票、网页窗口、广播、装订、切台、显影”。
2. 为它们分别选择媒介行为：时间形成编号或时间线，电影形成画幅或放映切换，网页作品形成窗口、索引或外链入口。
3. 只保留一个主隐喻，另选一至两个辅助母题。不得把赛博、复古、玻璃、Y2K、粗野主义、3D 和杂志排版无差别堆在同一页。
4. 写一句视觉命题并列出截图可验证的特征。视觉命题写“私人广播编辑台”时，应能看到频道、日期、切换和编辑式层级，而不只是文案出现“信号”。

## 让设计感来自关系而非效果数量

- 设一个主场景，使用字体大小、图像比例、列宽、留白和对齐建立重心。只有用户选择实验强度时，主场景才默认使用极端比例或持续运动。
- 使用 2 至 4 个稳定色彩角色：底色、正文色、主强调色和可选撞色。鲜明编辑模式下，撞色只承担少数状态或章节。
- 允许受控不对称、越界、叠压、描边、阴影、颗粒和非常规网格，但一次只选少数与主题相关的手段。
- 字体组合以角色而非数量取胜。显示字、正文、界面标签和数字最多各承担一种职责；中文回退必须实际截图检查。
- “有设计感但不浮夸”优先依靠精确比例、字体层级、材质、对齐、内容节奏和微交互，不依靠巨型口号、旋转爆炸贴、霓虹撞色、长时间跑马灯或所有卡片悬浮。
- 完成静态构图后列出当前页面所有效果类型。出现两类以上连续或滚动驱动效果时，按主 skill 的效果预算逐项保留或撤回，不能因为每个效果单独可用就默认组合合理。

## 空内容也要像完整产品

不得编造随笔、电影、客户、项目或评价来填页面。初始内容为空时：

1. 保留真实导航、内容分类、作者说明、更新时间或当前日期等已有信息。
2. 把空状态写成主题内的明确状态，同时用直白句子说明缺少什么。
3. 展示内容未来进入页面的结构和操作路径，但不生成假卡片、假数字或假封面。
4. 站主后台可以显示下一步录入动作；公开页不暴露服务器、令牌或内部配置细节。

## 高级交互的选择顺序

1. 先用原生页面结构建立静态基线。
2. 切换少量内容时使用语义标签页、可见按钮或 `scroll-snap`，默认不自动播放。
3. 需要空间层次时，把有限 3D 倾斜、视差或光照放在非关键展示层；链接、正文和表单的命中位置保持稳定。
4. 需要页面连续感时，优先采用同源 View Transitions 等渐进增强；不支持时保持普通导航。
5. 只有真实触控惯性、复杂循环、时间轴同步或 WebGL 场景确实构成核心叙事时才引入库，并遵循外部参考核验流程。

安静与鲜明编辑模式默认不使用连续漂浮、自动轮播、全屏视差或循环跑马灯。键盘、触控和减少动效保留相同信息、顺序与操作结果，只移除依赖细指针或连续运动的表现层。

## 手机端重新导演

- 先确定 320 至 430 像素下的标题行数、图像裁切、控件顺序和安全区，再写桌面规则的覆盖。
- 把横向编辑版面重排为章节、堆叠、抽屉或可见的横向浏览；核心导航不得因装饰层或 `overflow: hidden` 被裁掉。
- 触控目标保持足够尺寸。悬浮揭示的信息必须改为常显、点按切换或展开。
- 对大标题、旋转卡片、描边和阴影检查真实中文宽度；`scrollWidth` 没有溢出不能证明内容未被祖先容器裁切。
- 使用 CDP 或真实设备确认布局视口确实是目标宽度；窄截图、浏览器外窗宽度或响应式预览框标签不能代替 `innerWidth` 与 `clientWidth` 证据。

## 审校问题

- 当前强度是否与用户最后一次明确表述一致？
- 这套视觉能否替换站名后直接套给任意科技产品？能则作者性不足。
- 去掉动画后，首屏和内容顺序是否仍像完成品？不能则构图依赖动效。
- 设计感是否来自比例、排版、材料和节奏，还是只来自效果数量？
- 手机截图是否保留完整标题、导航、主操作和上下文，而不只是没有横向滚动条？
- 首屏之外的长内容、筛选与后台编辑页面是否仍沿用同一视觉角色并保持任务清楚？
- 空状态是否诚实、具体并符合主题，且没有暴露后台细节？
