## 先判断配色输入

按以下顺序处理：

1. 先区分权威品牌输入与通用模板输入。用户确认的品牌 token、正式设计稿或现成产品组件系统保留其值与角色，先修复映射、对比度和不一致；通用模板、示例站和 showcase 只提供结构与颜色角色槽位，不自动继承其具体色值，也不把“模板原色”当成品牌约束。
2. 用户提供偏好或禁用项时，把它们写入当前视觉合同，区分“本项目不使用”和“通用禁用”。后给出的明确修正优先。
3. 只有抽象目标且没有参考时，先从内容、页面类型和使用环境选中性色气质、明暗模式与主操作色职责，再核验一至三个原始设计系统。不要先挑一个流行色再给它编理由。
4. 多个合理方向会显著改变品牌身份时，给出少量角色化候选并说明差异；不生成大量仅换色的主题让用户盲选。

每次配色决策都写明当前页面的目的、读者、真实内容、使用环境和用户偏好怎样决定表面明暗、操作色面积、强调色与语义色。营销页、内容站、知识库、个人/文化站和管理台即使使用同一模板骨架，也不能因模板方便而共用一套未经重新论证的颜色。

## 建立角色而不是色值清单

整体页面或主题重构至少填写以下合同；单组件修复只填写受影响部分：

| 角色 | 必须说明 | 常见使用位置 | 禁止 |
| --- | --- | --- | --- |
| 页面底与表面 | 页面底、嵌套层、浮层、遮罩的关系 | body、侧栏、卡片、表格、弹窗 | 每个区块使用不同色相背景 |
| 文字与图标 | 主、次、弱、反色、禁用 | 标题、正文、元数据、图标 | 只靠降低透明度制造不可读弱文本 |
| 主操作 | 默认、hover、active、focus、禁用 | 主按钮、链接、选中状态 | 与装饰色或语义色争用同一角色 |
| 辅助强调 | 出现条件、面积和使用位置 | 次级章节、少量标签、品牌细节 | 为“活泼”随机增加第二主色 |
| 语义反馈 | 信息、成功、警告、错误的文本/底/边框 | 提示、状态、校验、危险动作 | 作为无语义大面积装饰或排行底色 |
| 数据序列 | 类别/顺序/发散/强调规则 | 图表、热图、数据标签 | 与操作色和语义色混为一套 |
| 焦点与选择 | 键盘焦点、文本选择、当前项 | 控件、导航、编辑器 | 只用阴影或颜色且在实际背景不可见 |

再写明用户可见的正向特征、不得出现的特征、默认表面策略、一个主表达手段、最多两个辅助手段和当前视口的竞争色相预算。预算不是固定色相数量，而是声明哪些非中性色可以同时占据明显面积以及各自职责。

## 让主题、内容与配色互相证明

颜色不是脱离内容的装饰层。先说明页面主题、真实素材和读者需要产生的视觉感受，再决定表面、主色和强调色；最终截图应能同时回答“这是什么”和“为什么这样配色”。

## 控制表面与竞争色相

1. 先用明度、留白、边框和排版建立层级，再决定是否需要色相差。相邻容器只有在真实嵌套、选择或高对比时刻需要新表面。
2. 一个视口中，面积和饱和度接近的多个非中性色会争夺注意力。逐个标记为主操作、辅助强调、语义反馈、数据或真实内容色；无法归类的颜色删除或降为中性。
3. 中性色可以是纯灰或带轻微冷暖倾向，但同一页面避免同时使用互不相关的蓝灰、黄灰、紫灰作为多套底色。图片和品牌材料确有需要时，在合同中说明关系。
4. 语义颜色随状态出现，不承担品牌识别。主操作色恰好与某一语义色接近时，仍用文字、图标、形状和位置区分含义。
5. 大面积深色、亮色或有色表面不是默认错误。只有品牌、内容、使用环境或明确视觉命题支持，并且文字、控件、图像和相邻表面在实际截图中成立时才保留。
6. 不全局禁止黑、紫、橙、黄、渐变或高饱和。判断失败的是特定角色、面积、组合和上下文，不是色名本身。

## 按网页类型选择起点

以下是角色结构的起点，不是可直接套用的固定主题：

| 场景 | 中性与表面 | 非中性色职责 | 重点检查 |
| --- | --- | --- | --- |
| 管理台、数据与专业工具 | 稳定中性底，少量可追踪嵌套层 | 一个主操作色；语义色只在状态；数据序列独立 | 密集视口是否出现竞争色相，状态是否装饰化 |
| 文档、知识与长文 | 安静底色、强正文、有限边界 | 链接/当前目录使用轻量主色，警告独立 | 长时间阅读、代码、表格和锚点焦点 |
| 内容、编辑与文化 | 可从纸张、摄影或材料提取冷暖中性 | 一个编辑强调色，可有受控章节色 | 图片色与界面色是否冲突，正文是否被弱化 |
| 营销、产品与服务 | 中性基础允许少数高对比品牌时刻 | 主行动色明确，辅助色服务产品演示/证据 | 行动、价格、证据是否被装饰色稀释 |
| 电商、目录与预订 | 商品图像是主要色彩来源，界面表面稳定 | 操作、促销、库存/风险各自分工 | 促销色、品牌色和状态色是否混淆 |
| 社区、账户与公共服务 | 可信中性底和稳定表单表面 | 主操作、身份/关系和风险按需分开 | 权限、危险动作、错误和通知是否清楚 |
| 深色创意或沉浸站 | 独立构建暗色表面和文字层级 | 少量高亮色服务主题/导航/反馈 | 发光和高饱和面积、图片边缘、低亮设备 |

当用户只说“现代、好看”时，优先通过比例、排版、表面关系和一个有依据的强调色建立现代感，不自动生成蓝紫渐变、玻璃卡和大面积柔和彩块。

## 明暗模式与主题切换

1. 把暗色模式视为独立角色映射，不做颜色反转。重新检查表面层级、文字、边框、焦点、图像、阴影、语义色和数据序列。
2. 只有项目、用户环境或现有产品要求时实现双模式。不能完成全部核心页面和组件时，交付一个完整模式优于两个不一致模式。
3. 主题切换尊重系统偏好并允许用户明确选择时保存选择；不要在服务器和客户端初始状态不一致时制造闪烁。
4. 内联高对比区域只用于真正的视觉或任务转折，例如应用外壳、沉浸首屏或危险确认；不要用多套主题分隔普通章节。

## 语义色与数据颜色

- 语义色不得承担无语义的大面积装饰；它们只在用户需要知道信息、成功、警告、错误或风险时出现。
- 信息、成功、警告、错误先由文字说明和图标/形状表达，颜色作第二通道。为每类定义柔和背景、边框/图形和高对比文字，不只定义一个色值。
- 危险色只用于真实风险、不可逆动作和错误；普通标签、排行、常规排除和一般强调不自动使用。
- 数据颜色按变量类型选择：类别使用可区分色相，顺序使用连续明度，发散使用有意义中点，单一重点使用一个强调色加中性上下文。
- 数据序列与界面主操作、成功/警告/错误分开登记。若颜色不可避免重合，使用直接标签、线型、点型、纹理或位置双重编码。
- 图表属于真实统计结果时使用 `publication-figures`；本文件只规定页面中的颜色角色与界面协调。

## 编码与检查

1. 以语义 token 编码，不在组件里散落色名或十六进制值。推荐角色结构：`canvas`、`surface-*`、`text-*`、`border-*`、`action-*`、`focus`、`status-*`、`data-*`。
2. 保留一层从来源色阶到语义 token 的映射，使品牌换色、暗色和高对比模式不改组件职责。没有多主题需求时也保持角色命名。
3. 为所有交互颜色覆盖默认、hover、active、focus、selected 和 disabled 中实际适用的状态。透明叠层必须在最不利真实背景上计算。
4. 对正文、次要文字、链接、按钮、焦点、边框和状态记录实际前景、背景、比值和阈值。自动工具不能可靠处理渐变、图片、混合模式或透明叠层时人工检查。
5. 在同一状态的桌面和手机截图上盘点：无职责颜色、竞争色相、语义色装饰化、表面层过多、弱文字、图片与界面色冲突、焦点/选择不清。
6. 机器对比度通过只证明相应颜色对达到阈值，不证明整页协调；视觉门禁必须单独核对合同与截图。

## 官方参考的可迁移原则

- [Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) 把色阶步骤映射到页面底、组件状态、边框、实色背景和文字；迁移角色分工，不复制成统一品牌。
- [Radix 调色板组合](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette) 区分品牌、带色中性和语义色，并提示高彩组件与带色背景可能冲突。
- [Primer Primitives](https://primer.style/product/primitives/color/) 展示功能 token、明暗、高对比和色觉辅助模式；迁移多模式映射与角色命名。
- [Carbon 颜色分层](https://carbondesignsystem.com/elements/color/usage/) 用背景、层、字段和边框 token 表达嵌套关系；迁移层级方法，不复制 IBM 品牌值。

实际采用代码或资产前，按 `external-design-research.md` 重新核验当前版本、许可证、维护状态和项目兼容性。
