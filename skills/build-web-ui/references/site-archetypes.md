## 先按主任务选择

页面类型由用户在该页面要完成的主任务决定，不由框架、行业名称或首页风格决定。同一产品可以同时包含营销站、知识库、账户和管理台；逐页选择类型，并通过品牌 token、导航关系和术语保持整体一致。

| 主任务 | 页面类型 | 设计优先级 | 主要失败信号 |
| --- | --- | --- | --- |
| 理解价值并采取行动 | 营销、产品、服务 | 清楚主张、真实证据、下一步 | 口号多于事实，所有区块同质卡片化 |
| 发现、比较并完成交易 | 电商、目录、预订 | 商品信息、库存/规格、信任、结算 | 图片好看但比较和状态不清 |
| 浏览、阅读与回访内容 | 内容、编辑、媒体 | 编辑层级、节奏、归档、作者和时间 | 首屏占满，正文与来源薄弱 |
| 查找答案并完成学习 | 文档、知识库、课程 | 搜索、目录、版本、代码与进度 | 装饰掩盖信息架构，手机目录不可用 |
| 认识作者、作品或活动 | 个人、作品集、文化、活动 | 作者性、作品顺序、材料与记忆点 | 套用产品模板，效果多于真实作品 |
| 监测、分析或执行任务 | 管理台、数据产品、科研工具 | 对象、状态、筛选、异常、批量操作 | 指标卡堆满首屏，操作和异常被弱化 |
| 参与、协作和管理身份 | 社区、会员、账户 | 身份、权限、关系、通知和治理 | 动态内容无上下文，权限后果不清 |
| 提交正式事项或获得服务 | 公共服务、高风险表单 | 资格、步骤、保存、错误、确认和帮助 | 一次展示过多字段，错误不能恢复 |

只创建用户请求或现有路由需要的页面，不因参考蓝图自动扩大项目范围。

## 营销、产品与服务页

核心路径通常为：理解对象与价值，确认适用性，查看差异和证据，处理顾虑，采取行动。

- 页面：主页/落地页、功能或服务详情、案例/证据、价格或方案、常见问题、联系/注册；只保留实际需要的项目。
- 组件：清楚导航、主行动、产品演示、比较、案例、价格、FAQ、表单和页脚。每个组件承担路径中的一个问题，不按模板凑齐。
- 内容：用真实能力、条件、结果和限制替代“革新、赋能、无缝”等空泛口号；不得虚构客户、评分或增长数字。
- 视觉：允许较强首屏和品牌表达，但价格、条款、证据、表单和操作后果保持稳定。主行动色不与多个装饰色争夺注意力。
- 状态：表单加载/成功/错误、方案不可用、登录前后、链接和媒体失败。
- 验收：首屏能说明“是什么、适合谁、下一步”，深层证据可达；手机端行动入口、比较和表单不被装饰层挤压。

## 电商、目录与预订

核心路径通常为：发现对象，筛选/搜索，比较，理解规格/价格/库存，选择，加入或预订，结算，确认与售后。

- 页面：分类/搜索、商品或服务详情、比较、购物车/清单、结算/预订、订单/确认和帮助。
- 组件：搜索、筛选、排序、规格与变体、图库、价格、库存/时间、数量、购物车、地址/支付/确认。图库和轮播不能隐藏规格与购买状态。
- 内容：价格、促销条件、库存、配送、退换和费用必须真实且位置明确；占位数据不能伪装成可购买内容。
- 视觉：让商品/服务成为视觉重心，界面色服务导航、选择和状态。季节色、分类色和品牌色要有分工，不能形成无语义彩虹。
- 状态：无结果、缺货、规格冲突、价格变化、优惠失效、支付失败、预订冲突、购物车为空和网络重试。
- 验收：键盘与触控均能选规格、改数量、查看费用和恢复失败；结算不依赖 hover、动画或颜色单独传达状态。

## 内容、编辑与媒体站

核心路径通常为：发现内容，判断相关性，阅读/观看，理解来源与时间，继续探索或订阅。

- 页面：首页/频道、文章/故事、作者/主题、归档/搜索、关于和订阅。
- 组件：编辑式标题、摘要、文章正文、元数据、目录、图注、引用、相关文章、分页/归档和搜索。
- 内容：标题、日期、作者、来源、更新信息与正文层级构成产品价值。不要用巨大 hero 把真实内容推到首屏之外。
- 视觉：以字型、行长、图片比例、章节节奏和受控不对称形成识别；卡片只用于真正可比较的内容单元。
- 状态：无搜索结果、旧内容/修订、媒体加载失败、订阅错误、长标题和无图内容。
- 验收：长文在真实中文/英文长度下耐读；分享链接、锚点、图片图注、打印/阅读模式和手机排版按项目需要成立。

## 文档、知识库与课程站

核心路径通常为：搜索或定位主题，理解版本和前置条件，完成步骤，验证结果，继续下一主题。

- 页面：入口、分类、文档/课程正文、搜索结果、版本说明、示例/练习和错误排查。
- 组件：全站搜索、侧栏、面包屑、页内目录、代码/命令、提示/警告、版本切换、上一页/下一页和进度。
- 内容：信息架构、术语、版本和稳定 URL 优先于英雄区。示例输入、输出和错误必须可区分，不使用装饰背景降低代码可读性。
- 视觉：保持阅读宽度、目录层级和代码/表格对比，品牌表达集中在入口、章节标识和插图。
- 状态：搜索无结果、版本过期、代码折行、目录过长、权限内容和离线/网络失败。
- 验收：桌面多栏与手机折叠导航均可键盘使用；锚点不被固定头部遮挡，代码和表格能滚动或重排而不裁切。

## 个人、作品集、文化与活动站

核心路径通常为：认识作者/主题，浏览作品或记录，理解时间/地点/材料，进入详情或联系/参与。

- 页面：主页、作品/记录索引、详情、关于、活动/日程和联系。
- 组件：编辑式首屏、作品浏览、时间线、地点/地图、媒体、档案索引、活动信息和联系入口。
- 视觉：依据用户材料选择安静、鲜明或实验强度，并读取 `personal-cultural-sites.md`。作者性来自真实材料与关系，不来自随机贴纸和效果数量。
- 状态：内容为空、作品无封面、活动结束、外链失效、媒体不可用和联系表单失败。
- 验收：隐去站名仍能从构图、字体、材料、色彩或浏览行为识别主题；静态截图成立，手机端重新组织内容而非裁切舞台。

## 管理台、数据产品与科研工具

核心路径通常为：确认当前对象与状态，发现异常，筛选/比较，执行动作，确认后果并追溯。

- 页面：登录、总览、列表、详情、创建/编辑、任务进度、设置/权限、日志/审计和错误帮助。
- 组件：导航、搜索、筛选、表格/列表、批量操作、状态、详情面板、表单、弹窗、通知和恢复入口。
- 内容：优先对象名称、口径、更新时间、状态、异常原因和动作后果。指标只在支持决策时进入首屏，不自动生成等宽摘要卡阵列。
- 视觉：使用稳定表面和清楚密度；主操作色、语义色和数据序列分开。深色导航、高饱和状态和数据颜色只有在合同中有职责时使用。
- 状态：加载、无数据、无结果、部分失败、权限不足、过期数据、并发冲突、批量选择和撤销/重试。
- 验收：真实长字段、宽表、窄屏替代布局、键盘核心路径、权限边界和错误恢复均有证据；登录页与应用页可以共享品牌但采用不同密度。

## 社区、会员与账户产品

核心路径通常为：识别身份与权限，发现内容/成员，参与互动，处理通知，管理关系和安全设置。

- 页面：注册/登录、动态/目录、内容详情、创建/编辑、个人资料、通知、成员/权限、设置和治理。
- 组件：身份标识、发布/回复、关注/收藏、通知、成员列表、角色、隐私与安全控制。
- 内容：清楚区分作者、时间、编辑状态、可见范围和治理动作；不制造假活跃度、假成员或假互动。
- 视觉：关系和上下文优先于装饰；行动强调不能让危险治理操作与普通互动同权重。
- 状态：匿名/登录、无权限、内容删除/隐藏、发送中/失败、冲突编辑、封禁/申诉和通知为空。
- 验收：键盘、触控和辅助技术能理解内容顺序、作者、操作与结果；私密内容不进入公开索引、预览或通知泄露。

## 公共服务与高风险表单

核心路径通常为：确认资格与材料，分步填写，保存/返回，处理错误，复核，提交并获得可追溯确认。

- 页面：资格说明、开始页、分步表单、复核、确认、状态查询和帮助。
- 组件：步骤/进度、字段与提示、错误摘要、保存继续、材料上传、复核清单和确认编号。
- 内容：用直接语言说明谁在什么条件下需要什么、为什么需要、怎样更正和下一步。风险、费用、时限和不可逆后果置于行动附近。
- 视觉：可信、稳定、低歧义；颜色辅助层级和状态，不让品牌表达遮盖说明、错误和帮助。
- 状态：资格不符、字段错误、保存失败、会话过期、上传失败、重复提交、维护中和人工协助路径。
- 验收：不用颜色、动画或记忆也能完成流程；错误摘要可定位字段，返回不丢数据，提交结果与后续责任明确。

## 混合站点

1. 逐页记录“页面类型、主任务、密度、视觉强度、共享 token 和专属组件”。
2. 共享品牌识别、术语、导航关系、基础字体与颜色角色；不要强迫营销首页、文档、账户和管理台使用同一布局密度或同一组件组合。
3. 组件跨类型复用时保持行为和可访问性，允许尺寸、密度和视觉权重按上下文变化。
4. 浏览器验收按独立布局、鉴权边界和高风险任务抽样，至少覆盖每种实际页面类型。
