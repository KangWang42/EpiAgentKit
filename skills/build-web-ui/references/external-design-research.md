## 何时执行

出现以下任一情况时执行：

- 用户要求寻找设计案例、开源仓库、配色方案、悬浮、3D、视差、轮播、卡片切换或动画案例；
- 实现可能新增组件、定位、轮播、动效、3D 或其它交互依赖；
- 用户要求整体“美观、现代、高级、优雅、有趣、不生硬”等抽象审美效果，但没有已锁定品牌 token、完整设计稿或明确参考站，且风格或配色会决定整页身份。

用户只要求局部修复、内容调整或已有组件内的小改动，已有完整品牌/设计稿，或外部参考不会改变结果时跳过，不为每个网页任务强制浏览。抽象审美分支做轻量研究，通常核验一至三个互补的原始来源即可，不用链接数量制造充分感。

## 先核验来源再提取模式

1. 先读用户给出的页面、当前项目和已有设计系统，再搜索外部案例。外部参考不能覆盖项目技术合同、真实内容和既有行为。
2. 视觉案例优先原作者网站、作品说明和实际页面；实现资料优先官方文档、官方仓库、发布页和许可证。聚合站、截图站和短视频只作发现线索，不能单独证明实现方式或授权范围。
3. 对每个候选记录名称、原始链接、用途、查看日期、当前版本或提交状态、代码许可证、图片/字体等资产授权、框架与依赖、维护状态和目标浏览器。无法核验的项目只作灵感，不复制代码或资产。
4. 克隆或运行陌生仓库前检查许可证、包清单、安装脚本、构建命令和网络/凭据需求；不执行来源不明的脚本，不把示例密钥、遥测或远程资源带进产品。
5. 把参考拆成内容组织、空间构图、交互反馈和工程实现。复制原则与行为，不复制品牌文案、素材、颜色值、独特布局尺寸或整页代码。
6. 配色参考记录它怎样处理页面底、表面、文字、操作、语义反馈、数据和明暗模式；只展示成组色块但没有角色、状态和可访问性依据的页面只作灵感。

至少形成以下决策记录；短任务可用紧凑列表，候选较多时使用表格：

| 候选 | 已核验来源与许可 | 可迁移模式 | 采用或拒绝 | 当前实现 | 回退 |
| --- | --- | --- | --- | --- | --- |
| 原作者页面或官方仓库 | 链接、版本、许可和限制 | 与当前内容直接相关的行为 | 说明任务收益与成本 | 原生 CSS/JS 或固定依赖 | 静态、触控、键盘、减少动效 |

不得只记录采用项。至少说明主要候选为什么采用、缩减或拒绝，让“效果太多”“与内容无关”“许可不明”和“依赖成本过高”等判断可回查。

主要迁移原则如下：

- 组件库解决状态、语义和工程一致性，视觉身份仍由当前项目的真实内容、读者、素材、排版和颜色角色决定。
- 公开营销页、内容站和沉浸式创意页不因采用企业组件库而自动变成密集卡片网格；管理台也不因参考创意站而加入无任务收益的全屏动效。
- 只能选择一套有样式的组件库作为页面基础；无样式 primitives 可以参与组合，但必须统一焦点、浮层、表单验证、主题 token 和版本策略。
- 复制行为和可验证的设计原则，不复制品牌文案、图标、颜色值、独特布局尺寸、示例素材或整页代码；代码或资产许可不清时只作灵感并拒绝迁移。

## 按具体组件建立采用矩阵

星数、下载量、示例数量和“看起来完整”只用于发现候选，不能替代选型。对当前任务确实需要的每个复合组件逐项比较；不为当前页面和任务不会使用的组件评估整套库。

| 维度 | 必须核验的问题 |
| --- | --- |
| 来源与所有权 | 当前版本或提交、代码/资产许可；是复制后由项目维护的源码、注册表安装项，还是运行时包依赖 |
| 任务与状态 | 是否覆盖真实字段、权限、长内容、加载、空、错、成功、禁用、危险操作和恢复路径中的适用项 |
| 输入与可访问性 | 语义、可访问名称、焦点、键盘、触控、屏幕阅读和减少动效由谁实现，项目仍需补什么 |
| 视觉与主题 | token、CSS 变量、暗色、高对比、RTL、密度和品牌样式怎样接入；是否会带入第二套有样式系统 |
| 运行边界 | 框架和浏览器兼容、SSR/水合、国际化、表单和路由集成是否符合现有项目 |
| 成本与迁移 | 直接/传递依赖、生产包实际增量、导入方式、版本升级和弃用路径；不得只抄官网标称体积 |
| 证据 | 官方 API/可访问性说明、当前项目的组件测试、故事、实际页面和生产构建分别证明什么 |
| 决策 | 采用、包装、缩减、继续沿用现有组件或拒绝，以及静态/原生回退 |

已有组件行为正确时优先保留并调整视觉层。只有能力矩阵显示焦点管理、碰撞定位、虚拟化、复杂选择或维护成本确有净收益时才替换。替换按组件小步进行并保持行为测试，不做整库一次性迁移。

shadcn/ui 的 registry 分发的是会写入项目的代码和配置，不是免审查皮肤。只有项目已具备相应 CLI 且本轮获准引入时，才先查看解析后的文件、目标路径、依赖、环境变量和差异；优先固定可复现的提交或版本。不得为参考一个组件而安装 CLI，也不得把 registry 中的远程依赖链直接当作已审代码。

## 组件状态与视觉回归参考

- [Storybook](https://github.com/storybookjs/storybook) 的官方文档把 story 作为组件在特定参数和状态下的可复用测试输入；[args](https://storybook.js.org/docs/writing-stories/args) 表达变体，[play function 与组件测试](https://storybook.js.org/docs/writing-tests) 表达交互。项目已经使用 Storybook 或同等组件夹具时，为新增或重构的共享组件补齐真实适用的默认、长内容、加载、空、错、权限、暗色、窄宽和减少动效状态；不得为了故事矩阵虚构业务能力。
- [Playwright](https://github.com/microsoft/playwright) 的[视觉比较](https://playwright.dev/docs/test-snapshots)以参考截图为基线，并明确提示不同操作系统、浏览器版本和环境会改变渲染。项目已经有截图回归框架时复用其视口、浏览器、字体、时区、数据和动画稳定策略；第一次基线和每次有意变化都要人工审阅，失败时保留实际图和差异图，禁止自动更新基线让测试转绿。
- 组件故事证明隔离状态，页面浏览器矩阵证明真实路由、数据、容器、鉴权和组合关系，两者不能互相代替。现有项目没有组件故事或截图框架时，仍按本 skill 的页面合同和 CDP 审计完成当前任务；局部样式修复不为此新增 Storybook、Playwright、Chromatic 或云服务。

## 选择原生实现或依赖

- CSS `scroll-snap`、`transform`、`transition`、`dialog`、`details` 和少量指针反馈已能可靠完成时优先原生实现。
- 只有复杂触控惯性、循环、同步控制、焦点管理或跨框架适配确实需要成熟实现时才引入库。固定兼容版本，保留许可证，按需导入，并测量生产包增量。
- 需要无样式可访问组件时，在项目现有体系、React Aria、Base UI 或 Radix 中选择一套；不要把多套 primitive 的焦点和状态模型混进同一组件。
- 需要浮层碰撞定位、精确触控轮播或复杂动效时，分别评估 Floating UI、Embla 或 Motion；只引入解决当前问题的包，不复制其示例站视觉。
- 不因参考站使用 WebGL、Three.js、GSAP 或大型框架就自动采用。它们只有在核心叙事依赖该媒介、静态基线仍完整且目标设备验证通过时才成立。
- 参考项目长期未维护并不自动淘汰，但必须隔离其思路与旧代码；不把过时依赖直接带进现代项目。

## 轮播与卡片切换

1. 内容少且不要求无限循环时先考虑语义列表加 CSS 横向滚动与 `scroll-snap`。
2. 保持 DOM 顺序、标题层级和真实链接；隐藏视觉页不能从辅助技术中制造重复或错误顺序。
3. 提供可见的上一项、下一项和当前位置；按钮使用原生控件并具备准确名称。触控滑动不能是唯一操作方式。
4. 默认不自动播放。确需自动播放时提供暂停，用户交互后停止，并在页面失焦、组件离屏和减少动效模式下禁用。
5. 不为桌面多列卡片强制套轮播；宽屏能同时比较的内容保持网格，窄屏再切换为横向浏览。

## 3D 悬浮、视差与网格运动

1. 只作用于非关键展示层，不作用于正文、表单、导航、错误信息或需要精确点击的控件。静止状态必须清晰，效果关闭后信息与链接仍完整。
2. 鼠标细指针可使用有限倾斜或层次位移；触控设备不模拟 hover，改用轻量按压反馈、横向浏览或静态层次。键盘聚焦只显示稳定焦点。
3. `prefers-reduced-motion: reduce` 下移除视差、自动播放、连续漂浮和大幅空间转换，保留必要的即时状态反馈。
4. 优先只动画 `transform` 与 `opacity`，避免循环读取布局后写入样式。共享并取消 `requestAnimationFrame`；页面隐藏、组件离屏、指针离开或元素销毁时停止更新。
5. 限制同时运动的面积、层数和频率。实现前声明新增 JavaScript、图片、字体和 GPU 效果预算；实现后在目标手机和桌面实测。
6. WebGL 或全屏运动背景只能承担可移除的氛围层。加载失败、低能力设备、节省流量、减少动效或不支持环境直接显示稳定 HTML/CSS 内容。

## 停止与撤回条件

出现任一情况时拒绝候选或撤回效果：

- 核心内容只有动画完成后才可见，或 hover 是唯一发现与操作路径。
- 触控滚动被劫持、浏览器返回失效、键盘焦点丢失、屏幕阅读顺序错误或缩放受限。
