## 何时执行

出现以下任一情况时执行：

- 用户要求寻找设计案例、开源仓库、配色方案、悬浮、3D、视差、轮播、卡片切换或动画案例；
- 实现可能新增组件、定位、轮播、动效、3D 或其它交互依赖；
- 用户要求整体“美观、现代、高级、优雅、有趣、不生硬”等抽象审美效果，但没有已锁定品牌 token、完整设计稿或明确参考站，且风格或配色会决定整页身份。

用户只要求局部修复、内容调整或已有组件内的小改动，已有完整品牌/设计稿，或外部参考不会改变结果时跳过，不为每个网页任务强制浏览。抽象审美分支做轻量研究，通常核验一至三个互补的原始来源即可，不用链接数量制造充分感。

## 先核验来源再提取模式

1. 先读用户给出的页面、当前项目和已有设计系统，再搜索外部案例。外部参考不能覆盖项目技术合同、真实内容和既有行为。
2. 视觉案例优先原作者网站、作品说明和实际页面；实现资料优先官方文档、官方仓库、发布页和许可证。聚合站、截图站和短视频只作发现线索，不能单独证明实现方式或授权范围。
3. 对每个候选记录名称、原始链接、用途、查看日期、当前版本或提交状态、代码许可证、图片/字体等资产授权、框架与依赖、维护状态和目标浏览器。无法核验的项目只作灵感，不复制代码或资产。
4. 克隆或运行陌生仓库前检查许可证、包清单、安装脚本、构建命令和网络/凭据需求；不执行来源不明的脚本，不把示例密钥、遥测或远程资源带进产品。
5. 把参考拆成内容组织、空间构图、交互反馈和工程实现。复制原则与行为，不复制品牌文案、素材、颜色值、独特布局尺寸或整页代码。
6. 配色参考记录它怎样处理页面底、表面、文字、操作、语义反馈、数据和明暗模式；只展示成组色块但没有角色、状态和可访问性依据的页面只作灵感。

至少形成以下决策记录；短任务可用紧凑列表，候选较多时使用表格：

| 候选 | 已核验来源与许可 | 可迁移模式 | 采用或拒绝 | 当前实现 | 回退 |
| --- | --- | --- | --- | --- | --- |
| 原作者页面或官方仓库 | 链接、版本、许可和限制 | 与当前内容直接相关的行为 | 说明任务收益与成本 | 原生 CSS/JS 或固定依赖 | 静态、触控、键盘、减少动效 |

不得只记录采用项。至少说明主要候选为什么采用、缩减或拒绝，让“效果太多”“与内容无关”“许可不明”和“依赖成本过高”等判断可回查。

## 优先核验的原始来源

下表是来源入口，不是默认依赖或主题包。采用时重新检查当前版本、许可、维护状态、框架与资产条款；只引用设计原则不等于有权复制代码或品牌资产。

| 需要 | 原始来源 | 可迁移内容 | 已核验许可边界 |
| --- | --- | --- | --- |
| 颜色角色与状态色阶 | [Radix Colors](https://www.radix-ui.com/colors) 与 [Radix Primitives](https://github.com/radix-ui/primitives) | 页面底、组件状态、边框、实色背景、文字与明暗映射 | Primitives 仓库为 MIT；使用前核对具体包和资产 |
| 功能 token 与多模式 | [Primer Primitives](https://github.com/primer/primitives) | 语义 token、明暗、高对比及色觉辅助模式 | MIT |
| 企业/任务界面分层 | [Carbon Design System](https://carbondesignsystem.com/elements/color/usage/) 与 [Carbon 仓库](https://github.com/carbon-design-system/carbon) | 表面层、字段、边框、主题和密集组件规范 | Apache-2.0 |
| 内容优先与渐进增强 | [U.S. Web Design System](https://designsystem.digital.gov/) 与 [USWDS 仓库](https://github.com/uswds/uswds) | 服务模式、语义 HTML、移动与无障碍组件 | 大部分为 CC0，部分资产例外，必须读取仓库许可 |
| WAI-ARIA 组件行为 | [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/patterns/) | 标签页、弹窗、组合框、菜单、网格等键盘与语义模型 | 指导材料；示例不是未经测试即可投产的组件库 |
| React 可访问组件 | [React Aria Components](https://react-spectrum.adobe.com/react-aria/components.html) 与 [React Spectrum 仓库](https://github.com/adobe/react-spectrum) | 无样式组件、国际化、输入方式和状态行为 | Apache-2.0 |
| React 无样式组件 | [Base UI](https://base-ui.com/) 与 [Base UI 仓库](https://github.com/mui/base-ui) | 可访问 primitives 与组合式状态模型 | MIT |
| 浮层定位 | [Floating UI](https://github.com/floating-ui/floating-ui) | tooltip、popover、dropdown 的锚定、碰撞与交互 | MIT |
| 触控轮播 | [Embla Carousel](https://github.com/davidjerleke/embla-carousel) | 确需惯性、循环或精确滑动时的底层行为 | MIT |
| 复杂动效 | [Motion](https://github.com/motiondivision/motion) | 确需手势、弹簧、布局或时间线时的可中断运动 | 核心库为 MIT；付费示例和资源另行核验 |

Radix、Primer、Carbon 和 USWDS 带有各自产品语境。学习角色、状态、可访问性和分层方法；不复制品牌色、字体、图标或整页组件外观，也不把它们移植成当前站点身份。Shopify Polaris 等带使用限制或已弃用实现的方案只能在许可与当前平台适用性明确时采用，不能因知名度直接列为通用开源模板。

## 项目级前端参考

这些项目适合核验组件组织、主题契约和交互状态；它们不是可直接套用的页面皮肤。采用前重新检查当前版本、仓库许可、框架、目标浏览器和生产包影响，并在决策记录中写明采用、缩减或拒绝的原因。

| 项目 | 已核验来源与许可 | 可迁移模式 | 采用边界 |
| --- | --- | --- | --- |
| [shadcn/ui](https://ui.shadcn.com/docs) / [仓库](https://github.com/shadcn-ui/ui) | 官方文档与仓库；MIT | 开放源码归属、组合式接口、registry 分发和可直接改造的组件 | 学习组件契约和分发方式；不要复制其常见的灰色圆角默认外观，也不要把 registry 当成未经审阅的依赖源 |
| [Ant Design](https://ant.design/docs/react/introduce) / [仓库](https://github.com/ant-design/ant-design) | 官方文档与仓库；MIT | 企业组件状态、主题定制、国际化、SSR 和完整文档 | 适合已有 Ant Design 或确需企业级组件覆盖的项目；同一页面不要再混入另一套有样式组件库 |
| [MUI](https://mui.com/) / [仓库](https://github.com/mui/material-ui) | 官方仓库；MIT | 广覆盖组件、主题和版本迁移契约 | 仅在既有 MUI 体系或需求确有依据时采用；迁移时先锁定版本和主题 token，不把 Material Design 的品牌语气误当成通用现代感 |
| [Headless UI](https://headlessui.com/) / [仓库](https://github.com/tailwindlabs/headlessui) | 官方站点与仓库；MIT | React/Vue 无样式、可访问组件和状态模型 | 适合已有 Tailwind 或需要从零建立视觉层的项目；必须自行完成视觉合同、焦点、错误和响应式状态 |

主要迁移原则如下：

- 组件库解决状态、语义和工程一致性，视觉身份仍由当前项目的真实内容、读者、素材、排版和颜色角色决定。
- 公开营销页、内容站和沉浸式创意页不因采用企业组件库而自动变成密集卡片网格；管理台也不因参考创意站而加入无任务收益的全屏动效。
- 只能选择一套有样式的组件库作为页面基础；无样式 primitives 可以参与组合，但必须统一焦点、浮层、表单验证、主题 token 和版本策略。
- 复制行为和可验证的设计原则，不复制品牌文案、图标、颜色值、独特布局尺寸、示例素材或整页代码；代码或资产许可不清时只作灵感并拒绝迁移。

## 选择原生实现或依赖

- CSS `scroll-snap`、`transform`、`transition`、`dialog`、`details` 和少量指针反馈已能可靠完成时优先原生实现。
- 只有复杂触控惯性、循环、同步控制、焦点管理或跨框架适配确实需要成熟实现时才引入库。固定兼容版本，保留许可证，按需导入，并测量生产包增量。
- 需要无样式可访问组件时，在项目现有体系、React Aria、Base UI 或 Radix 中选择一套；不要把多套 primitive 的焦点和状态模型混进同一组件。
- 需要浮层碰撞定位、精确触控轮播或复杂动效时，分别评估 Floating UI、Embla 或 Motion；只引入解决当前问题的包，不复制其示例站视觉。
- 不因参考站使用 WebGL、Three.js、GSAP 或大型框架就自动采用。它们只有在核心叙事依赖该媒介、静态基线仍完整且目标设备验证通过时才成立。
- 参考项目长期未维护并不自动淘汰，但必须隔离其思路与旧代码；不把过时依赖直接带进现代项目。

## 轮播与卡片切换

1. 内容少且不要求无限循环时先考虑语义列表加 CSS 横向滚动与 `scroll-snap`。
2. 保持 DOM 顺序、标题层级和真实链接；隐藏视觉页不能从辅助技术中制造重复或错误顺序。
3. 提供可见的上一项、下一项和当前位置；按钮使用原生控件并具备准确名称。触控滑动不能是唯一操作方式。
4. 默认不自动播放。确需自动播放时提供暂停，用户交互后停止，并在页面失焦、组件离屏和减少动效模式下禁用。
5. 不为桌面多列卡片强制套轮播；宽屏能同时比较的内容保持网格，窄屏再切换为横向浏览。

## 3D 悬浮、视差与网格运动

1. 只作用于非关键展示层，不作用于正文、表单、导航、错误信息或需要精确点击的控件。静止状态必须清晰，效果关闭后信息与链接仍完整。
2. 鼠标细指针可使用有限倾斜或层次位移；触控设备不模拟 hover，改用轻量按压反馈、横向浏览或静态层次。键盘聚焦只显示稳定焦点。
3. `prefers-reduced-motion: reduce` 下移除视差、自动播放、连续漂浮和大幅空间转换，保留必要的即时状态反馈。
4. 优先只动画 `transform` 与 `opacity`，避免循环读取布局后写入样式。共享并取消 `requestAnimationFrame`；页面隐藏、组件离屏、指针离开或元素销毁时停止更新。
5. 限制同时运动的面积、层数和频率。实现前声明新增 JavaScript、图片、字体和 GPU 效果预算；实现后在目标手机和桌面实测。
6. WebGL 或全屏运动背景只能承担可移除的氛围层。加载失败、低能力设备、节省流量、减少动效或不支持环境直接显示稳定 HTML/CSS 内容。

## 停止与撤回条件

出现任一情况时拒绝候选或撤回效果：

- 核心内容只有动画完成后才可见，或 hover 是唯一发现与操作路径。
- 触控滚动被劫持、浏览器返回失效、键盘焦点丢失、屏幕阅读顺序错误或缩放受限。
- 无法核验代码或资产许可，必须运行可疑安装脚本，或依赖与当前技术栈冲突。
- 新效果使生产包、LCP、INP、CLS、耗电或内存超出项目预算，且缩减后仍无明确任务收益。
- 视觉参考与站点身份、内容、受众或浏览行为无关，只增加“看起来高级”的装饰，或让专业工具、长文和后台降低可读性。
- 单项效果各自可用，但与页面已有倾斜、滚动显影、连续场景、轮播或装饰运动叠加后削弱视觉重心。

## 交付证据

交付说明列出采用的来源与许可、迁移模式、拒绝项、原生或依赖选择、生产包影响、静态/触控/键盘/减少动效回退，以及桌面和手机浏览器验证结果。链接清单、单张截图或“动画可运行”均不能单独作为验收。整体审美任务还需说明所选参考为什么与当前主题、内容和读者相符，以及哪些流行方案因模板感、配色冲突或任务不匹配被拒绝。
