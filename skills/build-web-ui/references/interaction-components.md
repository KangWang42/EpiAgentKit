## 先选择实现层

按以下顺序选择，每前进一步都要说明原有层为什么不足：

1. 沿用项目已经存在并通过行为测试的组件和 token。
2. 使用原生 HTML 与 CSS，例如 `button`、`a`、`details`、`dialog`、表单控件、滚动、`scroll-snap` 和 View Transitions 渐进增强。
3. 在现有框架中使用无样式可访问组件，处理焦点、键盘、弹窗、组合框或复杂选择；视觉仍由当前项目定义。
4. 只为单一难题采用专用库，例如浮层碰撞定位、触控轮播、虚拟化或复杂动效；不要为一个组件引入整套视觉系统。

不得同时混用多套有样式组件库。无样式库也可能带来不同状态模型；逐组件验证 API、焦点与卸载行为，不做全局一次性替换。

## 建立组件合同

每个新建或重构的复合组件记录：

| 项目 | 要回答的问题 |
| --- | --- |
| 任务 | 用户为什么需要它，能否由页面结构或原生元素直接完成？ |
| 信息源 | 文案、字段、选项、权限、状态和错误来自哪里？ |
| 状态 | 默认、hover、focus、pressed、selected、disabled、loading、empty、success、error、permission 中哪些适用？ |
| 输入 | 鼠标、键盘、触控和辅助技术怎样完成同一任务？ |
| 焦点 | 打开、切换、关闭、删除和失败后焦点去哪里？ |
| 反馈 | 用户何时知道输入已接收、正在处理、成功或需要恢复？ |
| 响应式 | 窄屏是重排、折叠、滚动、抽屉还是替代视图？ |
| 回退 | 无 JavaScript、减少动效、加载失败或低能力设备时保留什么？ |
| 证据 | 哪个测试、URL、状态、截图和键盘路径证明它可用？ |

只实现业务中实际存在的状态。组件文档可以列出未实现分支，但不得用虚构数据把它们伪装成当前产品能力。

## 让交互流畅而不是持续运动

1. 输入后立即改变可感知状态，例如按下、选中、展开或显示进度；网络结果较慢时先确认动作已接收，不伪造成功。
2. 让动效解释因果和空间关系：内容从触发点展开、对象移动到新位置、视图切换保留上下文。纯装饰循环不计为流畅。
3. 动效可以在任意时刻被新输入中断，并收敛到最新业务状态；避免多个定时器、过期 Promise 或重复点击让界面回弹到旧状态。
4. 优先动画 `transform` 与 `opacity`。确需高度动画时避免每帧交替读取和写入布局；不要用 `transition: all` 隐藏意外属性变化。
5. 同类组件使用一致的时间感和缓动关系。短促局部反馈快于页面/容器转换；距离更长或内容更重时适度延长，不为“丝滑”增加等待。
6. 页面隐藏、组件离屏、浮层关闭或指针离开后停止连续更新。减少动效模式移除视差、自动播放、长位移和弹性过冲，保留即时状态反馈。
7. 运动前后保持文字清晰、点击目标稳定和布局可预测；动效不能掩盖网络等待、输入延迟或布局偏移。

## 导航与内容切换

- 主导航使用真实链接和稳定 URL；单页应用也保留浏览器返回、刷新、分享和深链语义。
- 移动导航打开后管理焦点、滚动和关闭路径；关闭后焦点返回触发器。不要只靠屏幕外位移隐藏仍可聚焦内容。
- 标签页适合在同一上下文切换少量并列面板；若内容需要独立链接、历史和抓取，使用页面或路由。按 WAI-ARIA APG 的键盘模型实现方向键、Home/End 和选中状态。
- 手风琴适合按需展开独立章节，不用来隐藏用户必须顺序阅读的核心步骤。标题用按钮并保持展开状态可感知。
- 面包屑表达层级，不替代全局导航；当前页不是可重复跳转的普通链接。
- View Transitions 只作渐进增强。不支持或减少动效时保持普通导航和 DOM 状态切换。

## 搜索、筛选、表格与批量操作

- 搜索说明范围、提交方式和清除路径；输入建议与最终结果区分。延迟请求可取消，旧响应不能覆盖新查询。
- 筛选显示已应用条件、结果数量和一键清除；桌面侧栏转为手机抽屉时保留条件、提交/取消和焦点返回。
- 静态数据使用语义表格；只有需要单元格级方向键、编辑或高密度交互时采用 ARIA grid，并实现完整键盘模型。
- 列排序写明字段与方向，不能只旋转图标。宽表在窄屏选择横向滚动、关键列固定、详情展开或替代列表，不能任意隐藏业务关键列。
- 批量操作先显示选择范围和后果。分页、筛选或刷新后选择是否保留必须明确；部分失败返回逐项结果与重试路径。
- 虚拟化只用于真实规模需要，并检查辅助技术、查找、打印、焦点和滚动恢复；少量项目不为性能想象引入复杂度。

## 表单、弹窗与危险操作

- 字段有持久标签、格式/单位、必要性和就近错误。提交失败后保留输入，错误摘要可跳转到对应字段。
- 禁用按钮不能替代解释。若用户缺少前置条件，在动作附近说明原因和解决方式。
- 弹窗只用于需要暂时阻断背景或集中确认的任务；普通详情、长表单和可分享内容优先页面或侧栏。
- 弹窗打开时把焦点放在合适的标题、说明或控件；Tab 不离开弹窗，Escape 按语义关闭，关闭后返回触发器或合理的后续对象。
- 危险操作说明对象、范围、可逆性和后果。不可逆动作使用明确动词，并根据风险把初始焦点放在安全位置；成功后显示结果和恢复/下一步。
- 自动保存显示保存中、已保存和失败状态；多个版本或并发编辑不能静默覆盖。

## 轮播、拖拽与空间交互

- 内容少且不要求无限循环时，先使用语义列表和 CSS `scroll-snap`。宽屏可比较的内容保持网格，窄屏再横向浏览。
- 轮播提供可见的上一项、下一项和当前位置。默认不自动播放；确需自动播放时提供暂停，交互后停止，并在离屏、失焦和减少动效时禁用。
- 触控滑动不是唯一操作。键盘、按钮和辅助技术访问相同项目，视觉克隆不能制造重复阅读顺序。
- 拖拽必须提供点击/键盘替代、目标提示、取消与撤销。拖动中自动滚动要受控，不能劫持页面滚动。
- 浮层、菜单和提示处理视口碰撞、滚动容器、缩放与触控。tooltip 不能承载完成任务所必需的信息。
- 3D、视差和指针跟随只作用于非关键展示层；静止状态、触控和键盘仍完整。

## 反馈、加载与空状态

- 局部动作在局部反馈，跨页或长任务显示可追踪进度。不要用全屏 loading 覆盖仍可操作的稳定内容。
- 骨架屏只在结构已知且能减少跳动时使用，形状与真实内容近似；未知等待使用明确进度或状态文字。
- 空状态说明“当前为什么为空、用户可以做什么”，并区分首次使用、筛选无结果、权限不足和加载失败。
- toast 适合短暂、非阻断且不需要立即操作的反馈；重要错误、不可逆结果和需要恢复的事项保留在页面内。
- 乐观更新只用于高成功率且可撤回的动作。失败时恢复真实状态并说明影响，不让动画掩盖回滚。
- 动态消息使用合适的 `aria-live`，避免频繁播报或用 assertive 打断普通进度。

## 组件验收

1. 实跑现有组件测试、类型检查和生产构建。
2. 用真实浏览器覆盖鼠标、完整键盘路径、触控等价操作、减少动效和浏览器返回。
3. 检查适用状态、长文案、空/错/加载、重复点击、快速切换、网络延迟和卸载后的过期更新。
4. 检查焦点顺序、可见焦点、弹窗焦点圈、滚动锁、点击外部、Escape、删除/关闭后的焦点位置。
5. 同时查看桌面与真实手机布局视口，确认浮层未被裁切、软键盘不遮挡操作、触控目标和安全区可用。
6. 记录未自动覆盖的辅助技术、真实设备或复杂输入限制；组件动画运行不等于组件完成。
