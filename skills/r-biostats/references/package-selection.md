# R 包选择与复用

本文件用于选择实现工具，不替代研究设计和统计方法确认。包只能实现已经确认的 estimand、分析集、统计量、模型和输出，不能因默认参数方便而改变研究问题。

## 1. 先查成熟包，再写最小适配

需要新增统计、整理、批处理或导出能力时，按以下顺序执行：

1. 先看项目锁文件、现有脚本和已验证依赖，能沿用时不另建平行实现。
2. 按具体任务查官方包索引、CRAN 手册、包作者维护的参考站和当前安装版本帮助页。搜索结果和博客只用于发现候选，不能代替函数参数与返回值核验。
3. 核对候选包是否支持当前设计、数据结构、统计口径、缺失处理、权重或相关结构，以及目标文件格式；再核对返回对象能否提取结果、依赖是否已在项目环境中兼容、实际运行是否产生未解释警告。
4. 成熟包能够完整完成任务时，直接使用公开接口。只为固定标签、相对路径、表图登记、格式衔接或同一结果的多格式输出编写短小适配层；不得复制包内已实现的算法，也不得调用或复制未导出的内部函数来换取短期便利。
5. 没有包满足已确认口径时，才写最小自定义实现，并用公开示例或独立计算核对边界。跨脚本反复出现的稳定适配层按项目规则集中维护，不让主分析脚本携带长篇通用工具。

改用另一个包若会改变估计方法、默认参照、缺失处理、检验或区间算法，属于方法变化，必须先确认；仅输出层不兼容时，可以在保持同一已确认统计内容的前提下改用文件生成包，并记录回退原因。包缺失、版本不兼容或安装失败时遵循上游依赖规则，不静默换包。

## 2. tidyverse 作为默认数据工作框架

[tidyverse 包索引](https://www.tidyverse.org/packages/)用于按任务寻找核心包和专用包；[tidyverse 官方博客](https://www.tidyverse.org/blog/)用于发现版本变化、新包和改进方向；[tidyverse 风格指南](https://style.tidyverse.org/)用于保持一致语法。博客不是 API 规范，采用其中介绍的功能前仍需打开该包当前参考页并在项目版本上实跑。

| 任务 | 优先包或接口 | 使用边界 |
|---|---|---|
| 表格数据清洗与连接 | `dplyr`、`tidyr`、`tibble` | 保持一条可读主线；不为简单变换创建重复中间对象 |
| 字符串、分类和日期 | `stringr`、`forcats`、`lubridate` | 水平顺序和日期口径仍来自方案或已确认规则 |
| 矩形文件和统计软件数据 | `readr`、`readxl`、`haven` | 显式核对列类型、编码、标签和缺失码；原始数据保持只读 |
| 批处理 | `purrr::map*()`、`walk*()`、`dplyr::across()` | 仅有副作用时用 `walk*()`；顺序执行更清楚时允许短小 `for` |
| 数据库或大数据后端 | `DBI`/对应后端、`dbplyr`；经验证后可用 `dtplyr` 或 `duckplyr` | 后端转换不得改变排序、缺失、数值精度或分析结果；性能替换先隔离验证 |
| 建模工作流 | 项目既有模型包；需要统一预处理和重采样时评估 `tidymodels` | 不为了统一语法迁移已经可复现的正式模型主线 |
| 可复现问题样例 | `reprex` | 仅使用公开或去标识示例，不把私密研究数据复制到外部服务 |

同一脚本实际使用多个核心 tidyverse 包时可以写 `library(tidyverse)`；只用一两个包的短脚本可以直接加载对应包。专用包不会因加载 tidyverse 自动可用，必须显式加载或使用 `包名::函数()`。

## 3. `bruceR` 的适用位置

[bruceR 官方参考](https://psychbruce.github.io/bruceR/reference/)提供简洁的导入、描述、心理测量、方差分析、模型整理和中介/调节接口。把它作为经过核验的便利层，不作为所有流行病学分析的统一入口。

| 功能 | 可以使用的场景 | 必须显式核对的默认行为 |
|---|---|---|
| `import()` / `export()` | Q/L 任务或格式明确、标签行为已经实测的文件 | 它会按扩展名分派到底层包；正式项目仍从相对路径出发，并核对列类型、标签、编码和覆盖行为 |
| `Describe()`、`Freq()`、`Corr()` | 探索性描述、频数和相关分析，或需要简洁控制台输出 | `Describe()` 与 `Corr()` 的 `all.as.numeric`、相关方法、P 值校正、缺失处理和是否绘图；它们不替代正式 Table 1 规则 |
| `TTEST()`、`MANOVA()`、`EMMEANS()` | 设计与函数能力完全一致的 t 检验、方差分析和边际均值 | 配对、方差齐性、平方和类型、球形校正、反向比较和多重比较校正均要显式设置，不接受便利默认替用户决定 |
| `model_summary()`、`GLM_summary()`、`HLM_summary()` | 已经拟合并验证的模型需要简洁整理或并列表 | 正式结果仍从原模型对象提取；核对标准化、稳健标准误、聚类、模型检查和 Word 输出能力 |
| `Alpha()`、`EFA()`、`CFA()` | 心理测量或量表分析确实属于当前任务 | 反向计分、提取方法、旋转、因子数、估计量和缺失处理必须来自方案或已核验证据 |
| `PROCESS()` | 中介、调节或条件过程模型与该接口支持的模型完全一致 | 明确 bootstrap/Monte Carlo 方法、模拟次数、随机种子、中心化、协变量路径和置信区间；不得声称运行了 Hayes 的 SPSS PROCESS 宏 |

`set_wd()` 不进入正式项目主流程；正式脚本从项目根运行并使用项目相对路径。bruceR 函数的便利默认可能直接影响结果，例如当前版本中 `TTEST()` 的 `var.equal`、`PROCESS()` 的 `nsim` 与 `center`、`CFA()` 的缺失处理均需要主动决定。部分 `file` 参数生成旧式 `.doc`，不能当作已经通过 `.docx` 文件验收。先查看当前安装版本的 `formals()` 与帮助页，再写入脚本。

## 4. 描述性表格和模型结果表

- 常规独立组描述性表优先按 [描述性统计](descriptive.md) 和 [compareGroups 官方手册](https://CRAN.R-project.org/package=compareGroups) 判断 `compareGroups` 是否兼容；兼容时使用其公开的 `compareGroups()`、`createTable()` 和导出接口，不重写分类汇总与检验逻辑。
- 需要复杂抽样权重、更多自定义统计、严格的单一说明列控制或统一回归表时，优先按 [gtsummary 官方参考](https://www.danieldsjoberg.com/gtsummary/reference/)评估 `tbl_summary()`、`tbl_svysummary()`、`tbl_regression()` 及其公开转换接口。
- 项目已经验证 `tableone`、`arsenal`、`finalfit` 或其他表格包时可以沿用，但必须用相同分析集、分母、统计量、检验和文件验收标准核对，不因包名熟悉就并行重算。
- 同一最终表的 Excel 与 Word 版本必须来自同一个已确认的表对象或同一份结构化表数据。一个格式失败时，修正生成层或从同一来源同时重建两种格式，不分别维护两套数字。

## 5. 完成检查

- 已记录实际使用的包和版本；代码只加载真实依赖。
- 已核对公开接口、关键默认值、返回对象和目标格式，不依赖博客片段、旧示例或未导出内部函数。
- 代表性输入已实跑；全部 error、warning、failed 和 nan 均已归因。
- 自定义代码只覆盖成熟包没有提供的差异，且没有形成第二套统计算法或重复格式系统。
- 回退没有改变分析口径；若改变，已按方法变更处理并取得必要确认。
