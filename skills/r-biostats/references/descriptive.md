# 描述性统计与 Table 1

本文件规定描述性统计和 Table 1 的内容结构。Excel、Word 或其他文件中的具体写入与格式处理另用相应文件操作 skill；文件能打开不能替代本文件的统计内容检查。

## 1. 先确定统计口径

在计算前确认数据来源、分析集、分组变量、每列分母、连续变量的汇总方式、分类变量的水平顺序、缺失处理与呈现，以及是否需要组间检验。这些选择由研究设计、SAP 和目标期刊决定，不由导出工具默认值决定。

- 连续变量按分布和研究用途报告均值（标准差）、中位数（四分位数间距）或其他已确认统计量。
- 分类变量报告 `n（%）`，写清列百分比、行百分比或总体百分比；未知或缺失是否单列必须与分析和正文一致。
- 只有设计、SAP 或目标期刊要求时才添加 P 值或标准化差异；不得把 `add_p()` 当作 Table 1 的默认步骤。
- 组名或列注中给出必要的总样本量，正文、表头、表注和模型分析集的分母应能相互核对。
- 分组表在纳入候选行前检查每个变量是否由分组变量定义、直接组成或确定性派生。会机械重复分组定义的行默认不进入同一描述表；若研究问题确需展示，改用专门分布表或在表注说明其角色，不能把定义重叠当作独立组间差异。
- 当各组互斥且完备并使用同一分析集时，断言总体人数等于各组人数之和；允许重叠分组、不同缺失策略或调查加权总体时，使用与该设计相符的关系检查并分别报告原始人数与加权估计，不能用一个起始样本量覆盖所有列。

同一批变量还进入回归模型时，分别确认描述表与模型的缺失策略。不得从模型使用多重插补推断 Table 1 也应基于插补数据，也不得从 Table 1 使用观察数据推断模型只能采用完整病例。方案明确要求插补后描述时，另行确认汇总和不确定性处理；否则按 Table 1 自身口径生成并在表注说明。

## 2. 分类变量的行层级

默认只设置一个说明列（stub column），在同一列中放置变量名称和分类水平，后面才是各组或总体统计列。除非用户提供的正式模板明确要求，不增加独立“分层”“水平”列。

```text
特征                         暴露组（N=...）   对照组（N=...）
分析集总数                   n                 n
性别
  女性                       n（%）             n（%）
  男性                       n（%）             n（%）
  未知或其他                 n（%）             n（%）
年龄组
  <18 岁                     n（%）             n（%）
  18–64 岁                   n（%）             n（%）
  ≥65 岁                     n（%）             n（%）
  未知                       n（%）             n（%）
```

- 每个分类变量名称只出现一次，作为变量标题行；分类水平放在其下方并在同一说明列显示。
- 变量标题行与分类水平行在数据中保留明确的行类型或缩进级别，不能先丢失层级后靠人工空格修饰。
- 连续变量通常一行完成，名称和汇总统计放在同一行；需要多个统计量时按已确认模板处理。
- 二分类变量在全表统一选择一种方式：直接报告含义明确的“是”或“有”一行，或保留变量标题行并缩进列出适用水平。不得出现读者无法判断分母或参照含义的双列结构。
- 变量标签、水平名称、顺序和合并方式来自方案、代码中的口径常量或已确认模板，不由字母顺序或文件写入顺序决定。

## 3. 实现

### 3.1 默认选择顺序

普通独立组或全样本的描述性表中，变量类型、连续变量汇总方式、分类水平、缺失呈现和所需检验都能由 compareGroups 明确表达时，把 `compareGroups` 作为兼容场景的首选。以下任一情况不强制使用：复杂抽样权重、配对或重复测量、聚类相关、目标统计量不受支持、目标模板需要它无法稳定生成的层级或格式，或当前版本的导出文件不能通过 Word/Excel 验收。

compareGroups 的 `method = 1` 会把连续变量按正态分布方式处理，不能把该默认值当作分布判断。为每个连续变量按已确认口径显式指定 `method`；计算正态连续变量的组间检验时，还要根据已确认的普通独立样本 t 检验或 Welch t 检验显式设置 `var.equal`，不能沿用当前版本的默认值替代方法决定。分类变量先设为有序且标签明确的 factor。`show.p.overall = FALSE` 只隐藏 P 值，底层仍会计算组间检验，因此相关 warning 仍需定位，复杂设计也不能因为“不显示 P 值”就忽略其不适用性。除非需要比值估计，设置 `compute.ratio = FALSE`。

只有部分分类变量需要显示缺失水平时，先用 `forcats::fct_na_value_to_level()` 按已确认标签处理这些变量，再保持 `include.miss = FALSE`；不要把 `include.miss = TRUE` 无差别应用于没有缺失的 factor。这样既保留变量级口径，也避免人为添加空水平后由 `simplify` 删除并产生警告。

两个导出函数的 `nmax = TRUE` 显示的是各组在所有行变量中至少有一个有效值的最大可用样本数，不自动等于预先定义的分析集分母。只有两者已经核对一致时才用它作为表头 N；不一致时设置 `nmax = FALSE`，并通过已确认模板或其它生成器写入真实分母。

同一张表需要反复调整或同时导出时，默认使用 `compareGroups()` → `createTable()` 两步流程，只计算一次，再从同一个表对象输出 Excel 与 Word：

```r
library(tidyverse)
library(compareGroups)

data_table_1 <- data_analysis |>
  select(group, age, sex, bmi, smoking) |>
  mutate(
    group = factor(group, levels = c("对照组", "暴露组")),
    sex = factor(sex, levels = c("女性", "男性")),
    smoking = smoking |>
      factor(levels = c("从不吸烟", "既往吸烟", "当前吸烟")) |>
      fct_na_value_to_level(level = "缺失")
  )

# 示例采用 Welch t 检验；普通独立样本 t 检验时设为 TRUE。
use_equal_variance_t_test <- FALSE

comparison_1 <- compareGroups(
  group ~ age + sex + bmi + smoking,
  data = data_table_1,
  method = c(age = 2, bmi = 1),
  include.miss = FALSE,
  byrow = FALSE,
  var.equal = use_equal_variance_t_test,
  compute.ratio = FALSE
)

table_1 <- createTable(
  comparison_1,
  show.p.overall = FALSE,
  show.p.trend = FALSE,
  show.p.mul = FALSE,
  show.all = TRUE,
  show.n = TRUE,
  digits = 1
)

fs::dir_create("03_tables")
export2xls(table_1, "03_tables/table1_baseline.xlsx", nmax = TRUE)
withr::with_dir(
  "03_tables",
  export2word(
    table_1,
    "table1_baseline.docx",
    nmax = TRUE,
    caption = "",
    strip = FALSE
  )
)
```

`export2xls()` 直接生成 Excel；`export2word()` 需要当前环境已有 Pandoc，并可能留下同名 `.Rmd` 中间文件。文件验证成功后只删除该导出器实际生成的明确路径，不让它混入正式表格目录。两个导出函数能写出文件不等于文件已经达到正式交付标准；包版本、Pandoc/Word 生成链和目标模板不同都可能影响结构、缩进、边框与分页。

### 3.2 回退与专门场景

- compareGroups 不兼容、缺失或导出未通过时，优先用 `gtsummary::tbl_summary()`；复杂抽样使用 `gtsummary::tbl_svysummary()`，不要把加权数据当作普通独立样本。
- Word 可从同一个 gtsummary 对象经 `as_flex_table()` 进入文件生成流程；Excel 可从同一对象的结构化表数据进入 `openxlsx` 或项目既有的工作簿生成流程。两种文件分别使用 `docx`、`xlsx` skill 验收。
- 项目已有经过验证的 `tableone`、`arsenal`、`finalfit` 或同类包时可以沿用；先核对它是否支持当前统计量、设计和双格式输出，不另起一套手工汇总。
- 只有成熟包都不能表达已确认结构时，才构建包含 `row_type`、`indent_level` 和显示标签的最小中间数据。辅助字段用于检查与格式处理，不作为最终可见列。

组间检验确实适用时，再根据变量类型、分布、样本量和设计选择 t 检验、Wilcoxon 秩和检验、方差分析、Kruskal–Wallis 检验、卡方检验、Fisher 精确检验或考虑配对、聚类和抽样设计的相应方法。包的自动选择必须与已确认方法一致；不一致时显式配置或换用更合适的专门包。

## 4. 文件生成与检查

- 在新项目 `02_code/00_setup.R` 的表格登记中注册正式表名，并由主流程生成当前版本；旧项目继续沿用已经确认的配置来源。
- 写入 Excel 时使用单元格的真实缩进属性表示分类水平，不用前导空格、全角空格或字符串拼接模拟缩进。
- 文件名已经包含表号和稳定表名时，工作表第 1 行直接写列标题，不在表内重复“表 1”或完整表题，不为装饰插入空白行、合并标题行或分隔行。只有用户提供的模板或目标期刊明确要求表内标题时例外。
- 默认用白底黑字、必要字重、对齐、列宽和真实缩进表达层级；不为父行、总数行或普通分组添加白色边框、装饰性横线、色带或其它没有信息作用的分隔。表注紧接表体，并与正文、图题或文件名已经承担的内容分工。
- 文件生成后同时核对内容和显示：变量名称是否只出现一次、分类水平是否归属正确、顺序是否正确、总数和百分比能否与来源数据及分母核对、辅助字段是否隐藏、缩进是否真实存在、表注是否说明统计口径。使用 compareGroups 时，从实际调用或表对象核对 `method`、`var.equal`、`include.miss`、`byrow` 和表头 N 均与当前口径一致。
- 同时交付 `.xlsx` 和 `.docx` 时，核对两种文件来自同一个已确认的表对象或同一份结构化表数据，行、列、分母、统计量、缺失和 P 值逐项一致；只有两种文件都通过各自文件 skill 的结构与显示检查，才能把双格式表格标为完成。
- 自定义或二次装配表格时，把稳定唯一的 `field_id` 与可重复的显示标签分开保存，例如三个可见列均为“P 值”时分别使用 `offline_p`、`online_p` 和 `overall_p`。构造键值对象前断言 `field_id` 唯一；装配后以行键和 `field_id` 逐单元格核对结构化来源与每种输出。重复显示标签合法，重复内部键或只检查某个数字是否在文件中出现不合法。
- 只检查工作簿能否重新打开、列宽、冻结窗格或颜色，不能证明 Table 1 内容合格。

任一变量名称在分类水平行重复、分类水平脱离对应变量标题行、二分类含义不清、分母不一致或缩进仅靠空格实现时，不得把统计表工作项标为完成。
