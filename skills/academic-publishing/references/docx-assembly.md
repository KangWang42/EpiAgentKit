# Word 拼装边界

实际 `.docx` 创建、编辑、渲染和验证由 `docx` skill 负责。本 reference 只保存论文内容层对 Word 拼装的要求，不指定 python-docx、pandoc 或其它固定实现。

1. 先锁定本轮论文模式和正文唯一来源。已有报告生成器、旧 Word 或文件名只能作为待核对输入；不得仅因它们存在就把进展状态、待确认块、运行说明或内部路径带入论文。用户明确要求进展或质量报告时，这些内容仍由相应报告工作流决定。
2. 先确认目标期刊、学校或用户提供的模板；没有模板时使用 `docx` 的中性默认。
3. 数字按固定结果名称从 `results/results.yaml`、旧项目结果文件或用户明确指定的正式结果中取得，不根据章节 Markdown 反向认定结果。
4. 包含多张正式表图时，把内容矩阵中的编号、功能、来源、位置、题注、正文引用、展示标签/单位和最终尺寸转换为 `docx/references/delivery-requirements.md` 的同一份任务清单；内容验收和文件验收不得各维护一套表序。
5. 标题层级、题注、交叉引用、表格、公式、上下标和参考文献在实际 Word 中可用且一致。
6. 没有模板时，数据表使用白底三线表，只保留表顶线、表头下分隔线和表底线；不加填充色、竖线、左右外框、逐行横线或隔行底色。非数据表是否需要其它边框由其功能决定，不把三线表规则扩展到所有 Word 表格。
7. 使用模板时保留既有样式、节、页眉页脚、域和编号；工具选择以不破坏这些结构为准。
8. 生成后渲染并检查分页、字体、缺字、表格跨页、图片裁切、题注和目录；文件能打开不等于版式通过。
9. 一次局部 Word 修改只验证授权范围；完整论文或学位论文才做全篇布局检查。

若某种转换工具无法保留当前模板要求，改用 `docx` skill 中已验证的其它实现；不得把对某个历史模板的限制写成所有 Word 文件的通用禁令。
